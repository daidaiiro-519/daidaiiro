基盤のアーキテクチャ（案）

核（ドメインモデル ・ ポート）と Rust の原典から決め、ddd ・ platform ・ 反証役のレビュー（前提の束つき）を統合した。schema-driven と ctxtrace の実装は手本にしていない。全文 arch/reviews/

ポートとアダプター。業務領域ごとの crate（domain/）・ 使う場面の application ・ 外の技術ごとの adapters ・ 入口の entry に分け、許す辺を1つの表に持つ。
依存の向きは Cargo の辺と循環の禁止で止め、Cargo が止めない書き方（dev の辺 ・ feature の統合 ・ pub use ・ allow）は検査で止める。

1　なぜポートとアダプターか

核の事実構成への帰結
変更の仕組み ・ AI ツール ・ 保存を差し替えられる（利用者「アダプターが変わったとしても機能するように」）業務の側がポート（trait）を持ち、外の技術の側が実装する。依存は外から中への1方向
同じ入力から同じ結果（Q0 #14）業務の側は入出力をしない。時刻と id もポートか値で受け取る
入口が複数（CLI ・ MCP ・ CI ・ 人の入口）駆動する側も業務の外に置く
中核5つは集約9 ・ 不変条件46 ・ 決定表を持つドメインモデル（ddd：ports-and-adapters「業務ロジックがドメインモデルならポートとアダプターを選択する」）中核はポートとアダプターで作る
補完（描画 ・ 移す ・ 公開）は形と参照の検査が中心（Q1 #23）同じ crate の形のまま、中は関数で書く。集約とリポジトリの作りを持ち込まない
基盤の内側は1つの区切られた文脈（Q9 #11）crate は文脈を分けるものではなく、業務領域の論理的な境界をビルドで守る手段。名前に contexts を使わない

4　依存の向き

crate依存してよい先理由（ドメインサービス）
values（無し）2つ以上の領域が使う値だけ
declarationvalues作成する ・ Concrete を照らす
validationdeclaration ・ valuesResolver ・ Validator。判定の記録の集約もここ
instancevalidation ・ declaration ・ values作成と変更のあとに検証する。取り込むは Concrete を読む
renderdeclaration ・ valuesビューの式が指す欄を Concrete で確かめる。状態は values の値で受け取る
changevalidation ・ render ・ declaration ・ values変更を見せる（全インスタンスの検証 ・ 描画の差分）・ 状態を導く
searchchange ・ validation ・ declaration ・ values状態 ・ 判定の結果 ・ term で探す
sessionvalues再開か新規かは、枠 ・ AI ツールの答え ・ 設定の値だけで決まる
migration ・ publishdeclaration ・ values移す ・ 公開された言葉の版を出す
applicationdomain/ の全部駆動する側のポート10。1回に変える集約は1つ
adapters/*自分が実装するポートの crate ・ values外の技術を閉じ込める
entry/cliapplication ・ adapters/*起動と結びつけ

表に無い辺はすべて禁止。特に validation → change ・ render → change ・ session → ほかの領域 ・ domain → adapters。人の入口だけのポート（判定する ・ Abstract の版を出す）は、MCP を足すときに別の crate に分け、MCP から届かないようにする

6　決定的にする検査

Cargo が止めない書き方（platform が試作で実測）止める検査
dev-dependencies は循環を許す（change → fs → change が通った）cargo metadata の辺を種類（normal ・ dev ・ build）ごとに architecture.json と突き合わせる。domain から adapters ・ entry への辺は種類を問わず0件
workspace のビルドで feature が統合される（jsonschema の取りに行く機能が入った）jsonschema は [workspace.dependencies] に default-features = false で1か所。cargo tree -e features で確かめ、業務の crate を -p で1つずつ単独にビルドする
pub use した外の crate を、書いていない crate が使えたdomain の crate からの外の crate の pub use を grep で0件
clippy の disallowed は #[allow] で外せるdomain/ の clippy を forbid にする（E0453 で止まることを実測）。主な守りは、crate ごとに許す外の crate の表
（設計）表に無い外の crate を足すarchitecture.json の外の crate の許可と cargo metadata を突き合わせる
