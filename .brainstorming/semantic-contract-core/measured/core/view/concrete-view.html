ACDR の Concrete スキーマ（全文）

正本 examples/acdr.concrete.json。docs と acdr-inspect を戻し、docs の形をいまの acdr Skill に合わせた版（本体の検査と58の場面は合格）

欄を拡張するのは x- ではなく、JSON Schema の properties。x- は、JSON Schema で書けない意味（読み方 ・ 決まり ・ 任せる先 ・ 置き場所など）だけを持つ。

キーの種類と役割

種類何を書くかこの Concrete での例
欄（properties の中）インスタンスが持つデータの形。拡張したい欄はここに足す。形は JSON Schema の標準のキーワード（type ・ pattern ・ items ・ required ・ if/then など）で書く$schema ・ kind ・ no ・ title ・ status ・ decision ・ why ・ shift ・ alternatives ・ supersedes ・ docs ・ id
x-（Abstract の9つ）JSON Schema では書けない意味だけ：読み方と書くときの決まり（x-prompt）・ 任せる先（x-delegates）・ 置き場所（x-instance-path）・ 名前の型（x-instance-label）・ 人が決める欄（x-decided-by）・ ほかを指す（x-relationship）などx-instance-path ・ x-instance-label ・ x-delegates、欄の中の x-prompt ・ x-decided-by ・ x-relationship
Concrete が足す x-（x-extensions で定義）9つで足りない新しい意味のキーワードを必要とするときだけ。名前 ・ 値の形 ・ 説明 ・ 書くときの決まりを x-extensions に書いてから使ういまは無い。acdr Skill のスキーマにある x-view（描画で隠す）を移すなら、ここで定義する
