5　Abstract の一員

本体に従うスキーマ。インスタンスのファイル（変更の記録 ・ 判定の記録 ・ 設定）と、手元の DB の行（session）と、出力の形（change-view）

変更の記録（change）

キー値
$schemaurn:semantic-agent-schema:base:semantic-abstract-schema:v1
$idurn:semantic-agent-schema:base:change:v1
title変更の記録
description意図1つぶんの変更の記録。セッション ID ・ 前後の値 ・ 変更の仕組みの値（commit など）は持たない。前後は変更の仕組みからポートで受け取る。

欄型と制約説明読み方（read）書くときの決まり（write）
$schema 必須const: "urn:semantic-agent-schema:base:change:v1"
kind 必須const: "change"種類means 変更の記録であること。
id 必須type: "string" pattern: "^[0-7][0-9A-HJKMNP-TV-Z]{25}$" readOnly: true記録の idmeans 基盤が書いた時に1回だけ決める、打ち合わせずに一意な値（ULID）である。
parse 時刻の順に並ぶ26文字。

shown 変更を見せるとき、目的 → 意図の順の先頭に出る。
intent 必須type: "string" minLength: 1 maxLength: 120意図means この変更で何をしたかったかの1文である。
shown 変更を見せるときの見出しになる。		one-intent（ai ・ judge）意図は1つで、変更の項目のすべてがその意図のための変更である。
writer_kind 必須enum: ["human", "ai-agent"]書いた者の種類means 人か AI の Agent かである。
items 必須type: "array" minItems: 1 readOnly: true items: "object"変更の項目means どの対象のどの欄が変わったかの並びで、基盤が最後に確定した姿 → いまの前後から入れる。
parse 対象はインスタンスなら id と kind、それ以外はパス。欄は JSON の対象だけが持つ。
when AI は書かない。基盤が「変更を記録する」で入れる。		unit-field（machine）欄は x-prompt を持つ書く単位の JSON Pointer で、配列の添字まで下げない。
replacestype: "string" pattern: "^[0-7][0-9A-HJKMNP-TV-Z]{25}$" x-relationship: {"to": "urn:semantic-agent-schema:base:change:v1"}置き換える意図の idmeans 差し戻した意図を直すときに、前の変更の記録を指す。
