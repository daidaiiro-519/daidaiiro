基盤の核：ドメインモデル ・ スキーマ ・ DB をそろえ、シミュレーションで振る舞いを確かめる

正本：domain-model-v2.json（Q1）。この会話の決定は memory と measured/abstract-draft にあり、正本にはまだ入っていない

核は1つのフォルダ（measured/core/）にし、5つを同じ版でそろえる。
合意したら、シミュレーションが期待する振る舞いを全部実行して通ることを、核ができた印にする。

1　核の5つ

ドメインモデル

集約 ・ 値オブジェクト ・ ポート ・ 不変条件。v2 に決定を適用したもの

スキーマ

Abstract の本体と一員（変更の記録 ・ 判定の記録 ・ セッション ・ 索引の行 ・ 変更のまとまりの形）

ポートの契約

入出力を JSON Schema で書く。Git ・ SQLite の語を使わない

DB

SQLite のアダプターの DDL。スキーマの行の形から導く

期待する振る舞い

使う場面の事後条件と不変条件を、実行できる場面にする。シミュレーションが全部通す

2　v2 に適用するもの

状態どこ中身v2 との関係
合意済み任せる先x-delegates の中身は自分の任せる先の定義（role ・ answer ・ run）。ほかの Concrete の URN を書かないv2 の「任せる先」は Concrete の URN とモデルを持つ
合意済み任せる先の種類judging ・ working。argv があれば CLI のプロセス。by: ai は argv の無い judging、by: machine は argv の有る judging か基盤のエンジンv2 に無い
合意済み基盤の任せる先基盤自身も x-delegates に judge を持つv2 に無い
合意済み呼ぶ者呼ぶのは親のセッション。呼ばれた子はほかを呼ばず、決めきれない点を needs で返すv2 に無い
合意済み呼び出しの書式protocol の call：delegate ・ target ・ rules ・ inputs ・ task ・ handoff。Abstract の $defs/agents は外したQ4（protocol）へ
合意済みx-prompt の読み方read は means ・ shown ・ parse ・ when、ほかに write。描き方は3つの型。ビューは任意Q7 の形に足す
合意済み名前URN の持ち主は base。Concrete の URN の種類はインスタンスの kind の名詞v2 は core
合意済みAbstract の本体$schema は自分の $id。9つの x- を x-extensions に登録Q7 の形に足す
合意済み決まりの書き方rule は状態で書く（read-perspectives）v2 に無い
合意済みセッション呼び名3つ。同じ目的は1つ、任せる先は目的 ・ 親 ・ 役割で1つ、オーケストレーターはリポジトリに1つで入れ子にしない。不変条件①は任せる先のセッションだけQ11 ・ I46 を直す
合意済みJSON Schema能力をフルに使い、x-prompt には書けないものだけ残すQ7 の方針に足す
合意済み外の CLI文脈の技術スタックの CLI を任せる先として置く（Q0 #13 を残す）変わらない
案確定の単位承認ごとに変更の仕組みで確定し、1単位＝1意図にするv2 の I33 は1つの変更に意図が2つある場合を持つ
案変更の項目変更の記録から「対象 ・ 欄」を外し、前後から導くv2 は持つ（U13）
案ポート「変更の前後を受け取る」入出力を target ・ before ・ after にし、決着の文から Git の語を外すv2 は操作の名前だけ
案外れた判定violated の判定は確定に入れないv2 に無い
未決セッションと索引の行の形Abstract の一員として書き、DDL をそこから導く—
未決確定しなかった変更の記録手元の索引の行をどうするか—
未決対象ごとの経緯U13 が必要とする、変更の仕組みへの操作—
未決単位がまとめられたときsquash などで1単位に意図が2つ以上入ったときの扱い—
未決例外の書き方Q1 #7 ・ #22—

合意済み：この会話で利用者と決めた（正本に未反映）。案：この数ターンで出した（反証していない）。未決：答えがまだ無い

3　進め方

順すること出すもの
1案と未決の9件に答えを書く答えの下書き
2結論を渡さない反証役と、ddd ・ platform ・ qa ・ usecase の4つのアドバイザーに同時に依頼する指摘の一覧（そろうまで答えを変えない）
3v2 に全部を適用して核の5つを書くmeasured/core/
4参照の実装でシミュレーションを回す（Git とスナップショット、SQLite）振る舞いごとの合否のページ
5核と合否を1つのページで出し、合意を取る。合意したらボードと正本へ ACDR で適用する差分のページ
