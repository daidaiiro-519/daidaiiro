Semantic Search と用語

利用者の言葉「処理自体は多分全部機械的…整形する部分がaiが行う部分で、それを整形する部分の契約としてjsonスキーマがある」「コマンドとしてはセマンティック系もあるでしょ？ただそれが返すのはそのセマンティックをするための手順を返す」「jmethを使わないというのはそれさっきいったユースケースをクリアできない」「ハーネスをaiではない方にカテゴライズするのは意味不明」と、Codex ・ Claude Code の fork とキャッシュの実測を合わせて整理した。例の名前は架空。入出力の形は protocol（Q4）が決まるまで案

Semantic Search は、自然な言葉の問いに答えのスキーマで答える使う場面（U28）。semantic-search のコマンドが手順を返し、AI は問いを JMESPath の条件に、結果を答えに整形するだけ。探す ・ 確かめるは機械的なコマンドで、出どころに式と版を残すので、答えは何度でも同じ結果で確かめられる

1　コマンドと用語

コマンド種類返すもの
semantic-searchセマンティック（手順を返す）条件のスキーマ ・ 使ってよいコマンド ・ 答えのスキーマ ・ 書き方の rule ・ kind と term の候補
semantic-readセマンティック（手順を返す）その欄の x-prompt（read と write の rule）と読み進め方
semantic-writeセマンティック（手順を返す）その欄の書き方の rule ・ 使える Patch の op ・ 書いたあとに呼ぶ validate
search機械的インスタンスごとに JMESPath の where を評価し、id ・ 版 ・ 式 ・ select の値 ・ 探した範囲を返す
get機械的欄の x-prompt ・ 値 ・ 版
patch機械的JSON Patch（test ・ add ・ replace ・ remove）を適用し、検証の結果と needs
validate機械的渡した値を保存せずに検証する。出どころの式をその版で評価し直して一致を確かめる

セマンティック系のコマンドは処理をせず、手順を返す。手順は契約から決まるので、返すもの自体は決定論的。AI はその手順に従って機械的なコマンドを呼ぶ

2　送る JSON と返る JSON

① semantic-search に問う
{
  "for": "semantic-search",
  "question": "AI に何を許すかを決めた記録と、その責任者は？",
  "answer_schema": "urn:semantic-agent-schema:sample:answer-owner:v1"
}
手順が返る
{
  "steps": [
    "問いを条件のスキーマ（query）の形に整形する",
    "search を呼ぶ",
    "答えのスキーマの形に整形し、出どころを付ける",
    "validate を呼ぶ"
  ],
  "query_schema": "urn:semantic-agent-schema:core:query:v1",
  "commands": [
    "search",
    "get",
    "validate"
  ],
  "rules": [
    {
      "id": "where-is-jmespath",
      "rule": "where はインスタンス1件に評価する JMESPath の式。真のものを選ぶ"
    }
  ],
  "candidates": {
    "kind": [
      "urn:semantic-agent-schema:sample:record:v1"
    ],
    "term": [
      "urn:semantic-agent-schema:sample:glossary:v1#permission"
    ]
  }
}
② AI が作った条件 → ③ search
{
  "kind": [
    "urn:semantic-agent-schema:sample:record:v1"
  ],
  "where": "contains(subject, 'AI') && decision != null",
  "select": {
    "owner": "owner",
    "decision": "decision"
  },
  "contexts": [
    "sample"
  ]
}
search の結果
{
  "query": {
    "kind": [
      "urn:semantic-agent-schema:sample:record:v1"
    ],
    "where": "contains(subject, 'AI') && decision != null",
    "select": {
      "owner": "owner",
      "decision": "decision"
    },
    "contexts": [
      "sample"
    ]
  },
  "items": [
    {
      "id": "r-12",
      "kind": "urn:semantic-agent-schema:sample:record:v1",
      "version": "<読んだ版>",
      "values": {
        "owner": "yamada",
        "decision": "許可は各ツールの設定に任せる"
      }
    }
  ],
  "scope": {
    "contexts": [
      "sample"
    ],
    "index_of": "<正本の版>"
  }
}
④ AI が整形した答え → ⑤ validate
{
  "$schema": "urn:semantic-agent-schema:sample:answer-owner:v1",
  "items": [
    {
      "record": "r-12",
      "owner": "yamada",
      "provenance": {
        "id": "r-12",
        "kind": "urn:semantic-agent-schema:sample:record:v1",
        "version": "<読んだ版>",
        "select": "owner"
      }
    }
  ]
}
validate の結果（保存しない）
[
  {
    "rule": "provenance-reproduces",
    "by": "machine",
    "value": "verified",
    "why": "その版で式を評価し直すと yamada"
  }
]

JMESPath は選ぶ（where）と取り出す（select）にだけ使い、返す形は基盤が決める。JMESPath に位置が付かない弱点は、出どころに id ・ 版 ・ 式を残して評価し直すことで補う。写した値でない要約 ・ 組み合わせを答えに入れたときだけ、AI の rule（根拠の判定）が必要になる

3　呼ぶ側

呼ぶ側種類使うコマンド
AI ツール（Claude Code ・ Codex ・ Copilot ・ Kiro）と、それを動かす harnessAI が伴うsemantic-* で手順を受け取り、機械的なコマンドを呼ぶ
CIAI が伴わない機械的なコマンド（search ・ validate など）を直接呼ぶ

4　AI をどこで動かすか

形セッションキャッシュ使う場面
A　いまのセッションで行う（基本）増えないいまの会話のまま効く問う者が AI のとき
B　文脈を引き継ぎ、残さない fork残らないClaude Code の fork：効く（原典「its first request reads the parent's cache」）。Codex の fork --ephemeral：効く（実測 64%、再開と同じ）いまの会話から切り離して1回だけ整形させたいとき
採らない：保存する fork ・ 毎回新しいセッション残る ・ 増えるCodex の保存する fork は 29%（実測）。新しいセッションは親のキャッシュを読まない──

Copilot と Kiro は、残さない fork をコマンドだけで作れるか ・ キャッシュが効くかが原文に無い（不明）。基盤は fork を前提にせず、AI ツールのアダプターが「残さない fork ができるか」「そのときキャッシュが効くか（効く ・ 効かない ・ 不明）」を返し、できなければ A にする

6　確かめてほしいこと

確かめてほしいこと私の見解
semantic-* のコマンドは手順を返し、機械的なコマンドが処理するそうする（あなたのイメージ）
search の条件に JMESPath（where ・ select）を使い、出どころに式と版を残して validate が評価し直すそうする
harness は AI の側、AI でない呼ぶ側は CIそうする
AI は基本いまのセッションで動かし、切り離したいときは残さない fork（できる AI ツールだけ）そうする
