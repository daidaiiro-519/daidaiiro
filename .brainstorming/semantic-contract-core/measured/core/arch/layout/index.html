2　承認済みから変えたもの

もの承認済みの形（変更前）確定する形（変更後）なぜ
ファクトリの置き場所crate の直下の factories/aggregates/<集約>/factories/ に移し、集約の欄を pub(in crate::aggregates::<集約>) にする直下の factories/ からは、欄を pub(crate) にしないと集約を作れない（実測 E0451）。pub(crate) だと crate のどこからでも書き換えられる。集約のフォルダの下に置けば、欄をその集約のフォルダの中にだけ見せて作れる。別の集約 ・ services/ からの書き換えは E0616 で止まる（実測）
値オブジェクトの置き場所crate の直下values/利用者「そっちの方が分かりやすい」。値オブジェクトは自分の new で作られ、ほかから中身に触らないので、分けても失うものが無い
エンティティの置き場所（決めていなかった）aggregates/<集約>/entities/。2つ以上の集約が持つもの（任せる先）だけ aggregates/entities/集約の外から勝手に作れないようにする（実測 E0624）。利用者「①でお願いします」
session の依存どこにも依存しないsession → declaration（目的の参照 purpose_ref.rs を declaration に置く）session と change の両方が目的の参照を持つ。declaration は中心で、ほかの domain の crate も依存している
MCP の入口無い（ボード Q3 は「駆動する側は CLI ・ MCP」なのに、arch.html に無かった）cli の crate に2つ目の実行ファイル src/bin/mcp.rs を足し、compose.rs は lib から2つで使うボード Q3 に合わせる。起動時の結合が1か所のまま。原典：「Other executables can be placed in src/bin/」（Cargo Book Package Layout）
システムテストの置き場所tests/system.rstests/system/main.rs ＋ trace.rs1つの結合テストの crate の中をモジュールに分け、追跡の検査を同じ crate に置く
test-suite/ の中約21場面の JSONscenarios/*.json ・ trace.json ・ untested.jsonqa-advisor の追跡の持ち方

承認を受けたら、arch.html の5節 ・ 図 ・ 4節の辺の表を、この形に直す（ACDR）

3　実測

確かめたこと結果
crate の直下の factories/ から、欄を private のまま集約を作る（承認済みの形）コンパイルが通らない：error[E0451]: field … is private
同じ形で欄を pub(crate) にしたあと、集約の外から欄を書き換えるコンパイルが通る（書き換えを止められない）
values/ ・ aggregates/（集約のフォルダ aggregates/<集約>/ に entities/ ・ factories/）・ services/ に分け、欄を pub(in crate::aggregates::<集約>) にするコンパイルが通る（ファクトリは欄で集約を作れる）
同じ形で、別の集約（glossary）から ConcreteSchema の欄を書き換えるコンパイルが通らない：error[E0616]: field `inner` of struct `ConcreteSchema` is private

2. ワークスペースと crate
