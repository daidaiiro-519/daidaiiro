ドメインサービスの分け直し

利用者の見立て「ドメインサービスではなく、エンティティや値オブジェクト、集約でやるべき処理がほぼほぼ」「再開か新規かを決めるも…ドメインサービスだと思うから４つか」を、ddd-advisor（arch/reviews/ddd-services.html）と、結論を渡さない反証役に通し、前提に照らして1つにした。arch.html と model.json はまだ直していない

ドメインサービスは13から4つ（Resolver ・ Validator ・ Renderer ・ 再開か新規かを決める）にする。残りの9つは、ファクトリ3 ・ 集約の操作 ・ 値オブジェクトの操作 ・ 使う場面へ移す。あなたの見立てどおりの数になった

1　13の行き先

いまのドメインサービス分け直した後どこへ理由
作成するファクトリConcrete の雛形（Abstract から）は declaration、インスタンスの雛形（Concrete から）は instance のファクトリ集約を1つ丸ごと作る。Evans「Create an entire aggregate as a piece, enforcing its invariants.」
Concrete を照らす集約の操作 ＋ ValidatorConcrete の中で閉じる不変条件（I4 rule の id が一意）は集約 Concrete の根。Abstract に従うか（I3 ・ I6）は、Abstract を schema として Concrete を検証する ValidatorConcrete は Abstract のインスタンスでもある（Q1 #6）ので、従うかの検査は検証と同じ処理
Semantic Schema Resolverドメインサービスresolver（自分の crate）Concrete ・ glossary ・ 公開された言葉の版 ・ 指す先のインスタンスを読み、どの集約にも属さない
Semantic Schema Validatorドメインサービスvalidation。答えを5つの値にまとめる規則（I14）は値オブジェクト「検証結果」、使い直すかの判定（I16）は集約「判定の記録」へ移すrule × インスタンスの組で決まり、どの集約にも属さない
状態を導く値オブジェクトの操作「インスタンスの状態」を検証結果の並びから決定表で作る（I19）Evans「moving complex logic into value objects when a concept fitting the responsibility presents itself」
変更を見せるファクトリ ＋ 使う場面変更のまとまり（保存しない値）を、変更の記録と変更の前後から作るファクトリ（I31 ・ I35 ・ I36）は change。全インスタンスの検証と描画を呼ぶ順は applicationchange は検証も描画も呼ばない（4節の依存の向き）
例外をまとめる値オブジェクトの操作検証結果の並びを原因ごとにまとめる（I23）1種類の値をまとめる計算
意味で探して取り出す使う場面 ＋ 値オブジェクト探すのは application（リポジトリへの問い合わせ）。探す条件 ・ 一致の決まり（I25 ・ I41）・ 探した範囲（I42）は search の crate の値オブジェクトEvans「Provide methods that select objects based on criteria meaningful to domain experts.」（Repositories）
Semantic Schema Rendererドメインサービスrender。描く前の検査（I26）は集約「ビュー」と「デザインシステム」へ移すビューが無い kind も既定の描き方で描くので、集約「ビュー」の操作にできない
移す集約の操作集約 Concrete のコマンド。移し方は Abstract の版が持つ（I27）変える集約は Concrete 1つ
取り込むファクトリ ＋ 使う場面インスタンスのファクトリ（作成する の2段目と同じ）。ファイルを読む ・ 下書きの一覧は applicationインスタンスを作る入口を1つにする
公開された言葉の版を出す集約の操作集約 Concrete と Abstract のコマンド（出した版は変えない I1 ・ I7）各集約自身の不変条件
再開か新規かを決めるドメインサービスsession。「閉じる」は集約「セッション」のコマンドへ移し、サービスは「再開する ID」か「新しく立てる（閉じる ID）」を返すだけにするAI ツールの答え ・ 設定 ・ 時刻を合わせて決める方針で、セッション自身の状態だけでは決まらない

2　ドメインサービス4つの名前（英語と日本語の対）

英語（型の名前）日本語ファイル
Semantic Schema Resolver（SemanticSchemaResolver）セマンティックスキーマリゾルバーresolver/src/services/resolver.rs
Semantic Schema Validator（SemanticSchemaValidator）セマンティックスキーマバリデーターvalidation/src/services/validator.rs
Semantic Schema Renderer（SemanticSchemaRenderer）セマンティックスキーマレンダラーrender/src/services/renderer.rs
Session Selector（SessionSelector）セッションセレクターsession/src/services/selector.rs
決めたこと理由
日本語は英語の技術用語をそのままカタカナにするQ5（決着）の日本語「解決器 ・ 検証器」の「器」は、あなたが使わないと決めた語（比喩）に入っている。技術用語に戻す
Renderer の英語は model.json のままQ5 には Renderer の名前が無い。Resolver ・ Validator と同じ形にそろえた
再開か新規かを決めるを Session Selector にするいまの名前は処理を述べた文なので、ほかの3つと同じく役割の名詞にした。開いているセッションを再開するか新しく立てるかを選び、ID か「新しく立てる」を返す。「判定」は判定の記録の語と重なるので使わない

依存の向き（変更後）

crate依存してよい先理由
declaration（無し）Abstract ・ Concrete ・ glossary と、Abstract が決める値の型
instancedeclarationインスタンスは Concrete に従う
changedeclaration判定の記録 ・ 変更の記録 ・ 検証結果 ・ 状態。対象の型は declaration
resolverinstance ・ declaration$ref ・ glossary ・ 公開された言葉の版を解決し、x-relationship の指す先のインスタンスをたどる
validationresolver ・ change ・ instance ・ declarationインスタンスを検証する。解決は resolver に任せ、判定の記録の使い直しと I33 に change の型を使う
renderresolver ・ change ・ instance ・ declarationインスタンスを状態と rule ごとの結果と一緒に描く。Resolver を使い（Q5 #1）、Validator は見ない
searchchange ・ instance ・ declaration中核「意味で探す」。探す条件 ・ 一致の決まり（I25 ・ I41）・ 探した範囲（I42）の値オブジェクト。判定の結果と状態（I24）は change の型
session（無し）セッションと Session Selector。渡された値だけで決まる

resolver を自分の crate にしたので、render は Validator を見ずに Resolver だけを使える。これまでの表には validation → instance と render → instance が無かった（Validator と Renderer はインスタンスを読むのに、型を使えなかった）ので足した。resolver を validation から分けるのは、ボード Q5 #2「1つのドメインの中のモジュールにする」を変えることになる（利用者「正しいディレクトリ構成を優先してください」）

migration ・ publish の crate は無くなる。移す ・ 版を出すは Concrete ・ Abstract の型と同じ crate にしか書けない（Rust Reference「An implementing type must be defined within the same crate as the original type definition.」）。search は中核なので crate を残す。探す条件は change（状態 ・ 判定の結果）を使うので、declaration に置くと依存が逆になる

4　2つのレビューが分かれたところと、この答え

処理ddd-advisor反証役この答え
再開か新規かを決める集約「セッション」の操作（読む ・ 変えるのは1つのセッション）ドメインサービス（Q1 #37 が名前で決着。AI ツールの値と設定を合わせて決める）ドメインサービス。決め方は AI ツールと設定の方針で、セッション自身の状態だけでは決まらない。閉じるはセッションのコマンドへ（2人とも同じ）
変更を見せる の突き合わせ変更のまとまりのファクトリドメインサービスに残す（I31 ・ I22 ・ I35）ファクトリ。作るのは保存しない値「変更のまとまり」で、突き合わせはそれを作るときの不変条件
意味で探して取り出す使う場面 ＋ 値オブジェクト条件付きで残す（中核「意味で探す」を持つものを必要とする）使う場面 ＋ 値オブジェクト。中核「意味で探す」の決まりは search の crate の値オブジェクトが持つ
Concrete を照らす集約 Concrete の操作Validator に入れる両方。Concrete の中で閉じる不変条件は根、Abstract に従うかは Validator
