search の完成イメージ

利用者「searchの対象だけなんかちゃんと認識を合わせた方がいいと思った。これの完成イメージは？？」への答え。model.json のドメインサービス「意味で探して取り出す」と不変条件 I24 ・ I25 ・ I41 ・ I42 から、具体の場面を起こした。条件と結果の JSON の形はまだ決めていない（protocol は Q4 で待ち）。下の形は案である

search は、スキーマで決めた意味の単位（種類 ・ term ・ x-relationship ・ 状態と判定の結果）でインスタンスを探し、見つけたものと探した範囲を返す。JSON の中を式で自由に引くものでも、全文検索でもない

1　何で探すか

探す単位例決まり
種類（kind）ACDR の記録だけ種類の名前の範囲は Concrete の $id で決まる（I41）
状態と判定の結果判断待ちの ACDR、violated のあるインスタンスいまの入力に対する判定だけを使う（I24）
term（glossary の語）語「承認」を使っている欄版つきの id で一致を決める（I25）
x-relationshipこの ACDR を指しているもの、指しているもの公開された言葉は、読む側が指した版で探す（I25）
Concrete の拡張項目ある x- を使っている欄──

2　場面ごとの完成イメージ

1　判断待ちの ACDR を探す（人が読む U12 ・ AI が作業の前に U5）

状態と判定の結果で探す。効かなくなった判定は verified として扱わない（I24）

探す条件
{
  "kind": [
    "urn:semantic-agent-schema:acdr:decision-record:v1"
  ],
  "state": [
    "判断待ち"
  ]
}
返る結果
{
  "items": [
    {
      "id": "0197-ai-permissions",
      "kind": "urn:semantic-agent-schema:acdr:decision-record:v1",
      "state": "判断待ち",
      "results": [
        {
          "rule": "I33",
          "value": "unverified",
          "why": "AI の答えが割れた"
        }
      ]
    }
  ],
  "scope": {
    "contexts": [
      "daidaiiro"
    ],
    "index_of": "HEAD 60ce3cf6"
  }
}

2　語「承認」を使っている欄を探す（AI がインスタンスを変える前 U6）

term は glossary の版つきの id で一致を決める。v1 の「承認」と v2 の「承認」は別の語（I25）

探す条件
{
  "term": "urn:semantic-agent-schema:acdr:glossary:v1#approval"
}
返る結果
{
  "items": [
    {
      "id": "0197-ai-permissions",
      "kind": "urn:semantic-agent-schema:acdr:decision-record:v1",
      "at": "/decision",
      "term": "urn:semantic-agent-schema:acdr:glossary:v1#approval"
    },
    {
      "id": "0199-dependency-rules",
      "kind": "urn:semantic-agent-schema:acdr:decision-record:v1",
      "at": "/why",
      "term": "urn:semantic-agent-schema:acdr:glossary:v1#approval"
    }
  ],
  "scope": {
    "contexts": [
      "daidaiiro"
    ],
    "index_of": "HEAD 60ce3cf6"
  }
}

3　この ACDR を指しているものを探す（変える前に、壊れる参照を知る U6）

x-relationship をたどる。種類の名前は Concrete の $id の範囲で決まり、別の文脈の同じ名前は別物（I41）

探す条件
{
  "related_to": {
    "id": "0199-dependency-rules",
    "kind": "urn:semantic-agent-schema:acdr:decision-record:v1"
  },
  "direction": "incoming"
}
返る結果
{
  "items": [
    {
      "id": "0200-dependency-rules-name",
      "kind": "urn:semantic-agent-schema:acdr:decision-record:v1",
      "via": "/supersedes"
    }
  ],
  "scope": {
    "contexts": [
      "daidaiiro"
    ],
    "index_of": "HEAD 60ce3cf6"
  }
}

4　ほかの文脈の公開された言葉を読む（U24 ・ 範囲の宣言 U26）

探した範囲を必ず付ける。範囲の外は「探していない」と返し、0件を「無い」と返さない（I42）

探す条件
{
  "term": "urn:semantic-agent-schema:brainstorming:glossary:v2#settled",
  "contexts": [
    "daidaiiro",
    "other-repo"
  ]
}
返る結果
{
  "items": [],
  "scope": {
    "contexts": [
      "daidaiiro"
    ],
    "index_of": "HEAD 60ce3cf6"
  },
  "not_searched": [
    {
      "context": "other-repo",
      "why": "文脈の地図に無い"
    }
  ]
}

3　search ではないもの

用途どこが持つか
書く前に、その欄の x-prompt（読み方と書くときの rule）を受け取る同じ入口の「案内する」。探すのではなく、欄の位置を指して受け取る
JSON の中を式で自由に引く（JMESPath のような式）持たない。返す部分を絞るときの指し方は、前提が欄の位置に使う JSON Pointer にそろえる案（未決）
本文の文字列で探す（全文検索）持たない。意味の単位で探す
関係の索引の保存索引は正本のファイルから作り直せるもので、遅いと測れてから手元の DB を同じポートの後ろに置く（ports.outbound）

4　確かめてほしいこと

確かめてほしいこと私の見解
search が探す単位を、1節の5つ（種類 ・ 状態と判定の結果 ・ term ・ x-relationship ・ 拡張項目）にするこの5つにする。model.json の定義と同じ
x-prompt を受け取るのは search ではなく「案内する」にする分ける。探すのではなく、位置を指して受け取るため
JMESPath のような式の言語を持たない持たない。返す部分は JSON Pointer で指す
