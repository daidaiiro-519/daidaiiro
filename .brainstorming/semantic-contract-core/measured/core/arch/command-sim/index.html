コマンドのシミュレーション

AI が行う操作は、すべてセマンティック。セマンティックのコマンドは procedure（手順 ・ 入力のスキーマ ・ 出力のスキーマ）を返す。AI が生成するのは入力だけで、出力は機械的なコマンドが作り、型どおりかを validate が見る

問い答え
出力は機械的に作るか作る。AI は入力（Patch ・ 条件 ・ 判定）だけを生成し、状態に適用するのは機械的なコマンド
入力を機械的に適用したら、出力は型どおりかそうとは限らない。だから検査が2回ある ── ①入力が入力のスキーマに合うか（適用する前）②出力が形 ・ 機械の rule ・ AI の rule に合うか（適用した後。AI の rule は needs で返る）
検査で外れたら①で外れた入力は断り、状態に触れない。②で外れても保存し、violated で返す（Q8：保存は断らない）
状態を変える操作の入力は何か事前状態に足す ・ 変える ・ 取り除く分だけ（Patch の add ・ replace ・ remove）。作るは新しい文書の値、判定は判定1件が入力になる
状態を変えない操作（探す ・ 読む）は事後状態は事前状態と同じ。出力（結果）だけが増え、それも出力のスキーマで検査する

5　決めたこと

決めたこと理由
AI が行う操作は、すべてセマンティックのコマンドにするAI が関わるかどうかで、セマンティックと機械的を分ける
セマンティックのコマンドは procedure（手順 ・ 入力のスキーマ ・ 出力のスキーマ）を返す。procedure は Abstract のファイルに足すAI が生成する入力と、機械的に作る出力を、どちらも型で検査できる
セマンティックは、入力のスキーマが違う操作ごとに別のコマンドにする（7つ）返す型は同じ procedure でも、入力が操作ごとに違う。変えると意図を書くは、どちらも Patch なので semantic-write 1つ
検査は2回。①適用する前に入力を見る ②適用した後に出力を見る①で外れた入力は断り、状態に触れない。②で外れても保存し、violated で返す（Q8）
AI の判定は、semantic-judge が依頼を返し、validate が答えをまとめる。judge は人の判定だけ承認済みの Validator の2段（依頼の一覧を返す → 答えをまとめる）に合わせる
消すを無くす。不要になったものは superseded にして残す。項目を消すのは変える（Patch の remove）消すでしか済まない場面が無く、消すと指している記録が壊れる
確定していない変更の取り消しは Git の側でする。基盤は戻った姿を validate するだけ基盤は変更の仕組みを持たない

あとで正本に適用するときに書き換える前提：U11「消す」→「置き換えて残す」、I11「判定は効かない」→「superseded の記録の判定は効かない」。0150 ・ 0160 ・ 0120 ・ 0210 は架空。U28 ・ query ・ procedure は、まだ正本（model.json ・ Abstract のファイル）に適用していない
