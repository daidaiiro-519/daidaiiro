決めたことの全体

ACDR 0201 で、正本（ボード ・ model.json ・ アーキテクチャの頁）に適用した内容の1枚。作業ツリーに適用済みで、承認を待っている。詳しい中身は0節の各頁にある

ドメインサービスは4つ、domain の crate は8つ。AI が行う操作はすべてセマンティックのコマンド（7つ）で、procedure（手順 ・ 入力のスキーマ ・ 出力のスキーマ）を返す。変更の記録と意図の判定は手元の DB、変更のまとめと rule の判定はコミットする。消すは持たない。Abstract のファイルは13個で、基盤の既定のビューを持つ

2　コマンド

種類コマンド返すもの
セマンティック（AI が行う操作）semantic-search ・ semantic-read ・ semantic-create ・ semantic-write ・ semantic-judge ・ semantic-import ・ semantic-migrateprocedure（手順 ・ 入力のスキーマ ・ 出力のスキーマ）。AI は入力だけを作る
機械的（入力を適用する）search ・ get ・ create ・ patch ・ import ・ migrate ・ validate出力の型（query の結果 ・ 値 ・ change ・ 検証の結果）
機械的（AI が行わない操作）judge（人）・ render ・ history ・ record ・ release ・ sessionjudgment ・ HTML ・ 経緯 ・ 変更の記録 ・ 版 ・ セッション

検査は2回 ── ①適用する前に入力が入力のスキーマに合うか（外れたら断り、状態に触れない）②適用した後に出力が形 ・ 機械の rule ・ AI の rule に合うか（外れても保存し violated、AI の rule は needs で返る）。AI の判定は semantic-judge が依頼を返し、validate が答えをまとめる。基盤は AI を起動しない

3　セッション

中身
種類オーケストレーター ・ 目的 ・ 任せる先。任せる先は「寿命（単発 ・ 継続）」×「親の文脈（引き継ぐ ・ 引き継がない）」の4つの型。単発は登録しない
AI ツールのアダプター再開できるか ・ 有効時間 ・ 履歴の割合 ・ 型ごとの手段（fork ・ 親のセッション自身 ・ sessions import ・ session/fork）・ キャッシュが効くか
目的を引き継ぐとき引き継ぐ前にコミットする（手元の DB はほかの人に見えない）

4　DB（手元の SQLite）と ER

-- 手元の DB（SQLite）。確定しない。同じリポジトリのどの作業ディレクトリからも1つ
CREATE TABLE sessions (
  tool         TEXT NOT NULL,
  id           TEXT NOT NULL,            -- AI ツールが発行した値。基盤は解釈しない
  purpose_ref  TEXT,                     -- 目的の参照（オーケストレーターは持たない）
  parent_tool  TEXT, parent_id TEXT,     -- 親（任意）
  role         TEXT,                     -- 役割。継続の子だけ
  context      TEXT CHECK (context IN ('fresh','inherited')),  -- 親の文脈を引き継ぐか。継続の子だけ
  state        TEXT NOT NULL CHECK (state IN ('open','closed')),
  last_used_at TEXT NOT NULL,
  PRIMARY KEY (tool, id),
  CHECK ((role IS NULL) = (context IS NULL))
);
CREATE UNIQUE INDEX one_open_delegate_session ON sessions (parent_tool, parent_id, role) WHERE state = 'open' AND role IS NOT NULL;
-- 単発の子と、判定させる AI の呼び出しは登録しない

CREATE TABLE changes (                   -- 変更の記録
  id                 TEXT PRIMARY KEY,   -- 打ち合わせなしで一意な値
  purpose_ref        TEXT NOT NULL,
  intent             TEXT NOT NULL,      -- 意図（1件に1つ）
  writer_kind        TEXT NOT NULL CHECK (writer_kind IN ('human','agent')),
  replaces_intent_id TEXT,
  summary_id         TEXT,               -- 入ったまとめ（まだなら NULL）。1件は1つのまとめにだけ入る
  created_at         TEXT NOT NULL
);                                       -- セッション ID は持たない
CREATE TABLE change_items (              -- 変更の項目。前後の値は持たない（変更の仕組みから取る）
  change_id TEXT NOT NULL REFERENCES changes(id),
  target    TEXT NOT NULL,               -- kind と id、またはパス
  pointer   TEXT NOT NULL DEFAULT '',    -- 欄の JSON Pointer（ファイル全体は空）
  PRIMARY KEY (change_id, target, pointer)
);
CREATE TABLE intent_judgments (          -- 意図と変更が合うか（I33）・ 人の承認。上書きで最後の1件
  change_id  TEXT PRIMARY KEY REFERENCES changes(id),
  judge_kind TEXT NOT NULL CHECK (judge_kind IN ('ai','human')),
  result     TEXT NOT NULL CHECK (result IN ('verified','violated','unverified')),
  meaning    TEXT NOT NULL,              -- 意味
  reason     TEXT NOT NULL               -- 判定の理由
);
CREATE TABLE session_changes (           -- 手元のセッションの索引
  tool TEXT NOT NULL, id TEXT NOT NULL, change_id TEXT NOT NULL REFERENCES changes(id),
  PRIMARY KEY (tool, id, change_id)
);
CREATE TABLE relations (                 -- 関係の索引。確定したファイルから作り直せる
  from_id TEXT NOT NULL, to_id TEXT NOT NULL, via TEXT NOT NULL,
  PRIMARY KEY (from_id, to_id, via)
);
-- 消す表は無い。不要なインスタンスは superseded にして残す

5　Abstract のファイル（13）

置き場所は semantic-agent-schema/schemas/v1/。$id は urn:semantic-agent-schema:base:…:v1。基盤の既定のビューは schemas/v1/views/

ファイル中身使われ方
abstract.json（本体）Concrete の形 ・ 9つの x- ・ 拡張の契約Concrete が $schema に書く
change変更の記録の形 ・ 変更のまとまり（$defs）手元の DB の行の形
change-summary変更のまとめ：目的 ・ 意図 ・ 対象と欄 ・ 例外 ・ 意図の判定の結果コミットごとに1件。基盤が作る
judgment判定の記録（rule の判定と意図の判定）rule の判定はコミット、意図の判定は手元の DB
sessionセッションの7つの欄（context を含む）手元の DB の行の形
procedureセマンティックのコマンドが返す手順 ・ 入力のスキーマ ・ 出力のスキーマ$defs に操作ごとの入力（read-request ・ create-request ・ import-request …）
query探す条件（where ・ select ・ 範囲）・ 結果 ・ $defs/provenance（出どころ）semantic-search と search
settings探す範囲 ・ validator ・ 設定の値文脈の設定
viewビュー（描く kind は Concrete か Abstract のファイル）views/ に既定のビュー（session ・ change-summary ・ judgment）
catalog ・ design-tokensデザインシステム描く前の検査（I26）
glossary文脈の言葉
published公開された言葉の版ほかの文脈が x-relationship で読む
