2　ドメインサービスとは

問い答え出どころ
定義「When a significant process or transformation in the domain is not a natural responsibility of an entity or value object, add an operation to the model as a standalone interface declared as a service.」Evans DDD Reference p.14 Services
何に属するか「State these assertions in the ubiquitous language of a specific bounded context.」── 区切られた文脈に属する。業務領域（subdomain）に属するとは書いていない同上
基盤では基盤の内側は1つの区切られた文脈（Q9 #11）。だから業務領域をまたぐドメインサービスも許される。crate は、model.json が各ドメインサービスに付けた業務領域で置くpremises/board-answers.json:293 ・ model.json domain_services
「変更を見せる」の中身並べる順（例外 → 目的 → 意図 → …）と例外の判定がドメインサービス。前後の取得 ・ 全件の検証 ・ 描画の呼び出しは使う場面の処理なので application へ移す反証役の指摘 s ・ Evans p.14「a significant process or transformation in the domain」

4　比べた案

案判定理由
いまの案：各 domain の crate に ports.rs採らないtrait を通した入出力が domain の中で起きる。clippy の forbid は std の入出力しか止めない。Q3 の1行と食い違う
混在：読むポート3つ（契約 ・ インスタンス ・ 判定の記録を読む）だけ domain（ddd-advisor の案）採らない読む先が中身で決まる読み出しを途中で行う理由は、全部を先に読むと遅いことだけ。前提は「関係の索引は、遅いと測れてから」なので、それまでは先に読んで渡せる。遅いと測れたら、そのときに置き場所を決め直す
application の ports/（この答え）採るdomain は値の関数だけになり、Q0 #14「同じ入力から同じ結果」を型の上で守れる
