子のセッションの型

利用者「forkでいいものやsessionとして別の文脈としてその目的と意図の間は継続している必要がある子セッションの区別も契約として持っていた方がいい」「ClaudeCodeとCodexとCopilotとKiroで抽象できる契約として整理できること、キャッシュを利かすことができること」「A,Bも両方あるイメージ」を受けた整理。実測は 2026-10-25、約4万トークンの資料を読ませた親から各1回

子は3つの型を持つ。継続する子 A は4つの AI ツールすべてで再開のキャッシュが効く。分岐でキャッシュが効くのは Claude Code と Codex。継続する子 B を作るときに親のキャッシュが効くのは Claude Code だけ。契約は型ごとに AI ツールの能力を持ち、できない ・ 効かないツールでは代わりの型にする

1　3つの型

型親の文脈続くか向いている仕事寿命
分岐持って始まる1回で終わる。残さない反証、Semantic Search の整形1回の呼び出し
継続する子 A（既定）持たずに始まる（仕事の指示だけ）続く。役割ごとに再開する指示だけで進められる長い仕事役割の仕事が終わるか、目的が閉じるまで
継続する子 B持って始まる続く。役割ごとに再開する会話の意図を知らないと外れる長い仕事同上

3　ツールでできない ・ 効かないときの代わり

型代わり
分岐いまのセッションの中で行う（Copilot ・ Kiro）
継続する子 B親の文脈の分を1回払って作る（Codex ・ Kiro）。それが重いなら A にし、親が意図を指示に書いて渡す

4　契約に持つもの

持つもの中身
セッションの種類いまの3つ（オーケストレーター ・ 目的 ・ 任せる先）に、任せる先の型として 分岐 ・ 継続 A ・ 継続 B を足す。分岐は残さないので、セッションの集約に登録しない（判定させる AI と同じ）
AI ツールのアダプターが返す能力型ごとに「コマンドで作れるか（できる ・ できない）」と「親のキャッシュが効くか ・ 再開でキャッシュが効くか（効く ・ 効かない ・ 不明）」
選び方使う場面が型を求め、ツールができない ・ 効かないときは3節の代わりにする

5　確かめてほしいこと

確かめてほしいこと私の見解
子の3つの型（分岐 ・ 継続 A ・ 継続 B）を契約に持つ持つ。既定は A
AI ツールのアダプターが、型ごとに「作れるか」と「キャッシュが効くか」を返すそうする
Copilot の分岐 ・ B は、対話の中の /fork だけなので「コマンドでは作れない」とするそうする。必要なら対話で /fork して測る
