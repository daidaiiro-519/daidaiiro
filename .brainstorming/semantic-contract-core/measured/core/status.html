核の作業の整理

いまの作業：基盤の核（ドメインモデル ・ スキーマ ・ ポートの契約 ・ DB ・ 期待する振る舞い）をそろえ、シミュレーションで確かめる。キャッシュの話は、この中のセッションの決まりの一部

決めてほしいこと（2つ）

1同じ目的のセッションを新しく立てるとき、古いほうを閉じてよいか
いま古いほうが開いたまま → 新しく立てられず止まる
変更後新しく立てる時に古いほうを閉じる → 同時に開くのは常に1つ
ついでに直すこと：目的のセッションは親を比べない（オーケストレーターが替わっても同じ目的を再開できる） 完成イメージ：2つの判断の完成イメージ の2節
2再開か新規かを「費用」で比べて決めてよいか
いま（Q11 #3）有効時間内なら再開、切れたら新規
変更後再開の費用と、新規＋引き継ぎの費用を比べ、安いほう
理由：履歴が大きく、そのあと何ターンも続けると、有効時間内でも新規のほうが安い（下の3節） 完成イメージ：これから作る

2　決着したこと

① の決着の中身
  • 基盤はどのファイルも「最後に確定した姿 → いま」の差分を取る。誰が書いたかを問わない
  • AI は意図だけを渡す。変更の項目は基盤が差分から入れる
  • 意図に入らない未確定の変更は、先に確定する
  • 意図に合わない差分は I33 が出す
  • ポートの操作も DB の列も足さない

3　再開か新規かを、AI ツールに依らない契約で決める（上の2の中身）

契約（Semantic Agent Schema が持つ）
  • セッション ID は {ツールの種類, 文字列}
  • 同じ目的は同時に開かない ・ オーケストレーターはリポジトリに1つ
  • 再開の費用と、新規＋引き継ぎの費用を比べる式
  • 引き継ぎは確定した変更の記録から作り、量を数える
アダプター（Claude Code ・ Codex などで差し替える）
  • いまの履歴の量 ・ 最後に使った時刻
  • キャッシュの有効時間
  • 料金の倍率（書く ・ 読む）
  • Claude Code：会話そのものは1時間（サブスクリプション内）、サブエージェントは5分。書く 2倍（1時間）、読む 0.05倍（Opus 5.5）。原典で照合済み
  • Codex：未確認

例：履歴20万 ・ 引き継ぎ1万 ・ そのあと20ターン（Opus 5.5 ・ 有効時間1時間）

有効時間内に再開21万
有効時間内に新規3万
切れてから再開60万
切れてから新規3万

お金のほかに、引き継ぎで足りるか（渡したもの以外の文脈は消える）も判断に入る
