変更の記録と判定の記録の完成イメージ

変更前＝いまのシミュレーション（私がそれらしく並べたもの）、変更後＝決着済みの Q1 の正本（集約と値オブジェクト）の言葉から書いた Abstract の一員 change ・ judgment に合わせた記録 ・ 変更後の記録は jsonschema でその形に合う（実測）。2つの形も本体の検査を通る

1　変更の記録

変更前

{ "id": "c1",
  "目的": "ACDR 0197",
  "意図": "ACDR 0197 を起こす",
  "書いた者の種類": "AI の Agent",
  "欄": ["/no", "/title", "/status", "/decision", "/why", "/shift", "/alternatives"] }
  • id が一意に決まる値でない
  • 欄だけで、どの対象の欄かが無い
  • キーが日本語で、形が決まっていない

変更後

{
  "$schema": "urn:semantic-agent-schema:base:change:v1",
  "kind": "change",
  "id": "01JB8ZK3Q4M6R2T9V5X7Y1A3C5",
  "purpose_ref": "ACDR 0197",
  "intent": "ACDR 0197 を起こす",
  "writer_kind": "ai-agent",
  "items": [
    {
      "target": ".acdr/0197-…/acdr.json",
      "field": "/decision"
    },
    {
      "target": ".acdr/0197-…/acdr.json",
      "field": "/why"
    },
    {
      "target": ".acdr/0197-…/acdr.json",
      "field": "/shift"
    }
  ]
}
  • id は ULID（書いた時に1回だけ、打ち合わせずに一意。I37）
  • 変更の項目は 対象（target）と 欄（field）の組（Q1 #30）
  • セッション ID は持たない。前後の値も持たず、変更の仕組みから導く

2　判定の記録

変更前

{ "対象": "ACDR 0197",
  "rule": "least-privilege",
  "結果": "unverified",
  "判定した者": "AI（reviewer）",
  "読んだ欄": ["/decision", "/why", "/shift"],
  "効いているか": true }
  • 読んだ場所だけで、読んだ値が無い。値が変わったかを比べられない
  • 根拠が無い
  • 「効いているか」を記録に持っている（導くもので、持ってはいけない）

変更後

{
  "$schema": "urn:semantic-agent-schema:base:judgment:v1",
  "kind": "judgment",
  "id": "01JB8ZQ1H8N4P6S2W9Z3B5D7F1",
  "target": ".acdr/0197-…/acdr.json",
  "rule": "urn:semantic-agent-schema:acdr:decision-record:v1#least-privilege",
  "result": "unverified",
  "grounds": [
    {
      "at": "/why",
      "text": "最小権限の根拠が無い"
    }
  ],
  "judged_by": "ai",
  "judged_values": {
    "reads": [
      {
        "at": "/decision",
        "value": "ボードの画面の AI に何を許すかを、…"
      },
      {
        "at": "/why",
        "value": "画面の AI は agents.json の一覧だけで起動され、…"
      },
      {
        "at": "/shift",
        "value": [
          {
            "what": "許可の置き場所",
            "from": "agents.json",
            "to": "各 AI ツールの設定ファイル"
          }
        ]
      }
    ],
    "delegate": "urn:semantic-agent-schema:acdr:decision-record:v1#reviewer",
    "model": "opus"
  }
}
  • 判定した値に、読んだ値そのものと、任せる先とモデルを残す（値オブジェクト「判定した値」）
  • 根拠は、読んだ値の場所だけを指す（I14）
  • 効いているかは持たない

3　場面8（why と shift を書き足す）の振る舞い

変更前

親が why と shift を書き足す
判定の記録のファイルが書き換わる（効いているか：false）
コミットに判定の記録の書き換えが混ざる

変更後

親が why と shift を書き足す
判定の記録のファイルは変わらない
基盤が judged_values.reads と、いまの値を比べる
/why と /shift が違うので、この判定は効かないと導いて出す（I16）
