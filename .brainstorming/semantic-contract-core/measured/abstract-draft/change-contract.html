変更の記録の契約

あなたの言う抽象の目的（Semantic Agent Schema で作ったものにも、作っていない文書 ・ コードにも効く）に合わせた完成イメージ ・ 2つの未決に、私の見解を入れた

見解1：場所は2種類だけ。記録を足したコミットの中で引く JSON は pointer、それ以外（Markdown ・ HTML ・ コード）は本文に現れる文字列 find。find は「その記録を足したコミットの後の姿」の中で探すので、あとで本文が変わっても見つからなくならない 照らした行：Q1 #52（前の値は、変更の記録を足したコミットの親から取る）と同じ考え。根幹の原則5（同じ入力から同じ結果）
見解2：理由は記録の意図1つ。理由が違うなら記録を分ける 項目ごとの理由は持たない。ACDR の印ごとの「なぜ」は、意図ごとの別の変更の記録になる 照らした行：Q1 #28（1件が意図1つ）。足す前に引く：項目ごとの理由を足すと、意図と理由が2か所に並ぶ
