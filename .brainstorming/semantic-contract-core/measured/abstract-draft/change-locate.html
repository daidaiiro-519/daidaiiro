変更の場所の指し方

試作 changeview.py をデモのリポジトリで実行した結果（実測）。照らした根幹：同じ入力から同じ結果になること ／ 足す前に引く

結論：承認したらコミットする。1コミット＝1意図なので、場所を指す欄（find ・ hunk）を持たない。
意図に無い変更は、意図と差分が合っているかの判定（I33）が出す。

1　変更の記録（3つの案）

find

{ "intent": "…",  "items": [ { "target": "tool/agent.rs",    "at": { "find": "…" } } ] }

消した行を指せない。同じ文字列で外れる

hunk

{ "intent": "…",  "items": [ { "target": "tool/agent.rs",    "at": { "hunk": { "del": […],                      "add": […] } } } ] }

指せるが、差分の中身を記録へ写し直している

採る：場所を持たない

{ "purpose_ref": "ACDR 0197",  "intent": "止める順番を注記する",  "writer_kind": "ai-agent" }

どのファイルのどこが変わったかは、そのコミットの差分が持つ

2　描いた結果（1コミット＝1意図）

  /// 画面の AI を止める  fn stop_agent(child: &mut Child) {-     let _ = child.kill();+     let _ = child.kill(); // 先に止める↑ 意図：止める順番を注記する      let _ = child.wait();  }

記録が1件で items を持たないとき、コミットの差分すべてにその意図を付ける。例外：0件

3　流れ

1　AI が書くファイルを直接直してよいSAS で作っていない Markdown ・ HTML ・ コードも同じ
2　人が承認する意図と差分を見て承認する
3　基盤がコミットする変更の記録を作り、変更と一緒に1コミットにする記録はコミットの中に在るので、コミット ID を記録に書かない

4　意図に無い変更は、どこで出るか

変更前（場所を持つ）変更後（場所を持たない）
出すもの記録の場所に重ならないまとまりを、例外として出す意図と差分が合っているかの判定（I33）が、合わないまとまりを出す
例child.wait() を足したが記録に無い → 例外意図「止める順番を注記する」に child.wait() の追加が混ざる → violated：意図が合わない
仕組みの数場所の照合と、意図の判定の2つ意図の判定の1つ（もともと在る）

5　残ること（私の見解）

残ること扱い
1回の承認に、意図が2つ在るコミットを2つに分ける。意図ごとに承認する形にそろえる
SAS の JSON で、どの欄が変わったかを見たいコミットの前後の JSON を比べれば出る。記録には持たない
作業ツリーに、承認前の別の変更が残っている承認した意図の変更だけをコミットへ入れる。残りは次の承認を待つ
裏づけ：find と hunk を試した結果
場面find（AI が選ぶ文字列を、変更後の本文で探す）差分のまとまりの中身（消えた行 ・ 足した行）
行を書き換えた当たる当たる
行を消しただけ

同じ行が2つになった
