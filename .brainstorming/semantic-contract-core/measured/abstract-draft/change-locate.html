変更の場所を、find で指せるか

試作 changeview.py をデモのリポジトリで実行した結果（実測）。照らした根幹：同じ入力から同じ結果になること

結論：find は柔軟ではない。消しただけの変更を指せず、同じ文字列が2つあると当て推量になる。
場所は「差分のまとまりの中身」で持ち、基盤が差分から写す。

1　試した3つの場面

場面find（AI が選ぶ文字列を、変更後の本文で探す）差分のまとまりの中身（消えた行 ・ 足した行）
行を書き換えた当たる当たる
行を消しただけ
/// 画面の AI を止める		当たらない ── 変更後の本文に、その文字列が無い。「記録に無い変更」と出た当たる
同じ行が2つになった
cmd.args(&cfg.args); を2回		たまたま当たる ── 2つが隣り合っていたから。離れていれば、別の行に印が付く当たる
記録の無い変更が混ざった例外に出る例外に出る

2　変更の記録（変更前 → 変更後）

変更前：find

{ "intent": "止める関数の説明を消す",  "items": [ { "target": "tool/agent.rs",    "at": { "find": "/// 画面の AI を止める" } } ] }

AI が文字列を選ぶ。選び方で結果が変わる

変更後：差分のまとまりの中身

{ "intent": "止める関数の説明を消す",  "items": [ { "target": "tool/agent.rs",    "at": { "hunk": { "del": ["/// 画面の AI を止める"],                      "add": [] } } } ] }

基盤が差分から写す。AI は選ばない

例外：0件。find では、消した行が「記録に無い変更」として出ていた

4　だれが何をするか

1　AI が書くファイルを直接直してよい（SAS で作っていない Markdown ・ HTML ・ コードも）
2　基盤が差分を出す作業ツリーと HEAD の差を、まとまりに割るGit の差分そのもの
3　AI が意図を付けるまとまりごとに、どの意図かだけを言う。基盤が中身を記録へ写す付かないまとまりは、例外のまま残る

5　残ること（私の見解）

残ること扱い
同じ中身のまとまりが、1つのコミットに2つある何番目かを持たせる。中身と順番で1つに決まる
記録を作ったあと、コミットまでにさらに直した記録の中身とコミットの差分が合わなくなる。合わないまとまりは例外に出るので、隠れない
JSON の欄（pointer）SAS で作ったものは、欄の単位で意図を見たい。pointer は残し、それ以外のファイルはまとまりの中身で指す
