差分を受け取り、成型して扱う

決着済みの行：駆動される側のポート「変更の前後を受け取る（前の姿 ・ 後の姿 ・ 出した者 ・ 消した ID の履歴）」／「差分 ・ 履歴 ・ 出した者 ・ 時刻 ・ 承認 ・ 取り込みは変更の仕組みが持つ。基盤は差分を作らず受け取るだけ」／ I40 ・ I34 ・ I33

基盤が変更の仕組みに求めるのは「変更の単位ごとに、対象の前の姿と後の姿を返す」ことだけ。
Git は、このポートを満たすアダプターの1つ。基盤は受け取った前後を成型し、コミット ・ 履歴 ・ 承認を作り直さない。

1　境界

基盤（成型する）
受け取った前後から、行のまとまり ・ ファイルの全体の印 ・ JSON の欄ごとの前後を作る。同じ単位に入った変更の記録の意図を付ける。I33 の判定へ渡す
↓ 呼ぶ　／　↑ 前の姿と後の姿
ポート：変更の前後を受け取る
入力：変更の単位の参照（基盤は解釈しない文字列）出力：[ { "target": "tool/agent.rs",          "before": "…前の本文…（無ければ null）",          "after":  "…後の本文…（無ければ null）" }, … ]
↑ 満たす
アダプター
アダプター変更の単位の参照前の姿 ・ 後の姿試作で動かしたか
Gitcommit親の commit の中身 ・ その commit の中身動かした
スナップショット（変更の仕組みが無い場所）前と後のディレクトリの組2つのディレクトリのファイル動かした。Git と同じ画面が出た
ほかの変更の仕組みその仕組みの変更の idその仕組みが返すものアダプターを足すだけ。基盤は変えない

2　基盤が成型すること

成型受け取るものどの対象に
行のまとまりと、ファイルの全体に印前の本文 ・ 後の本文すべて（Markdown ・ HTML ・ コード ・ JSON）
欄ごとの前後（/why：前 → 後）同じ。JSON として読むJSON（SAS で作ったもの）
意図を付ける同じ単位に入った変更の記録その単位の変更すべて（1単位＝1意図）
意図と変更が合っているか（I33）意図と、上の成型の結果その単位の変更すべて

基盤は Git の差分の書式を読まない。前と後の本文から自分で成型するので、アダプターが替わっても同じ画面になる

3　ファイルと DB（変更前 → 変更後）

置き場所中身変更前変更後
ファイル変更の記録意図 ＋ 変えた場所（items）目的 ・ 意図 ・ 書いた者だけ。変えた場所はポートが返す前後
ファイル判定の記録対象はインスタンスのファイルI33 の判定は、対象が変更の記録になる
手元の DBsessions ・ session_changes変わらない
手元の DBchange_commits前の版で足した外した

change_commits を外した理由：commit を基盤の DB に写すのは、変更の仕組みの履歴を作り直すこと。どの単位に記録が入ったかは、ポートの「消した ID の履歴」と同じく変更の仕組みに聞く。索引は「遅いと測れてから」（決着済み）
