承認ごとにコミットしたときの、ファイルと DB の状態

前提：I40（記録はコミットするファイル、セッションと索引は手元の DB）、I34（記録にセッション ID を入れない）、I33（意図と変更が合っているか）、1承認＝1コミット＝1意図

ファイル：変更の記録は「目的 ・ 意図 ・ 書いた者」だけになり、変更と同じコミットに入る。
DB：テーブルの形は変わらない。変わるのは、関係の索引が「記録 → コミット」を持つことだけで、Git から作り直せる。

1　形の変更前 → 変更後

変更の記録（ファイル）変更前

{ "$schema": "urn:…:base:change:v1",  "kind": "change",  "id": "01JBA0C1…",  "purpose_ref": "ACDR 0197",  "intent": "許可の一覧を渡さない",  "writer_kind": "ai-agent",  "items": [ { "target": "tool/agent.rs",              "field": "…" } ] }

変更後

{ "$schema": "urn:…:base:change:v1",  "kind": "change",  "id": "01JBA0C1…",  "purpose_ref": "ACDR 0197",  "intent": "許可の一覧を渡さない",  "writer_kind": "ai-agent" }

どのファイルのどこを変えたかは、この記録が入ったコミットの差分が持つ

置き場所中身変更前変更後
ファイル（コミット）変更の記録 changes/{id}.json意図 ＋ 変えた場所（items）意図だけ。変えた場所はコミットの差分
ファイル（コミット）判定の記録 judgments/{id}.json対象はインスタンスのファイルI33 の判定は、対象が変更の記録になる
手元の DBsessions変わらない
手元の DBsession_changes（セッション → 記録の id）変わらない
手元の DB関係の索引 change_commits（私の案）無い記録の id → コミット ・ 目的。Git から作り直せるので、消えても困らない

3　DB が消えたとき（作り直し）

テーブル作り直せるかどこから
change_commits作り直せる記録のファイルを足したコミットを Git の履歴から引く（rebase でコミットが変わっても、引き直せば合う）
sessions ・ session_changes作り直せない手元だけのもの。消えると、だれのどのセッションかが分からなくなるだけで、記録 ・ 判定 ・ 差分は残る
