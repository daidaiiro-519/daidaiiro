Abstract と Concrete の完成イメージ

JSON Schema の実装（jsonschema 4.19）で、本体を本体自身で、Concrete を本体で、インスタンスを Concrete で検査し、どれも0件（実測）。Abstract は決着済みの Q7 の本体との差分。Concrete は、その Abstract に従って書いた ACDR の全体 ・ どちらも案で、ボードにはまだ当てていない

Abstract の本体で変えたところ（14）

どこ何をなぜ
URN の持ち主core → base（$id ・ $vocabulary ・ annotations の参照）Q6 #18：Abstract は基盤が持ち、基盤だけが変える
根の x-prompt の readparse と shown を足したAbstract 自身も read の観点を使う
根の x-prompt の writeread-perspectives を足した。rule-agent を「by と kind の対応」に書き直した。core を含む id を abstract にread の観点を要る欄に書かせる ／ x-delegates の中身を変えたため
