道具の契約：tool-contract

目的

Skill が道具（実行ファイル）を伴うとき、呼ぶ側に形を推測させないために使用する。

道具ごとに入口の形が違うと、呼ぶ側は呼ぶたびに本文を読み直す。
契約は、呼び方を1つに固定する。

契約は、呼ぶ側から観察できるものだけを規定する（ACDR 0036）。道具を書く言語と、
配布するかどうかは、利用者に委ねる。言語ごとの実装の形は言語の組が持ち
（いまは references/profiles/rust.md だけ）、配布は任意の機能として
references/distribution.md が持つ。

置く先中身
契約（この文書）2つの入口と起動のコマンド ・ CLI の規約 ・ 1つの宣言から CLI と MCP を組む ・ MCP の規約 ・ Skill のフォルダの求め方 ・ 外部の道具 ・ 層と許可辺 ・ 1段目の検査
言語の組入口の置き場所 ・ ソースの構成 ・ 雛形 ・ 組み立てのコマンド ・ 2段目の検査
配布（任意）配布物 ・ 導入スクリプト ・ 組み立ての定義

言語の組を作ってよい言語の条件は、公式の MCP の SDK が在ることだけである。
組が持つのは、雛形 ・ 組み立てのコマンド ・ ソースの検査の3つである。

原則

能力は1つ、呼び出し方は複数である。

能力を宣言に1度だけ書き、CLI と MCP はその宣言から組む。
能力を2か所に書くと、片方だけが古くなる。

呼び出し方が欠けても、能力は欠けない。
MCP の実装が無い環境では、MCP サーバーは立たず、CLI だけが動く。

標準入出力の規約 ── 原典

modelcontextprotocol.io/specification/2025-06-18/basic/transports（2026-09-24 取得 ・ 297行）から引用する。

行原文
27The server reads JSON-RPC messages from its standard input (stdin) and sends messages to its standard output (stdout).
31The server MAY write UTF-8 strings to its standard error (stderr) for logging purposes.
33The server MUST NOT write anything to its stdout that is not a valid MCP message.

だから、道具の中で標準出力へ書くと MCP サーバーが壊れる ── 子プロセスの標準出力も同じである（パイプかファイルで受ける）。

誤りの返し方 ── 原典

原典は2つを分けている（specification/2025-06-18/server/tools:389、2026-09-24 取得）。

種類原文この契約での対応
Protocol ErrorsStandard JSON-RPC errors for issues like: Unknown tools, Invalid arguments引数の不足 ・ 知らない動詞。SDK が返す
Tool Execution ErrorsReported in tool results with isError: trueok が偽のとき（読めない ・ 誤用）

findings は誤りではない。 検出が在っても isError は偽のままにする ── 違反の検出は、道具が正しく動作した結果である。

予期した失敗は、道具の結果として返す。 ok が偽なら CallToolResult の is_error を立て、こちらの文言を content に載せる ── 異常終了（panic）させると、呼ぶ側には理由が届かない。言語の組の雛形がこの形を持つ。

型は緩く受ける。 呼ぶ側は JSON の値を渡すので、数を文字列で包むことを強制しない（実測: timeout に 30 を渡すと、検証が不合格になっていた）。まとめて受ける引数は配列も受ける。

戻り値は、構造としても乗せる

原典が両方を求めている（server/tools:296・298、2026-09-24 取得）。

Structured content is returned as a JSON object in the structuredContent field of a result.
For backwards compatibility, a tool that returns structured content SHOULD also return the serialized JSON in a TextContent block.

{ok, findings, data} は JSON なので、そのまま structuredContent に乗る。MCP の面は、同じ値を構造と、文字列にした content の両方へ載せる。

子プロセスを起こすときの規律

道具が外のコマンドを実行するなら、3つを必ず指定する。どれも実測で欠陥が出た項目である（2026-09-24、9つの Skill で6か所）。

指定欠けると何が起きるか
標準入力を閉じる入力を待つ道具が、制限時間まで停止する（実測 5秒の設定で5.1秒）
制限時間（過ぎたら止める）停止した子プロセスを、永久に待つ
標準出力と標準エラーの受け先子プロセスの出力が、こちらの標準出力へ流れる ── MCP サーバーでは JSON-RPC の流れへ混入する

出力をまとめて受け取らない。 ファイルへ書き出し、上限までしか読まない ── 受け取ると、道具が出した量がそのままこちらの記憶に載る（実測: 100MB の出力で最大常駐が 306MB、ファイルへ書き出すと 24KB）。

- ガードレールと手順を、不変条件で記述させる。1回の出来事・特定の語・特定の形を規則にしない ── 規則が事例の形を取ると、その形だけが規制され、他の形は通過する。規則が禁じるのは性質であって、その性質が現れた1つの形ではない

216/// 本文を塊に分ける ── 段落 ・ 箇条書き ・ 表 ・ コード。**記号のまま残さない** ── 読み手に
217/// Markdown の構造を解釈させない。区切りの線（---）は捨てる。
218#[must_use]
219pub fn blocks_of(lines: &[String]) -> Vec<Value> {
220 fn cells(line: &str) -> Vec<String> {
221 line.trim()
222 .trim_matches('|')
223 .split('|')
224 .map(|c| c.trim().replace("**", "").replace('`', ""))
225 .collect()

227 let plain = |t: &str| t.replace("**", "").replace('`', "");
228 let mut out: Vec<Value> = Vec::new();
229 let mut para: Vec<String> = Vec::new();
230 let flush = |para: &mut Vec<String>, out: &mut Vec<Value>| {
231 if !para.is_empty() {
232 out.push(json!({"kind": "para", "text": para.join("")}));
233 para.clear();
234 }
235 };
236 let mut i = 0;
237 while i < lines.len() {
238 let line = lines[i].trim_end();
239 let t = line.trim_start();
240 if t.starts_with("```") {
241 flush(&mut para, &mut out);
242 let mut code = Vec::new();
243 i += 1;
244 while i < lines.len() && !lines[i].trim_start().starts_with("```") {
245 code.push(lines[i].clone());
246 i += 1;
247 }
248 out.push(json!({"kind": "code", "text": code.join("\n")}));
249 } else if t.starts_with('|') {
250 flush(&mut para, &mut out);
251 let head = cells(t);
252 let mut rows = Vec::new();
253 i += 1;
254 while i < lines.len() && lines[i].trim_start().starts_with('|') {
255 let r = cells(&lines[i]);
256 if !r
257 .iter()
258 .all(|c| c.chars().all(|ch| matches!(ch, '-' | ':' | ' ')))
259 {
260 rows.push(r);
261 }
262 i += 1;
263 }
264 out.push(json!({"kind": "table", "head": head, "rows": rows}));
265 continue;
266 } else if t.starts_with("- ")
267 || t.starts_with("* ")
268 || t.split_once(". ")
269 .is_some_and(|(n, _)| !n.is_empty() && n.chars().all(|c| c.is_ascii_digit()))
270 {
271 flush(&mut para, &mut out);
272 let ordered = !t.starts_with('-') && !t.starts_with('*');
273 let mut items = Vec::new();
274 while i < lines.len() {
275 let l = lines[i].trim_start();
276 let item = if let Some(x) = l.strip_prefix("- ").or_else(|| l.strip_prefix("* ")) {
277 x
278 } else if let Some((n, x)) = l
279 .split_once(". ")
280 .filter(|(n, _)| !n.is_empty() && n.chars().all(|c| c.is_ascii_digit()))
281 {
282 let _ = n;
283 x
284 } else {
285 break;
286 };
287 items.push(plain(item));
288 i += 1;
289 }
290 out.push(json!({"kind": "list", "ordered": ordered, "items": items}));
291 continue;
292 } else if t.is_empty() || t.chars().all(|c| c == '-') {
293 flush(&mut para, &mut out);
294 } else {
295 para.push(plain(t.trim_start_matches('>').trim()));
296 }
297 i += 1;
298 }
299 flush(&mut para, &mut out);
300 out
301}

457 }

459 }
460 }
