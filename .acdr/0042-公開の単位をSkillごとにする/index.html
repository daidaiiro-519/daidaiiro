ACDR 0042

公開の単位を Skill ごとにし、まとめての公開をオプションにする

承認承認を得た。適用してよい2026-09-29
決めること ── 承認か差し戻しを返すのは、この1件である
Release の公開の単位を Skill ごとにし、全部の Skill をまとめて公開する形はオプションとして残す。

なぜ、いま決めるのか

利用者は Skill を1つずつ選んで使う。ACDR 0029 は配布物の単位を Skill ごとと決めたが、公開の単位を決めていなかった。dist の雛形は、tag 1つで全部の Skill を組み立てて公開する形になっていた。この形では、1つの Skill を直すだけでも全部を組み立て直し、版も全部で1つになる。利用者は、Skill ごとの公開が基本で、まとめての公開はオプションだと指摘した。

形の変化

何がいまの形これからの形
公開の単位tag v<版> 1つで、全部の Skilltag -v<版> で、その Skill だけ（基本）。tag v<版> で全部（オプション）
導入スクリプトが取得する版リポジトリ全体の最新の Releaseその Skill の最新の Release。版の指定（<名前>@<版>）もできる。Skill ごとの公開が無ければ、まとめて公開した最新の版
組み立て毎回、道具を持つ9つの Skill を全部tag が指す Skill だけ

図で確認する

実現の形

release.yml に、tag から対象の Skill を決める段を加え、組み立て ・ 梱包 ・ 導入の試験を対象の Skill だけで行う。導入スクリプトは、GitHub の公開の一覧（API）から、その Skill の最新の tag を探す。手元で公開の一覧と配布物を HTTP で配り、install.sh を試験した。名前の指定 ・ 版の指定 ・ 名前の省略 ・ 無い版の4つとも、期待どおりに動いた。手元の Windows PowerShell 5.1 でも install.ps1 を実行し、irm | iex の形で導入できた。その試験で、git が無い Windows では install.ps1 が停止する不具合が判明し、直した。PowerShell 5.1 で irm | iex を使うと、日本語の表示が文字化けする。導入の動作には影響せず、この変更の前からある。

適用先

変更する正本は、このリポジトリの install.sh ・ install.ps1 ・ release.yml と、skills-creator の配布の雛形3件 ・ distribution.md ・ dist の案内の文である。

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
Skill ごとに release.yml を置く手順を1か所直しても、他の Skill の定義に反映されない。GitHub Actions が読むのはリポジトリの根の定義だけである
Skill ごとに acdr-latest のような動く tag を別に保つ公開のたびに tag の付け替えが必要になり、手順が増える。公開の一覧から探せば足りる
まとめての公開をやめる全部を一度に導入したい利用者の手段が無くなる。オプションとして残しても、手順は増えない

承認後に実施すること

  • 状態を accepted にして組み直し、.acdr/README.md へ行を加え、main へコミットする
  • 実行中の v1.0.0（まとめての公開）の結果を確認する
  • 必要なら、Skill ごとの tag（例 skills-creator-v1.0.0）で公開を試す

配布

目的

作った Skill を、他の人の環境へ配るときだけ使う。配布は契約の外の任意の機能である（ACDR 0036）
── skills-creator で Skill を作る人の多くは、自分のリポジトリで使うために作る。

配布の仕組み（配布物 ・ 導入スクリプト ・ 組み立ての定義）は、全言語で1つを共有する。
言語の組からは、組み立てのコマンドだけを借りる。入口が bin/ に在ることを前提にする。

規定

利用者の環境に Rust が無くても動く形で配る。 利用者はどの実行ファイルかを選ばない（ACDR 0029 ・ 0031）。

項目規定
配布物Skill ごと × 環境ごと。中身は Skill のフォルダから tool/ ・ mcp.json を除いたもの（SKILL.md ・ references/ ・ bin/ ・ tool.json など）
形式Linux ・ macOS は tar.gz、Windows は zip。道具を保持しない Skill は、環境に依存しない tar.gz と zip を1つずつ
名前<Skill の名前>-<環境>.tar.gz ・ .zip（環境は x86_64-unknown-linux-musl ・ x86_64-pc-windows-msvc ・ universal2-apple-darwin）。環境に依存しないものは -any
導入配布元のリポジトリの install.sh（macOS ・ Linux ・ WSL）と install.ps1（Windows）。OS と CPU を判別し、公開の一覧から版を決め、SHA-256 を照合してから展開し、MCP を claude mcp add --scope project で登録する
公開の単位Skill ごとである。 tag <Skill の名前>-v<版>（例 acdr-v1.0.0）を push すると、その Skill だけを公開する。tag v<版> は、全部の Skill をまとめて公開する（オプション）
導入の版install.sh acdr は、その Skill の最新の版を取得する。acdr@1.0.0 と書くと版を指定できる。Skill ごとの公開が無ければ、まとめて公開した最新の版から取得する。名前を省略すると、まとめて公開した最新の版から全部を導入する
組み立て配布元のリポジトリの .github/workflows/release.yml。tag から対象の Skill を決め、各 OS のランナーで組み立て、組み立てた場所と展開した先の2か所で起動を試験してから公開する

導入スクリプトと組み立ての定義は、配布元のリポジトリに1つずつ置く。雛形は references/distribution/ に在り、置く操作は次である。

skills-creator dist --repo <所有者/リポジトリ> [--path <配布元のリポジトリ>]
