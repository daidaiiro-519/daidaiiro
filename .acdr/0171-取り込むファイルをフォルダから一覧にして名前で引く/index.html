取り込むファイルをフォルダから一覧にして名前で引く

決めたこと

基盤が実行ファイルへ取り込むファイルは、フォルダの中から一覧を作って名前で引き、ソースのコードにファイルの場所を書かない。

なぜ決める必要があるか

基盤のスキーマとカタログを取り込む include_str! が、21か所 ・ 6ファイルに、../../../schemas/… の相対パスで書かれていた。../ の数はソースのファイルの深さで決まるので、ソースのファイルを1つ動かすだけで壊れる。同じファイルを別々の場所から別々の数の ../ で指してもいた。組み込みのスキーマの表（名前 ・ ファイル名 ・ 中身の9行）も、各スキーマの $id を手で写したもので、同じ弱さを持っていた。利用者が、相対パスは変更に弱すぎると指摘し、比べた5つの方法から、フォルダから一覧を作る方法を選んだ。skills-creator の試験も、../../ を3か所に書いていた。

どう変わるか

変更前と変更後

何が変更前変更後
取り込むファイルの指し方使う所ごとに include_str!("../../../schemas/…") を書く（21か所）crate files の build.rs が schemas/ と catalog/ の中から一覧を作り、使う側は名前（$id）かファイル名で引く
組み込みのスキーマの表名前 ・ ファイル名 ・ 中身を手で9行並べる各スキーマの $id から作る。$id の無いスキーマがあればビルドを止める
何を取り込んだかの確かめ方コードの include_str! を読む取り込んだ一覧（名前とファイル名）を固定する試験 files/tests/files.rs
skills-creator の試験が指すリポジトリの中の場所それぞれの試験が ../../ を書くtests/common/mod.rs の repo() と skills() の1か所から取る

比較した案と、採らなかった理由

案採らなかった理由
使う所ごとに CARGO_MANIFEST_DIR を基準に書くソースのファイルを動かしても壊れなくなるが、同じファイルを複数の所に書くのは変わらず、schemas/ を動かすと全部を直す
定数だけを持つ crate に、ファイルを1行ずつ書くパスは1か所になるが、ファイルを足すたびに1行足し、組み込みのスキーマの表は手で並べたまま残る
外部の crate でフォルダを丸ごと取り込む依存が1つ増える。API と保守の状況を原文で確かめていない
取り込まず、実行するときに Skill の assets/ から読む実行ファイル1つで動く形が崩れ、版ごとの中身を実行ファイルに固定する決まりにも反する
.cargo/config.toml の [env] で、根の場所を変数として渡すCargo はこの設定を、コマンドを実行した場所から探す。--manifest-path で別の場所から指す呼び方では読まれない（原文では未確認）

ここから下は、この決定で変わるファイルごとの差分である。タブでファイルを切り替える。
