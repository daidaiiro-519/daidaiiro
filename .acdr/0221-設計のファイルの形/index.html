SAS の試験の突き合わせのファイルに形（schema）を置く

決めたこと

SAS の試験の突き合わせのファイル（trace.json ・ untested.json）は、それぞれの形（JSON Schema）を $schema で指し、中身が形に従うことを試験で確かめる。

なぜ決める必要があるか

「JSON を伴う場合は schema がいる」（利用者の指摘）に、SAS の試験の突き合わせのファイル2つが反していた。agents-skills-creator で同じ2つのファイルに形を作ったので、その形を写し、SAS の $id とユースケースの番号の範囲（UC0〜UC7）に合わせた。形を置くだけでは中身がずれても気づかないので、従うことを試験で確かめる。architecture.json は architecture-lint の規則のファイルなので、ここでは扱わない（ACDR 0222）。

どう変わるか

変更前と変更後

何が変更前変更後
試験の突き合わせのファイル2つ形が無く、何を書いてよいかは中身を読んで推し量る。$schema で形を指し、試験が中身を形に照らす。
試験135件。突き合わせのファイルの形は確かめない。136件。test-support の files.rs が、2つの $schema と中身を確かめる。

比較した案と、採らなかった理由

案採らなかった理由
creator の形をそのまま指す（SAS から agents-skills-creator の $id を参照する）SAS は共用サービスで、上流が下流（creator）に依存する向きになる。形は SAS が自分で持つ。
形を置き、試験は足さない中身が形からずれても、誰も気づかない。
architecture.json にも新しい形を作るarchitecture.json は architecture-lint の規則のファイルで、形は architecture-lint の rules.schema.json が持つ。2つ目の形を作ると持ち主が2人になる（ACDR 0222 で扱う）。

1//! 試験の突き合わせのファイル（system-tests/trace.json ・ untested.json）が、$schema で指す自分の schema に従う。
2//! architecture.json は architecture-lint の規則のファイルで、その形と検査は architecture-lint が持つ。
3 
4#![allow(clippy::expect_used, clippy::panic)]
5 
6use serde_json::Value;
7use std::path::PathBuf;
8 
9fn root() -> PathBuf {
10 PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("../..")
11}
12 
13fn read(path: &PathBuf) -> Value {
14 serde_json::from_str(
15 &std::fs::read_to_string(path)
16 .unwrap_or_else(|e| panic!("{} を読めない: {e}", path.display())),
17 )
18 .unwrap_or_else(|e| panic!("{} が JSON でない: {e}", path.display()))
19}

33#[test]
34fn trace_files_follow_their_schema() {
35 for (file, schema) in FILES {
36 let value = read(&root().join(file));
37 let schema = read(&root().join(schema));
38 assert_eq!(
39 value.get("$schema"),
40 schema.get("$id"),
41 "{file} の $schema が、形の $id と違う"
42 );
43 let v = jsonschema::validator_for(&schema).expect("形を組めること");
44 let errors: Vec<String> = v.iter_errors(&value).map(|e| e.to_string()).collect();
45 assert!(errors.is_empty(), "{file} が形に従わない: {errors:?}");
46 }
