参照 VO-3 を、検査が使う3つで作り直す

決めたこと

参照 VO-3 を、書いた値 ・ 注釈の場所 ・ 指す先の種類の並びの3つで作り直し、検査が参照を集めるときに VO-3 を作る。宣言の VO-3 は、宣言を移すときにこの形へ直す

なぜ決める必要があるか

VO-3 の型は実装にあったが、検査は使わず、参照を Link の別々の欄で持っていた（ACDR 0144 で内部を隠したときに、使われていないと分かった）。宣言のとおりに当てはめると、「指す先」と「x-ref の値」はどちらも書いた値になる。また「指す先の種類」は文字列1つなので、注釈の to の配列を持てない。宣言の VO-3 は、注釈の仕様（ACDR 0126）が in ・ item ・ bare ・ self と to の配列を持つ前に書かれていた。

どう変わるか

変更前と変更後

何が変更前変更後
VO-3 の成分指す先（空でない）・ x-ref の値 ・ 指す先の種類（文字列1つ）書いた値（空でない）・ 注釈の場所（スキーマ#JSON Pointer）・ 指す先の種類の並び（to）
検査が参照を持つ形Link の別々の欄（value ・ annot）と、注釈から毎回引く toLink が VO-3 を持つ
書いた値が空の参照空の文字列を id として探す（多くは「指す先が無い」）探さずに「指す先が空」のずれとして返す
宣言の VO-3指す先 ・ x-ref の値 ・ 指す先の種類宣言を Python の試作から移すときに、この形へ直す。それまでは、この ACDR が VO-3 の改訂を持つ

比較した案と、採らなかった理由

案採らなかった理由
宣言のとおりに作る（指す先と x-ref の値に同じ書いた値を入れ、種類は1つ目だけ）同じ値を2つ持つことになる。to の2つ目以降を落とすので、指す先の種類を確かめる検査に使えない
実装の VO-3 を消し、宣言からも外す集約 AGG-1 は、インスタンスが参照を0件以上持つと宣言している。参照という概念は必要で、検査も同じ3つを持っていた
いま宣言の VO-3 も直す宣言はまだ Python の試作のスキーマの上にあり、移す作業が残っている。試作のスキーマを直すと、移す前の形を2か所で持つことになる
