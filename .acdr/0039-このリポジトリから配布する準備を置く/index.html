ACDR 0039

このリポジトリから Skill を配布する準備をする

承認承認を得た。適用してよい2026-09-29
決めること ── 承認か差し戻しを返すのは、この1件である
このリポジトリを Skill の配布元にし、tag を push すると OS ごとの配布物が Release に公開される状態にする。

なぜ、いま決めるのか

このリポジトリは OSS として公開している。利用者の環境に Rust が無くても Skill を使えるようにするには、OS ごとの配布物と導入スクリプトが必要になる（ACDR 0029 ・ 0031）。ACDR 0036 で配布は任意の機能になったが、このリポジトリは配布する側である。skills-creator の dist が雛形を保持しているので、それを置く。

形の変化

何がいまの形これからの形
利用者の導入リポジトリを複製し、各 Skill を cargo で組み立てるシェルに合った1行を実行する。導入スクリプトが環境に合う配布物を取得する
配布物無いSkill ごと × 環境ごとの tar.gz ・ zip と SHA256SUMS。v で始まる tag の push で CI が公開する

図で確認する

実現の形

skills-creator dist --repo daidaiiro-519/daidaiiro で、install.sh ・ install.ps1 ・ .github/workflows/release.yml を置いた。手元の Linux で、release.yml の梱包の手順を再現した。acdr ・ fact-check ・ skill-router の配布物と SHA256SUMS を作り、install.sh で別のリポジトリへ導入した。3つとも展開され、acdr と fact-check の MCP が .mcp.json に登録された。導入した acdr は、別の作業場所から起動しても宣言を返した。導入した fact-check は、導入先の tool.json の curl で原典を取得できた。道具を持つ9つの Skill の Cargo.lock はすべて git が追跡しており、CI の --locked を満たす。Windows と macOS での組み立てと導入は、tag を push して CI を実行するまで確認できない。

適用先

このリポジトリの根に install.sh と install.ps1 を置き、.github/workflows/release.yml を置く。skills-creator の導入スクリプトの雛形2件も変更する。

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
手元で3つの OS の配布物を組み立て、手で Release に置くmacOS の universal2 と Windows の msvc を手元の WSL では組み立てられない。手で置くと、SHA256SUMS との食い違いを検出できない
配布をやめ、利用者に cargo で組み立ててもらう利用者の環境に Rust があるとは限らないという条件に違反する（ACDR 0029）

承認後に実施すること

  • 状態を accepted にして組み直し、.acdr/README.md へ行を加え、main へコミットする
  • 利用者の指示で v で始まる tag を push し、CI の結果で Windows と macOS の動作を確認する

下に並ぶのは、この決定を採ったときに何がどう変わるかである ── 上の決定の具体である。
