描画の見た目の正本を schema-driven へ移す

決めたこと

描画の見た目の正本（デザイントークン ・ CSS ・ 部品の HTML）を schema-driven の references/design に置く。見本の design を見た目を変えずに移し、テスト条件の札は持たない

なぜ決める必要があるか

基盤の論点3で、描画の部品とトークンは基盤が持つと決めたが、まだボードの見本の中にあった。3回目（描画）を Rust で実装するには、19のコンポーネント（ACDR 0128）が使う部品と見た目の置き場所が必要になる。見本の色は view.tokens.json（skills-creator の references/view が正本）から、寸法 ・ 余白などは design/tokens.json から来ていて、2か所に分かれていた。これを schema-driven の tokens.json の1つにまとめる。テスト条件の札（tchip ・ design-only）は開発の concrete の機能なので、基盤には置かない。移したあとの CSS で見本のページを描き直し、テスト条件の札を除いて、5つのページの画像が移す前とバイト単位で同じことを確かめた

どう変わるか

変更前と変更後

何が変更前変更後
見た目の正本の置き場所ボード usecase-driven-concrete の sample/design と sample4.cssschema-driven の references/design（tokens.json ・ view.css ・ parts.html）
デザイントークン2つのファイル（色は view.tokens.json、寸法 ・ 余白 ・ 文字 ・ 角 ・ 線は design/tokens.json）tokens.json の1つ（palette ・ palettes ・ base ・ semantic ・ breakpoints）
部品60（テスト条件の札 tchip ・ design-only を含む）58。19のコンポーネントが内側で使う
skills-creator の references/viewいまの Skill の references の描画の色の正本当面はそのまま。いまの Skill を schema-driven の転写へ移すときに、schema-driven の design の転写に置き換える

比較した案と、採らなかった理由

案採らなかった理由
見本の design をボードに置いたまま、Rust の描画から読む基盤の正本がボードの見本の中にあることになり、転写の元が決まらない
色の正本を skills-creator の references/view のままにする描画は schema-driven の機能で、skills-creator の view はその先行の試しである（refs.rs と同じ）。正本を schema-driven に置き、skills-creator の側を後で転写に置き換える
移すときに見た目も作り直す描画の決まりは「いまの見本の水準を下回らない」である。移すことと作り直すことを同時にすると、見た目の違いがどちらから来たか分からない
