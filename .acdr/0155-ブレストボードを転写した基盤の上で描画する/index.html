ブレストボードを、転写した基盤の上で描画する

決めたこと

ブレストボードは schema-driven を転写して持ち、ボードのインスタンスを、基盤の render とボードの Design（部品 ・ CSS ・ JS ・ デザインシステム）で描画する

なぜ決める必要があるか

ボード board-on-schema-driven の論点3で、形の検査 ・ 描画 ・ 冪等性は基盤に任せると決めた。論点2で完成イメージの切り替えを、論点5でデザインシステムを決めた。いまのボードは、テンプレート ・ 検査 ・ トークンの CSS をすべて自分で持っている。作り直すときに、基盤の側の見落としが2つ表に出た（基礎の層を変数にしていない、CSS のコメントまで検査していた）。

どう変わるか

変更前と変更後

何が変更前変更後
描画ボードの render.rs が board.json から HTML を作る転写した schema-driven の render が、ページテンプレート pages/board.json とボードの Design で描画する
見た目board.template.html ・ board.css ・ board.js ・ tokens.json（ボードの tokens.rs が CSS の変数を作る）design/ の parts.html ・ board.css ・ board.js ・ design-system.json。CSS の変数は基盤が作る。見た目はいまのボードと同じ
画面から外した機能変更の引き出し ・ 変更の印 ・ 経過のタイムライン外した（論点1 ・ 4 で画面に出さないと決めたもの）
押した状態 ・ 焦点押した「差し戻す」だけ茶色。焦点の表示が無い押した状態はどのボタンも key。焦点は key の外枠

比較した案と、採らなかった理由

案採らなかった理由
いまの描画（render.rs）を残し、検査だけ基盤に任せるテンプレートと CSS の変数を、ボードと基盤の2か所で持つことになる
論点ごとにページテンプレートの節で描画する（タブを部品にしない）基盤のページテンプレートは節を上から並べる形で、タブで切り替える面を作れない。ボード全体を1つの部品にした
変更の印と引き出しを残すDesign が受け取るのはいまのインスタンスだけで、前の回と比べられない。承認者の画面の量を減らす決定にも合わない
旗を動詞の前に書ける CLI を残す基盤の CLI は動詞が先頭の形で、ボードだけ別の形にすると、ツールの呼び方が Skill ごとに分かれる
