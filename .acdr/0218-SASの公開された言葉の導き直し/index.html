SAS の公開された言葉の導き直し

決めたこと

SAS の公開された言葉のうち Abstract（と語彙 ・ 方言）を、以前の基盤の写しから、SAS の能力ごとに Concrete を書く人へ約束することだけを持つ形に導き直し、受け取りの型の穴を閉じる。

なぜ決める必要があるか

いまの Abstract は rule 52件のうち51件が、以前の基盤のスキーマ（archive の semantic-abstract-schema.json）と同じである。10-31 の作り直しでも、導き直さずに持ち込んだ。そのため、書けるのに SAS が何もしない約束が残った。x-delegates ・ rule の agent ・ x-instance-path ・ x-instance-label ・ kind ・ output-judging ・ output-working である。以前の語（基盤 ・ Semantic Schema Resolver ・ I33 ・ ETag ・ ボードの論点番号）も残り、使う側の URN も通らなかった。概念のページ（版20）の能力 ・ ユースケースと、利用者の要望「既存にとらわれず、正しい抽象概念として正しいスキーマか見る」に一致させる。v1 は未公開なので v1 のまま直す。

どう変わるか

変更前と変更後

何が変更前変更後
Abstract に置くもの以前の基盤の項目をそのまま（根の x- 7つ ・ $defs 20 ・ rule 40件）SAS がその約束どおりに振る舞う項目だけ。Concrete に書ける x- は5つ（x-prompt ・ x-relationship ・ x-decided-by ・ x-published ・ x-view）

比較した案と、採らなかった理由

案採らなかった理由
いまの項目を1つずつ棚卸しして、残すか外すかを決める反証役の指摘：「使っているから残す」「後で使うから残す」が混ざり、残す側も以前の写しのままになる。能力から約束を導いて突き合わせる順にした
x-delegates の run.argv ・ run.session だけを外し、role と kind を残すrole ・ kind も SAS は読まず、子セッションに渡してもいない。約束だけあって振る舞いが無い
x-instance-path ・ x-instance-label を残す（具体と抽象の観点の見解）どの能力の約束でもなく、SAS が何もしない。検索の範囲はステップ8 で約束を決めるときに足す（v1 未公開なので足すのは後からできる）
operation-request.schema.json を足すSAS の入力は CLI の引数で、JSON で依頼する口が無い。口が無いまま型を公開すると空の約束になる
dialect の $vocabulary の名前（…:vocab:v1）を vocabulary の $id にそろえるJSON Schema の $vocabulary は語彙の識別子で、メタスキーマの $id と同じである必要がない。jsonschema のアダプターもこの名前を使う
