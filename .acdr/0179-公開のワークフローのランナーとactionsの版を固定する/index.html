公開のワークフローのランナーと actions の版を固定する

決めたこと

基盤の公開のワークフローは、ランナーの image を版で固定し、actions は Node.js 24 で動く版を使う。

なぜ決める必要があるか

schema-driven-v0.1.0 の公開のとき、GitHub が2つの予告を出した。1つは、checkout ・ upload-artifact ・ download-artifact の v4 が Node.js 20 を対象にしていること。Node.js 20 は非推奨で、いまは Node.js 24 で強制して動かしている。もう1つは、ubuntu-latest が 2026-10-19 から Ubuntu 26.04 へ移り、2026-11-19 までに移り終えること（actions/runner-images の issue 14748）。どちらも、いまは動くが、予告どおりに変わった時点で、こちらが何も変えていないのに公開が壊れうる。公開は ACDR 0177 で、テストした版がそのまま配る版になるよう決めたので、ランナーと actions も、こちらが選んだ版で動かす。

どう変わるか

変更前と変更後

何が変更前変更後
ランナーの imageubuntu-latest ・ windows-latest ・ macos-14ubuntu-24.04 ・ windows-2025 ・ macos-14。上げるときは、こちらで版を変えて workflow_dispatch で通す
actions の版checkout@v4 ・ upload-artifact@v4 ・ download-artifact@v4（Node.js 20）checkout@v7 ・ upload-artifact@v7 ・ download-artifact@v8（Node.js 24）。attest@v4 はもとから Node.js 24

比較した案と、採らなかった理由

案採らなかった理由
何もせず、予告どおりに変わってから直す変わった時点で公開が壊れても、こちらの変更が無いので原因を探す手間が増える。公開の途中で壊れると、版を上げて出し直すことになる
actions を commit の SHA で固定する更新を追う手間が大きい。今回の目的は、予告された変化の前に、こちらで選んだ版へ移ることである。SHA での固定は、供給の安全の決定として別に決める
ubuntu-26.04 へ先に移るUbuntu 26.04 での musl のビルドを、まだ一度も試していない。いま通っている 24.04 に固定し、移るときは別に試す
