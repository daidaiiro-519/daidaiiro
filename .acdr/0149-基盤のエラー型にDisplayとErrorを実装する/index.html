基盤のエラー型に、Display と std::error::Error を実装する

決めたこと

基盤のエラー型すべてに Display と std::error::Error を実装し、Display の文は短く句点で終えない形にする

なぜ決める必要があるか

Rust API Guidelines の C-GOOD-ERR は「Error types should always implement the std::error::Error trait」とし、Display の文を短く句点なしにするよう求めている（interoperability.html:367、2026-10-07 取得）。基盤のエラー型のうち、これを満たしていたのは InvalidValue だけだった。ACDR 0144 で外へ出した ReadError ・ WriteError ・ QueryError ・ UseCaseError も実装していないので、具体はこれらを ? で自分のエラーへ渡せない。

どう変わるか

変更前と変更後

何が変更前変更後
外へ出すエラー型（4つ）Debug だけDisplay と std::error::Error を実装する
基盤の中のエラー型（5つ）Debug だけ（ApprovalReject は reason() を持つ）同じ形で Display と std::error::Error を実装する
Display の文無い短く、句点で終えない日本語の文（例：読めない：a.json が無い）
新しい crate──足さない。手で実装する（版は Cargo.lock で決める。ACDR 0122）

比較した案と、採らなかった理由

案採らなかった理由
thiserror で #[error("…")] を付けて実装する依存の crate が1つ増える。9つの型は数行ずつで書けるので、足すほどの量ではない
外へ出すエラー型だけに実装する基盤の中でエラーの書き方が2通りになる。どちらの書き方に合わせるかを、型を足すたびに決めることになる
UseCaseError の Display に、検証エラーの一覧も並べる一覧は errors の欄が持ち、CLI と MCP は JSON で返している。Display は短くする決まりに合わせ、理由と説明だけにする
