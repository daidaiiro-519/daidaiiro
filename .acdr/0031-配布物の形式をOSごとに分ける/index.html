ACDR 0031

配布物の形式を OS ごとに分ける

承認承認を得た。適用してよい2026-09-29
決めること ── 承認か差し戻しを返すのは、この1件である
道具の契約に従う Skill の配布物の形式を、Linux ・ macOS 向けは tar.gz、Windows 向けは zip にする。

なぜ、いま決めるのか

ACDR 0029 は配布物を「配布用の zip」とした。ACDR 0029 に従って Linux の1環境で試作したところ、その環境には zip コマンドが無かった。Linux（WSL の最小構成を含む）では zip と unzip が標準で入っていないことがあり、導入スクリプトが unzip に頼ると、その環境で導入できない。tar は Linux と macOS に標準で入っており、tar.gz は実行ファイルの実行権限も保持する。

形の変化

何がいまの形これからの形
Linux ・ macOS 向けの配布物zip。展開に unzip が必要であるtar.gz。展開には標準の tar を使う
Windows 向けの配布物zipzip（変更しない）。展開には PowerShell の Expand-Archive を使う

図で確認する

実現の形

ブレストボード（.brainstorming-board/skill-binaries/）の論点2の答えを改め、前の答えを履歴に保存した。他の論点と図の「配布用の zip」は、形式を含まない「配布物」へ統一した。試作の結果は trial/README.md にある。

適用先

変更する正本は、ブレストボード .brainstorming-board/skill-binaries/ の board.json と図（flow ・ unit ・ matrix）である。ACDR 0029 の論点2の「配布用の zip」も、この記録で改める。

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
全 OS を zip のまま維持し、導入スクリプトが unzip の有無を確認するunzip が無い環境では、利用者に unzip の導入を求めることになる。利用者の要件（1行で導入する）に違反する
全 OS を tar.gz にするWindows の PowerShell が標準で展開できるのは zip である（Expand-Archive）。tar.exe の有無は、Windows の版で異なる（推測。未照合）
