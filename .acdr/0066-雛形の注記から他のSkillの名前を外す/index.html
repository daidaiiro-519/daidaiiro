雛形の注記から他の Skill の名前を外す

決めたこと

skills-creator の Rust の雛形（refs.rs.tmpl ・ contract.rs.tmpl）の注記から、他の Skill の名前（acdr ・ design-svg ・ fact-check）を外す。

なぜ決める必要があるか

助言型は他の Skill に依存せず単体で動くと決め、accept の検査6が SKILL.md ・ スキーマ ・ 道具に他の Skill の名前が無いことを見る（ACDR 0061）。ところが雛形そのものの注記に3つの名前が残っており、scaffold --type advisor で生んだ advisor は必ず検査6で不合格になる。usecase-advisor の作り直しで accept を実行して判明した。注記は動作に影響しないが、雛形と検査の決まりを一致させるため、注記の側を直す。

どう変わるか

変更前と変更後

何が変更前変更後
雛形の注記acdr ・ design-svg ・ fact-check を例として名指しする名前を出さずに同じことを書く（差分の面 ・ 呼ぶ側 ・ 実測）
生んだ advisor の検査6どの advisor でも3件を検出して不合格検出0件

比較した案と、採らなかった理由

案採らなかった理由
accept の検査6の対象から、道具のコードの注記を外す注記を除く規則を道具ごとの言語で実装することになり、検査が複雑になる。雛形の注記は他の Skill の名前が無くても意味が通る
usecase-advisor の ACDR に含める雛形の欠陥は5つの advisor すべてに及ぶ。advisor ごとの ACDR に入れると、どの記録で直したかが追えなくなる
