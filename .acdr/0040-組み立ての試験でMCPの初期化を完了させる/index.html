ACDR 0040

組み立ての試験で、MCP の初期化を完了させる

承認承認を得た。適用してよい2026-09-29
決めること ── 承認か差し戻しを返すのは、この1件である
配布の CI の組み立ての試験で、MCP サーバーとの初期化の完了通知まで送ってから応答を照合する。

なぜ、いま決めるのか

tag v1.0.0 を push した CI（run 36524094089）が、Linux の組み立ての試験で失敗し、公開まで進まなかった。試験は initialize だけを送って入力を閉じていた。MCP の初期化は、initialize の応答のあとに、呼ぶ側が完了通知を送って終わる。サーバーは完了通知を待ったまま入力が閉じられたので、異常終了した。手元で同じ失敗を再現し、完了通知まで送ると終了コード0で応答が返ることを確認した。

形の変化

何がいまの形これからの形
MCP の起動の試験initialize だけを送り、出力を grep で直接照合するinitialize と初期化の完了通知を送り、応答を変数に受けてから照合する

実現の形

release.yml と、その雛形の2か所を同じ内容に修正した。直した手順を CI と同じシェルの設定（-e -o pipefail）で、手元の9つの MCP サーバーに対して実行し、すべて通過した。

適用先

変更する正本は、このリポジトリの .github/workflows/release.yml と、skills-creator の release.yml の雛形である。

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
pipefail を外すサーバーの異常終了を検出できなくなる。応答を返したあとに異常終了する入口を、試験が合格と判定することになる
MCP の起動の試験を削除する組み立てた MCP サーバーが応答するかを、公開の前に確認できなくなる

承認後に実施すること

  • 状態を accepted にして組み直し、.acdr/README.md へ行を加え、main へコミットする
  • 利用者の指示で、tag v1.0.0 を直したコミットへ付け直して push し、CI を再実行する
