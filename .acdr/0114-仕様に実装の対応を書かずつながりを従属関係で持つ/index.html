意思決定の記録 ・ 0114 ・ 2026-10-04 ・ 承認

仕様に実装の対応を書かず、つながりを従属関係で持つ

決めたこと

要求と設計の宣言は、要素どうしの従属関係でつなぐ。どの手順でどのコードが動くかは仕様に書かず、コードだけが持つ。仕様とコードは、宣言の各種類から取り出したテスト条件を、テストが確かめることでつながる。

なぜ決める必要があるか

use-case-driven-development の論点2で「つなぎはアプリケーション層の操作が持つ」と決め、操作が手順 → 呼ぶコマンド、拡張 → 起こす拒否、成功時保証 → 状態の変更を ID で配線していた。これは仕様の中に実装の対応を書く対応の表で、コードを直すたびに直すことになり、抽象の設計と実装がずれる。仕様と仕様のつながりは、サブドメインが束ねるユースケース ・ 文脈が対象とするサブドメイン ・ 集約が属する文脈のような従属関係として宣言にすでにあり、検査はその上で行える（見本で合格89件、ずれを5種類入れてすべて検知）。
