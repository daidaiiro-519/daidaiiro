ACDR 0043

Skill の references を、JSON Schema と JSON を正本にする形へ移す

承認承認を得た。適用してよい2026-09-29
決めること ── 承認か差し戻しを返すのは、この1件である
Skill の references（Skill の目的を達成するために参照する情報）は、JSON Schema と、それに従う JSON を正本にし、人は JSON から描画した HTML で読む。

なぜ、いま決めるのか

16の Skill のうち、アドバイザー系 ・ skill-router ・ memory-cultivator は、道具の契約ができる前の Markdown だけの形である。アドバイザー系の knowledge 62件は KnowledgeSchema v5 ・ v6 を記録しているが、スキーマの実体はどこにも無い。存在しない参照が4件あり、雛形と実物もずれている。道具を持つ Skill にも、スキーマの無い入力や、置いただけで検査に使っていないスキーマがある。利用者は、構造があらかじめ分離されていれば読み手は内容に集中できると述べ、SKILL.md 以外を Markdown で持たない方針を示した。ブレストボード skill-references で5件の論点を決着させたので、ここに記録する。

形の変化

何がいまの形これからの形
references の形Markdown と frontmatter（形の定義は無い）種類ごとの JSON Schema と JSON。種類は中身で名付ける（criteria ・ answer ・ document）
外部の原典要約して knowledge に書くdocument（出典と sha256 を付けた構造化した複製）で持ち、import で取り込む
人が読む形Markdown のファイルと、チャットの文章契約の描画が JSON から組む HTML。見せ方はスキーマの x-view
advisor の回答Markdown のテンプレートに沿った文章answer.schema.json の形の JSON。validate で検査し、HTML で渡す
道具8つの Skill が道具を保持しないすべての Skill が get ・ validate ・ view ・ import を持つ（契約の雛形が持つ）

実現の形

決定の内容は、ブレストボード skill-references（Round 7、743fc89）が正本として保持する。この記録には決定だけを記載し、適用は5つの段で行う。段1 で skills-creator の契約と雛形に、document のスキーマ ・ import ・ get ・ validate ・ view ・ x-view を読む汎用の描画 ・ 既定の型とトークンを加える。段2 で ddd-advisor を移して criteria と answer の欄を決め、段3〜5 で残りの Skill へ広げる。段ごとに ACDR で提示する。回答の形の完成イメージは、この記録の answer.example.html に置いた（試作の描画で組んだもの）。

適用先

変更する正本は、16の Skill すべてである。段1 では skills-creator の契約の文書と雛形を変更する。

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
Markdown と frontmatter のまま、frontmatter だけにスキーマを付ける本文の構造が散文のままで、読み手が構造を解釈することになる
取得のたびに原典を読み、必要な情報だけを契約の形にそろえる原典は変わり、取得できないこともある。同じ問いに、日によって違う答えが返る
Skill ごとに描画のコードを書く描画の仕組みが Skill ごとに分かれ、1つを直しても他に反映されない
モデルは JSON のファイルを直接読み、検査と描画だけを道具にするモデルが種類のファイル全体を読むことになり、JSON は記号が多い分だけ読む量が増える
advisor の回答を Markdown のテンプレートのまま残すテンプレートを踏襲したかを機械で検査できない。結論が先頭に来ず、図と比較の欄が無い

  • 段1 の直後に acdr を契約の描画へ移し、上部の節を4つ（決めたこと ・ なぜ ・ 変化 ・ 比較と選択の理由）に絞る（利用者の合意で前倒し）
