意思決定の記録 ・ ACDR 0154 ・ 2026-10-08 ・ 承認

ブレストボードのスキーマを、基盤の契約に従う形へ書き直す

決めたこと

ブレストボードと回答を、基盤の契約に従う board.schema.json と answer.schema.json のインスタンスにし、論点は承認者に見せる5つと、書き手だけが使う verification で持つ

なぜ決める必要があるか

ボード board-on-schema-driven で、論点の形（論点1）・ 完成イメージの形（論点2）・ 書き手の検証の記録の置き場所（論点4）を決めた。いまの board.schema.json は18の欄を持ち、x-prompt も x-generates も kind も無いので、基盤の check と render に渡せない。回答の answer-sheet.schema.json も同じである。

どう変わるか

変更前と変更後

何が変更前変更後
論点の欄18の欄（answer ・ decision ・ example ・ passed ・ tables ・ dropped ・ path ・ findings ・ requirements ・ out_of_scope など）問い ・ 答え（text と details）・ 完成イメージ ・ 根拠 ・ 採らなかった案と、書き手だけが使う verification
完成イメージブロックの並び（para ・ html ・ figure など）。図は figures/ のファイル名で指すfigure（SVG の文字列）・ code ・ ui ・ diff の4種類
論点の指し方番号（no）id（Q1 など）。いま見る論点と回答は、注釈 x-ref でこの id を指し、基盤の check が解決を確かめる
基盤の契約満たしていない（x-prompt ・ x-generates ・ kind が無い）満たす（check-schemas の指摘0件）
回答answer-sheet.schema.jsonanswer.schema.json のインスタンス（kind が answer）

比較した案と、採らなかった理由

案採らなかった理由
いまの18の欄を残し、ページテンプレートで5つだけを描画する書く側が18の欄を埋め続けることになる。どれが承認者のためかを、スキーマから読めない
図を figures/ のファイル名で指したまま持つ描画のときにファイルを読む処理が具体の側に必要になる。インスタンスに SVG を持てば、基盤の Renderer がそのまま検査して埋め込める
論点を番号のまま指す注釈 x-ref は、項目を id の文字列で探す。番号では基盤の参照の検査が使えない

ここから下は、この決定で変わるファイルごとの差分である。タブでファイルを切り替える。

変更 3 件
Git の差分変更箇所 1 件 ／ すべてに理由がある
このファイルの変更 1 件
  1. 全体を書き直した。基盤の契約に従い、インスタンスの置き場所を x-generates で、種類を根の kind（board）で示す。ボードの名前は id に置く。 いま見る論点は、論点の id（Q3 など）で指し、注釈 x-ref（to: self、in: topics）を付ける。存在しない論点を指すと、基盤の check が「指す先が無い」を出す。 完成イメージは、figure（SVG）・ code ・ ui（描画した HTML）・ diff の4種類から選ぶ（論点2）。図は SVG の文字列で持ち、何で描いたかを問わない。種類ごとに必要な欄は if と then で決める。 採らなかった案は、案と採らなかった理由で持つ。描画で取り消し線を付けない。 書き手の検証の記録を1つの欄にまとめ、ページテンプレートは描画しない（論点4）。前の答えも previous に残し、差し戻しで戻れるようにする。
