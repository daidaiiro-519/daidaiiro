図を埋め込むページで、幅の広い図を横に送る

決めたこと

図を埋め込むページ（ACDR と、各 Skill の references の view）は、figure に overflow-x:auto を持ち、min-width を持つ図を図の中で横に送る

なぜ決める必要があるか

ブレストボード design-svg-rework の論点3で、横に長い図は作成者が min-width を書き、論点5で、埋め込み先のページの CSS に横スクロールを足すと決めた（ACDR 4）。ACDR と advisor の view.css は figure svg に max-width:100% だけを持ち、min-width を持つ図が枠の外へはみ出していた。ブレストボードの CSS はすでに overflow-x:auto を持つ。

どう変わるか

変更前と変更後

何が変更前変更後
.rv figure の規則余白 ・ 枠線 ・ 角丸 ・ 地の色それに加えて overflow-x:auto
変える場所—skills-creator の見た目の正本（references/view/view.css）と、その複製31件（15の Skill と、契約のケースの部品）。view の出力を期待値に持つ契約のケース15件も同じ1行を変える
skills-creator check --cases 1view.css を変えると、複製が正本と違うことと、view の出力が期待値と違うことを検出するadvisor 6つ ・ skills-creator ・ ddd-advisor ほかは 0件。acdr など8つの Skill に残る2件は、この変更の前から在った refs.rs の差である

比較した案と、採らなかった理由

案採らなかった理由
図の側で幅を縮める（min-width を書かない）論点3で、スマホ幅で最小のフォントサイズが下がるので、横に長い図は min-width を書くと決めた
acdr.css だけに足すACDR のページの figure の規則は view.css の複製から来ており、advisor の view のページも同じ規則を使う。正本を1か所で変える
brainstorming-board の CSS も同じ形に直すすでに overflow-x:auto を持つ。別のセッションが作り直している最中なので触らない
