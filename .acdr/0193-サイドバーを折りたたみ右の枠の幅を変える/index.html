ブレストボードの左の一覧を折りたたみ、右の枠の幅を変えられるようにする

決めたこと

ブレストボードは、左のボードの一覧を左上のメニューで折りたためるようにし、右の AI に聞く ・ 変わったところの引き出しの幅を、利用者が縁を引いて変えられるようにする。枠の幅はデザイントークンに持つ。

なぜ決める必要があるか

左の一覧と右のチャットがどちらも固定の幅で、本文が狭くなり読みにくい、と利用者に指摘された。広い画面では一覧を閉じる手段が無く、狭い画面でだけメニューが出ていた。また枠の幅（270px ・ 360px ・ 420px）は CSS に直値で書かれ、デザインシステムのトークンに無かった。読む人が枠を自分の画面に合わせられるようにし、幅をトークンの正本に一致させる。 置き場所と操作は ux-advisor に判断基準で見てもらい、開いても閉じても同じ座標の同じボタン1つにする形と、引く操作だけに頼らない形を採った（ux-advisor.json）。

どう変わるか

変更前と変更後

何が変更前変更後
左のボードの一覧広い画面では常に出ている。狭い画面だけ、本文の上の「ボードの一覧」のボタンで重ねて開く開け閉めのボタン（≡）を、サイドバーの上端の左端に置く。閉じたときも同じ座標の同じボタンが本文の左上に残る。狭い画面でも同じ座標で、重ねて開き、Esc で閉じてボタンへ戻る
右の AI に聞くの幅360px で固定左の縁を引いて変える。引かずに押すと、既定と広い幅（既定の1.6倍）を切り替える。つまみを選んで ← → の鍵でも動かせる（Shift で大きく動く）
変わったところの引き出しの幅420px で固定AI に聞くと同じく、左の縁で変えられる
変えた幅と閉じた状態（無し）この端末のブラウザに残し、次に開いたときも同じにする。残せない枠では残さない
枠の幅の値CSS に直値（270px ・ 360px ・ 420px）デザイントークン size.pane-side ・ pane-chat ・ pane-drawer と、狭める下限 pane-min ・ 本文に残す幅 pane-main-min
開け閉めのボタンの見た目と名前「ボードの一覧」の文字のボタン枠の無いアイコンだけのボタン（≡）にし、ロゴと高さをそろえて控えめな色で置く。閉じたときだけ本文の上で面と細い線を付ける。名前は「ボードの一覧」に固定し、開閉は aria-expanded で伝える。広い画面 32px ・ 狭い画面 44px

比較した案と、採らなかった理由

案採らなかった理由
一覧とチャットの幅を、いまより狭い固定の値にする読む内容と画面の幅は人ごとに違い、1つの値では合わない
幅の切り替えを、小 ・ 中 ・ 大のボタンにする段階の間の幅を選べず、ボタンが3つ増える。縁を引く形はほかの道具でも見慣れた操作である
幅をその回の画面だけに持つ（sessionStorage）ボードを開き直すたびに幅を合わせ直すことになる。幅は読む人の好みなので、端末に残す
CSS の直値のまま幅を変えられるようにする幅がデザインシステムの正本に無いままになり、既定の値を直すときに CSS の中を探すことになる
開け閉めのボタンを、本文の左上（サイドバーの外）に置く（最初の試作）開け閉めするサイドバーの外に在るので本文の部品に見え、開いたときと閉じたときでボタンの座標が変わる
閉じたときに、アイコンだけの細い列を残すボードの一覧に項目ごとのアイコンが無く、列が意味の無い要素だけで本文の幅を取る
画面の上端に横長のバーを作り、その左端に置くボタン1つのために全幅の帯を足し、本文とチャットの縦の領域を削る。ブランドの置き場所も2か所に分かれる
幅の変更を、引く操作だけにする引く操作ができない人が幅を変えられない（WCAG 2.5.7 ドラッグ動作）。押す ・ 鍵の操作でも変えられるようにする
開け閉めのボタンを、枠付きのボタンにしてロゴの横に置く（2つ目の試作）ロゴの四角とボタンの四角が並んで張り合い、高さもずれて見える、と利用者に指摘された
