意思決定の記録 ・ ACDR 0143 ・ 2026-10-07 ・ 承認

基盤の正本を、利用側の Skill へ同じ並びで転写する

決めたこと

基盤の正本を利用側の Skill の tool/schema-driven/ の下へ同じ並びで転写し、基盤の新しい版へも更新できるようにする。転写した複製は具体の持ち物で、基盤は具体の変更を上書きしない

なぜ決める必要があるか

ボードの論点5（C）で、具体は基盤の crate を転写して呼ぶと決め、宣言の UC-9 ・ 10 が転写と差分の検査を求めている。宣言は、何を写すか ・ どこへ写すか ・ 転写した時点のハッシュ値をどこに記録するかを決めていなかった。用語集の TERM-21（正本）も、0132 より前の「crate ・ コンポーネント ・ デザイントークン」のままである。実際に本物の基盤を写して利用側でビルドし、写した crate を1文字も書き換えずに動く並びを確かめた。 利用者は、転写した段階でその能力は具体の持ち物になる想定である。転写したあとの具体は基盤とつながらず、基盤の更新を取り込むかは具体が決める。 さらに、基盤の版が上がったときに、具体が更新できる必要がある。

どう変わるか

変更前と変更後

何が変更前変更後
転写した複製宣言の TERM-54：複製に手の変更があれば転写しない。正本を直してから転写し直す具体の持ち物。具体は自由に変えてよく、基盤は具体が変えたファイルを一度も上書きしない
基盤の新しい版への更新無い（具体が1つでも変えていると、転写が丸ごと止まる）transcribe の2回目からは更新になる。基盤だけが変えたファイルは新しい版にし、具体だけが変えたファイルは残し、両方が変えたファイルは具体のものを残して、新しい版を隣（<ファイル名>.schema-driven-new）に置く。具体が見比べて合わせ、終わったら消す
転写した時点の記録決めていないtool/schema-driven/transcription.json に、基盤の版（tool/core/Cargo.toml の version）と、ファイルごとの sha256 を書く。更新のたびに新しい版へそろえる
差分の種類「差分：複製のうち、正本と内容が違うファイル」だけ基盤の版の差（例：0.1.0 → 0.2.0）と、ファイルごとの8種類（正本が新しくなった ・ 具体が変えた ・ 衝突 ・ 正本に増えた ・ 正本から消えた ・ 具体が足した ・ 具体が消した ・ 衝突の新しい版が残っている）
正本（写すもの）用語集 TERM-21：Rust の crate ・ コンポーネント ・ デザイントークンtool/core ・ tool/adapters ・ references。tests と target（ビルドの出力）は写さない。cli と mcp は、利用側が自分の CLI と MCP を作るので写さない
写す先決めていない利用側の Skill の tool/schema-driven/ の下に、正本と同じ並びで置く。crate が取り込むファイルの相対パス（../../../../references/…）が正本と同じになり、複製を書き換えずにビルドできる
crate の Cargo.tomlワークスペースの設定を受け継ぐ（version.workspace など）版 ・ edition ・ license を直接書く。利用側のワークスペースに同じ設定を求めない
正本の場所決めていない実行ファイルの場所（<Skill>/bin/ の1つ上）から求める

比較した案と、採らなかった理由

案採らなかった理由
写す先を tool/schema-driven/core のように1段浅くするcrate が取り込むファイルの相対パスが、正本と複製で合わなくなる。実際に写して利用側でビルドすると、references が見つからずに失敗した
写すときに、取り込むファイルのパスを書き換える複製が正本と1文字違うので、ハッシュ値でそのまま比べられなくなる
取り込むファイルを crate の中に複製して持つreferences の仕様が正本の中で2か所になり、どちらが正しいかを毎回確かめることになる
リポジトリの中では、具体が正本を直接参照する（Cargo の path 依存）基盤の変更が具体へそのまま流れ込み、能力が具体の持ち物にならない。転写したあとは基盤とつながらない、という利用者の想定に合わない
転写の記録を持たず、正本とだけ比べる基盤が変えたのか、具体が変えたのかを区別できない。具体の変更を上書きしてしまう
具体が1つでもファイルを変えていたら、更新を丸ごと止める（この ACDR の最初の形）具体が自分の持ち物を直すと、基盤の新しい版を一切取り込めなくなる
衝突したファイルを、基盤と具体の変更を混ぜて自動で合わせる合わせ方を誤ると、具体の変更が黙って壊れる。具体が見比べて合わせる

224 let record = self.record(skill)?;
225 let dir = Self::copy_dir(skill);
226 let mut done = Transcribed {

229 written: Vec::new(),
230 removed: Vec::new(),
231 kept: Vec::new(),
232 conflicts: Vec::new(),
233 };
234 let paths: BTreeSet<&String> = master.keys().chain(copy.keys()).collect();
235 for path in paths {
236 let (master_text, copy_text) = (master.get(path), copy.get(path));
237 if master_text.is_some() && master_text == copy_text {
238 continue;
239 }
240 let change = Self::change(master_text, copy_text, record.hashes.get(path));
241 match (master_text, change.by_master, change.by_concrete) {
242 // 具体が変えていなければ、基盤の版にそろえる
243 (Some(text), _, false) => {
244 self.write(&format!("{dir}/{path}"), text)?;
245 done.written.push(path.clone());
246 }
247 (None, _, false) => {
248 self.files
249 .remove(&format!("{dir}/{path}"))
250 .map_err(Instances::write_error)?;
251 done.removed.push(path.clone());
252 }
253 // 具体だけが変えたものは、そのまま残す（具体の持ち物）
254 (_, false, true) => done.kept.push(path.clone()),

256 (Some(text), true, true) => {

258 done.conflicts.push(path.clone());
259 }
260 // 基盤は消したが、具体が変えていたもの：具体のものを残す
261 (None, true, true) => done.kept.push(path.clone()),
262 }

265 .iter()
266 .map(|(path, text)| (path.clone(), Value::String(hash_of(text))))

269 "source": "schema-driven",

271 "files": hashes

273 .unwrap_or_default()

279 None

210 "pub fn base() { /* 0.2.0 */ }\n"
211 );
212 assert!(!copy_of(&skill, "references/meta-schema.json").exists());

214 assert_eq!(
215 read(&copy_of(&skill, "tool/adapters/src/lib.rs")),
216 "pub fn adapter() { /* 具体 */ }\n"
217 );

220 read(&copy_of(&skill, "tool/core/src/view.rs")),
221 "pub fn view() { /* 具体 */ }\n"

228 "pub fn view() { /* 0.2.0 */ }\n"

231 assert_eq!(done.kept, vec!["tool/adapters/src/lib.rs".to_owned()]);
232 assert_eq!(done.removed, vec!["references/meta-schema.json".to_owned()]);
233 // 更新のあと：衝突の新しい版が残っていることを知らせる。具体が合わせて新しい版を消せば、具体の変更だけが残る
234 assert_eq!(
235 kinds(&transcriptions, &skill),
236 vec![
237 pair("tool/adapters/src/lib.rs", "具体が変えた"),
238 pair("tool/core/src/view.rs", "具体が変えた"),
239 pair(
240 &format!("tool/core/src/view.rs{CONFLICT_SUFFIX}"),
241 "衝突の新しい版が残っている"

243 ]
244 );

246 &skill,
247 &format!("tool/core/src/view.rs{CONFLICT_SUFFIX}"),

254 );
255 assert_eq!(
256 kinds(&transcriptions, &skill),
257 vec![pair("tool/adapters/src/lib.rs", "具体が変えた")]
258 );
259 fs::remove_dir_all(master.parent().unwrap()).unwrap();
