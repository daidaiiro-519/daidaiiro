ACDR 0009

成果物の利用者の範囲

提案まだ承認を得ていない。適用してはならない2026-09-21
決めること ── 承認か差し戻しを返すのは、この1件である
成果物の利用者を参加者に限定せず、作者以外が実務で使った記録を同じ重みで数える。

なぜ、いま決めるのか

効果測定が、参加者どうしで試し合う前提で組まれていた。設問別紙は「各参加者は自分以外の2作品を試す」「運営が配分し偏りを抑える」と書き、試用の記録は3月の試用期間に集めるものとしていた。しかし成果物を使うのは参加者に限らない。作者の同僚やチームが実務で使った事実が、この前提では記録から漏れる。主KPIは「作者以外による利用」を数えるものなので、限定する理由が無い。

案採らなかった理由
参加者どうしの試用だけを数える実務で使われた事実が記録から漏れる。企画の目的は他の人の仕事に役立つ仕組みを作ることであり、その相手を参加者に限る理由が無い。
参加者の試用と、実務での利用を別の指標にする主KPIが2つに割れ、どちらで判定するかを部長が決めることになる。役立った記録であることは同じなので、1つの指標で数える。
配分の仕組みを残したまま、対象だけ広げる配分は参加者の名簿があって成立する。社内の利用者には名簿が無いため、依頼と記録の受け付けに替える。

AI活用ワークショップのアンケート・効果測定案

個人のAI活用の変化と、他の人が実務で使える成果物を報告の主軸にする。段階評価による自己申告、具体的な行動の説明、他の人の試用記録を組み合わせる。人気投票は共有会の表彰として扱う。

本書は運営がMicrosoft Formsへ転記するための設問案である。フォームの作成・配信はまだ行っていない。回答の所要時間は8分を目安にし、開始前に少人数で試して設問量を調整する。この設問と尺度は今回の企画に合わせて作ったもので、妥当性を検証済みの標準尺度ではない。

冒頭の属性現在の職種（開発／PM／PL／その他）、職種変更の有無。回答者名と回答日時は Forms が記録する

個人目標と成果物の記録

目指すのは、自分のスキルをAIで動く仕組みにし、他の人の仕事にも役立てることである。知識・ノウハウ・仕事の手順・判断の目安を言語化して組み込み、他の人もその仕組みを業務効率化や課題改善に使える形にする。説明や初回の支援があることは不合格条件にしない。

G3誰に使ってもらいますか。利用者と試す場面を記入する
G4何が変われば達成ですか。結果・確認方法・期限を記入する

成果物そのものは「成果物の登録」フォームで1件ずつ登録する。R2は件数だけを聞き、内訳は登録フォームの回答と突き合わせる。一人が複数作ることを前提にし、成果物ごとの優劣は付けない。

ID作者以外の利用者へ聞くこと

U6具体的な結果・受けた支援・改善点

U5は、役立たなかった理由を集計できる形で残すために置く。自由記述だけでは、同じ原因が別の言葉で書かれ、件数として数えられない。選択肢に当てはまらない場合はU6へ記入する。利用者名と回答日時は Forms が記録するため、入力欄は設けない。作者以外であれば、参加者でなくても回答できる。成果物の利用者を参加者に限定すると、実務で使われた事実が記録から漏れる。

作者が代行して実行した場面の閲覧だけなら、デモ閲覧とする。利用者が実際に操作して得た結果を残し、運営が用途・結果・役立った点を確認する。時間短縮を示す場合は比較条件と確認・修正時間も記録する。利用環境・使い方・人が確認する点を成果物に添える。公開や特定の実装方式は要求しない。

成果物の登録

作った仕組みは、作者が1件ずつ登録する。登録した一覧が、試用記録フォームの選択肢になる。

ID聞くこと

推奨KPI案

指標定義
主KPI：他の人に役立つ仕組みを作れた参加者の割合作者以外の利用（参加者に限らない）と「役立った」の具体的記録（U1〜U6）が確認できた参加者数／開始時の参加者数
補助：業務別のAI活用P・Dの各業務で、前後とも担当・実施機会がある同じ人の、段階2・3の人数変化
補助：個人目標の達成G4の条件とR1〜R3の根拠を照合した達成・一部達成・未達・未実施・未確認の人数

主KPIは一人が複数作っても一人として数え、未提出・未確認は分母から外さず内訳を併記する。役立たなかった試用（U4）と、うまくいかなかった点（U5）も件数で報告する。うまくいかなかった記録を残さないと、次の期に同じ原因を繰り返す。一部役立った成果物は別に報告する。共同制作では本人が具体化した知識・手順や担当を確認する。試用と実務利用の内訳を示し、デモ閲覧や配布だけは数えない。業務活用の分母は同じ業務で比較できた人数とし、除外人数も示す。主KPIの分母とは異なる。

目標値は事前調査と運営条件を踏まえ、開催前に設定する。現時点では割合の目標を決定していない。交流会の参加人数と「今後相談したい相手ができたか」は運営改善用の参考情報として扱い、制作のKPIと混ぜない。

表彰投票結果と利用者の感想を示す
今後の支援N項目の変化と、未解決の困りごとから教材・相談の改善を決める

比較には、同じ回答者名で3回とも回答した人を用いる。事前と終了時の比較、中間を含む推移では、それぞれ比較対象人数を明示する。未回答・対象外は補完せず、対応する分母から除く。職種が変わった人の職種別項目は同じ業務か確認し、比較できないものを分ける。

C（0〜4）とB（0〜3）とF1は意味の異なる段階なので合算しない。0〜4を等間隔とみなした「能力が何％伸びた」という表現もしない。少人数のため、割合だけでなく人数を必ず示す。

この設計で示すのは、期間中の変化と実例である。業務経験やツール更新の影響もあり、変化のすべてを研修だけの効果とは断定しない。学習が進んで自己評価が厳しくなる場合もあるため、点数が下がった項目は自由記述と実例を併せて読む。

Microsoft Formsでの実装

回答はMicrosoft Formsで集める。フォームは5本に分ける。

フォーム時期1人あたりの回答
事前10月1回
中間12月1回
成果物の登録随時作った件数だけ
終了時（作者）3月1回
試用記録（利用者）随時。使った時点で回答試した成果物の数だけ

One response per person が制限するのは、1つのフォームにつき1回の回答である。事前・中間・終了時を1本のフォームで実施すると、2回目以降の回答を受け付けない。成果物の登録と試用記録は複数回の回答を要するため、この設定を解除する。

設問質問の種類
F1・N1・N2・N4・R1・R2・U1・U3・U4・U5・W5Choice
C1〜C7Likert。行に7問、列に0〜4と「機会なし」
P1〜P6・D1〜D6Likert。行に6業務、列に0〜3と「担当外」「機会なし」
N3・G1〜G4・R3〜R5・U2・U6・W1〜W4Text

職種別の設問は Section で分け、担当業務を尋ねる設問から Add branching で分岐させる。分岐は後ろの設問へしか飛べないため、業務のセクションは担当業務の設問より後ろに置く。兼務者は両方のセクションを通過させる。

配布時は Only people in my organization can respond と Record name を選び、One response per person を上表のとおり設定する。回答期間は Start date と End date で指定する。集計は Open results in Excel から Download a copy を取得し、氏名の列で時点間を突き合わせる。

Microsoft Formsの[質問の種類](https://support.microsoft.com/en-us/office/create-a-form-with-microsoft-forms-4ffb64cc-7d5d-402f-b82e-b1d49418fd9d)・[設定](https://support.microsoft.com/en-us/forms/adjust-your-form-or-quiz-settings-in-microsoft-forms)・[分岐](https://support.microsoft.com/en-us/forms/use-branching-logic-in-microsoft-forms)・[集計](https://support.microsoft.com/en-us/office/check-your-form-results-02859424-341d-406f-b32a-9a0fbaf357af)を2026-09-20に確認した。上記の設定名と質問の種類は、原文の表記をそのまま用いている。フォームを5本に分ける構成と、兼務者をセクションへ通す順序は、今回の設計判断である。
