skills-creator を新しい形の基盤の上で作り直す

決めたこと

skills-creator は、新しい Skill の雛形と照合した基盤のエンジンを置き、Skill のフォルダを9つの項目で検査し、基盤と同じ形で作って3つの OS 向けに公開する。作られる Skill はソースを scripts/ に持ち、配る仕組みは持たない。

なぜ決める必要があるか

ボード skills-creator-on-base の論点0〜4で決めた。いままでの skills-creator は、tool.json と宣言したツールを前提に scaffold と check を持ち、判定しなかった項目を合格にしていた。宣言したツールの仕組みは ACDR 0175 で基盤から消し、古い形は配布していないので考慮しないと決めたので、その前提で作り直す。消したのは、古いコード（src/skills-creator/src と tests）と、凍結していた src/skills-creator-v3 である。Skill のフォルダの tool.json ・ assets/tool.schema.json ・ 古い雛形5つも消した。手元で、Claude Code と Codex の両方が skills-creator を呼び、SKILL.md の手順どおりに動いた。scaffold の直後は、記入欄の2項目（SKILL.md と concrete スキーマ）だけが不合格になった。ボードの論点0は「記入欄の項目だけ」と書いたが、基盤の create が作る concrete スキーマは title と description が空なので、schemas.check も記入欄として不合格になる。

比較した案と、採らなかった理由

案採らなかった理由
作られる Skill にも配る手順（入口のビルドと dist.json）を持たせる作られる Skill は作った人がソースを持ち、配り方も決める。skills-creator が持つと、使う人の言語とビルドを縛る

108/// 先頭の --- で囲んだ YAML を、JSON の対応表にする。本文の始まりの行の位置も返す。
109fn frontmatter(lines: &[&str]) -> Result<(Map<String, Value>, usize), (String, usize)> {
110 if lines.first().map(|l| l.trim_end()) != Some("---") {
111 return Err(("1行目が --- でない。先頭の欄が無い".into(), 0));
112 }
113 let Some(end) = lines
114 .iter()
115 .skip(1)
116 .position(|l| l.trim_end() == "---")
117 .map(|p| p + 1)
118 else {
119 return Err(("先頭の欄を閉じる --- が無い".into(), 0));
120 };
121 let source = lines[1..end].join("\n");
122 let documents = YamlLoader::load_from_str(&source)
123 .map_err(|error| (format!("YAML として読めない：{error}"), end + 1))?;
124 match documents.into_iter().next() {
125 Some(Yaml::Hash(hash)) => {
126 let mut map = Map::new();
127 for (key, value) in hash {
128 let Yaml::String(key) = key else {
129 return Err(("先頭の欄のキーが文字列でない".into(), end + 1));
130 };
131 map.insert(key, to_json(value));
132 }
133 Ok((map, end + 1))
134 }
135 _ => Err(("先頭の欄が、キーと値の対応表でない".into(), end + 1)),
136 }

目的
