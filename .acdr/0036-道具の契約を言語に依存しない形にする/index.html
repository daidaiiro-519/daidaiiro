skills-creator の道具の契約は、呼ぶ側から観察できるものだけを規定し、道具を書く言語と配布の有無を利用者に委ねる。

なぜ、いま決めるのか

skills-creator は、利用者が自分で Skill を作るための Skill である。いまの道具の契約は、Rust でしか道具を作れない形になっている。バイナリで配布する形も契約の必須になっている。バイナリで配るのは、このリポジトリが Rust を選んだ結果であり、契約の要件ではない。また、skills-creator で Skill を作る人の多くは自分のリポジトリで使うので、配布を必須にすると不要な作業を課す。利用者は、この抽象の高さが合っていないと指摘した。ブレストボード skills-creator-language で4件の論点を決着させたので、ここに記録する。ACDR 0029 の「利用者の環境に Rust が無くても動く形で配る」は、Rust の組と配布（任意）の決まりとして引き続き有効である。

形の変化

何がいまの形これからの形
契約が規定する範囲Rust の crate の構成 ・ bin/ ・ 配布の形まで呼ぶ側から観察できるもの（2つの入口 ・ CLI の規約 ・ Skill のフォルダの求め方 ・ 外部の道具 ・ 層と許可辺）だけ
道具を書く言語Rust だけ公式の MCP の SDK が在る言語。組はいま Rust だけで、必要になったときに加える

外部の道具Rust の定数 EXTERNAL に宣言し、部品が名前を直書きするtool.json に宣言し、宣言の層が部品へ注入する

比較した案

どれも反証を通過しなかった案である ── 未解決のまま残っているものではない。

案採らなかった理由
Rust だけの契約を維持する利用者が自分の言語で道具を作れない。skills-creator の目的と、抽象の高さが合わない
配布の形を言語の組に置く配布を使わない人にも、組ごとに配布の形の宣言を求める。配布の仕組みの大半は言語に依存しないので、組ごとに持つ理由も無い
入口の置き場所（bin/）を契約に置く起動のコマンドを登録に書けば、置き場所に依存せずに呼べる
実行環境を必要としない実行ファイルを出せることを、言語の条件にするバイナリで配るのは Rust を選んだ結果であり、契約の要件ではない
外部の道具の宣言だけを tool.json へ移し、部品の直書きは残す利用者が呼ぶコマンドを差し替えられず、試験で偽物に差し替えられない
層の検査を no-more-spaghetti に任せるSkill が他の Skill を名指しで呼ぶ形になる

skills-creator の道具の契約を、言語に依存しない形にする提案である。

変更 3 件
この面の変更 3 件
  1. tool.json を新しく置き、CLI の起動のコマンドと外部の道具を宣言する
    CLI の起動のコマンドと外部の道具の宣言を、言語に依存しないファイルに置く。MCP の起動のコマンドは、ホストの形式の mcp.json で維持する（論点2・3）
  2. 部品は外部の道具の名前を直書きせず、宣言の層から渡されたコマンドを起動する。
    部品が外部の道具の名前を直書きせず、宣言の層から注入されたコマンドを起動する。利用者は tool.json だけを書き換えて差し替えられる（論点3）
  3. check は、入口を起動する1段目と、言語の組が持つ2段目の2段で検査する。
    検査を、全言語で共通の振る舞いの検査と、言語の組が持つソースの検査の2段に分ける（論点2）

完成イメージ ── acdr の場合

契約 ・ 言語の組 ・ 配布の分け方

置く先中身
契約（必須 ・ 言語に依存しない）CLI と MCP の2つの入口と、その起動のコマンド ・ CLI の規約（動詞 ・ --json ・ {ok, findings, data} ・ 終了コード 0/1/2）・ 1つの宣言から CLI と MCP を組む ・ Skill のフォルダは、渡された値か入口自身の位置から求める ・ 外部の道具は tool.json に宣言して注入する ・ 層と許可辺
言語の組（Rust が1つ目）tool/ の中の構成 ・ 入口の置き場所（bin/）・ 雛形 ・ 組み立てのコマンド ・ ソースの検査
配布（任意）dist を実行した人だけが使う。入口が bin/ に在ることを前提にし、導入スクリプトと CI の枠は全言語で共有する

Skill のフォルダ

tool.json を新しく置き、CLI の起動のコマンドと外部の道具を宣言する。

acdr/
  SKILL.md
  mcp.json     MCP の起動のコマンド（変わらない）
  tool.json    CLI の起動のコマンドと、外部の道具（新しく置く）
  bin/         入口（Rust の組が決める置き場所）
  tool/        Rust のソース（EXTERNAL の定数は無くなる）

tool.json

{
  "cli": {"command": "${CLAUDE_PROJECT_DIR:-.}/.claude/skills/acdr/bin/acdr", "args": []},
  "external": [
    {"name": "git",
     "command": "git",
     "reason": "git のリポジトリの版から、変更前の中身を取得する。git の差分を記録することが目的である"}
  ]
}

利用者が別の git を使うときは、"command" の1行だけを書き換える。

部品は、外部の道具を引数で受け取る

部品は外部の道具の名前を直書きせず、宣言の層から渡されたコマンドを起動する。

pub fn before_of(git: &Path, root: &Path, rev: &str, rel: &str) -> Option<String> {
    let done = Command::new(git)   // 渡されたコマンドを起動する
    …
}

]}}

check は2段で検査する

check は、入口を起動する1段目と、言語の組が持つ2段目の2段で検査する。

$ skills-creator check .claude/skills/acdr
1段目（振る舞い）
  OK  tool.json と mcp.json が在り、経路が絶対パスでない
  OK  宣言を JSON で返す（道具 4件）
  OK  宣言に無い旗を、終了コード 2 で断る
  OK  MCP の tools/list が CLI の宣言と一致する（4件）
  OK  別の作業場所から起動できる
2段目（ソース ── Rust の組）
  OK  層が crate に分かれ、許可辺が宣言どおりである
  OK  部品が外部の道具の名前を直書きしていない

言語の組が無い Skill（たとえば Python で書いた Skill）では、2段目は「実行しない」と出し、合格とは扱わない。
