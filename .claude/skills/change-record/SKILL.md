---

## 目的

**変更を、結果と理由の両方が見える形で提示する。**
差分ツールは結果しか出さない。**なぜそう変えたかは、差分の外に置き去りになる。**

**このSkillが作るのは、変更後の全文が読めて、
変更箇所を押すと「変更前」と「なぜ」が開く1枚のHTMLである。**

**これは正本へ当てる前に見せるものである。**
当ててから見せると、読み手は追認するしかない。
**当てる前に見せれば、まだ止められる。**

**ただし、直す前に確かめることが1つある。**
**その文書が、いま何を出す文書なのかである。**
出すものが変わっていれば、直すのは本文ではなく骨格である。

---

## 役割

- **その文書が何を出す文書かを、文書の外から取り、いまの骨格と照らす**
- 変更を1件ずつ、**何を・何から何に・なぜ**の3つ組にする
- 変更後の全文を描画して置く。断片だけを見せない
- 変更箇所に印を付け、押すと変更前と理由が開くようにする
- **理由を持たない変更を、提示に含めない**
- **正本へ当てる前に見せ、承認を得てから当てる**
- 設計判断を残すときも、同じ形を当てる

---

## 処理対象と成果物

### 処理対象

**これから変更しようとしている文書・コード・設計である。**
あるいは、これから記録する設計判断である。

**すでに当ててしまった変更も扱えるが、それは例外である。**
**本来は、当てる前に受け取る。**

### 成果物

**HTMLのArtifact 1枚である。**
変更後の全文と、変更箇所ごとの「変更前」「なぜ」を持つ。

## 入力の想定

| 受け取る情報 | 解釈・既定値 |
|---|---|
| 対象の文書 | 明示されなければ、これから変更しようとしている文書すべてを対象にする |
| **出すものを決めている先** | **明示されなければ、探して特定する**（Step 1）。見つからなければ、見つからないと書く |
| 変更前の内容 | **正本の現在の中身をそのまま取る**。すでに当ててしまった場合は、git の作業ツリーと HEAD の差から取る |
| 理由 | **明示されなければ、変更したときの判断を書き起こす。推測で埋めない** |
| 見せる範囲 | 明示されなければ、変更のあった文書の全文を置く |

## 実行手順

### Step 1: 何を出す文書かを、外から取る

**その文書が何を出すべき文書かは、その文書の中には無い。**
**中から取れば、旧路線の記述が、旧路線を残す根拠になる。**

| 対象 | どこから取るか |
|---|---|
| 研究・企画の章 | 成果物を決めている親文書。出すものの一覧があるところ |
| Skill ・ テンプレート | 対応する定義票と、呼び出し元の Orchestrator |
| コード | そのモジュールが満たすべき仕様の記述 |

**取ってきたものと、いまの見出しの並びを照らす。本文はまだ読まない。**
**見出しの並びだけで、出すものが出るかを見る。**

| 照らした結果 | 次に何をするか |
|---|---|
| 見出しの並びが、出すものを出している | **Step 2 へ進む** |
| **出していない** | **本文の校正に入らない。骨格の案を出して、先に合意を取る** |

**内部の整合性は、目的のずれを検出できない。**
旧路線を一貫して書いた文書は、5観点を全部通る。
**一貫しているほうが、ずれに気づきにくい。**

| 照らさないと起きること | 実際に起きた例 |
|---|---|
| **書くべき文書と違うことに気づかない** | 成果物が「測る道具の設計」に変わったのに、「観察研究をどう実施するか」の順のまま11か所を直して出した |

### Step 2: 対象の全文を読む

**変更する文書を、頭から終わりまで読む。**
**検索で当たりを付けて、その周りだけを読まない。**

| 読まないと起きること | 実際に起きた例 |
|---|---|
| **置換がすり抜ける** | `dataset/` で置換したので、`references/` で始まるパスが1つ残った |
| **読み手が止まる箇所を見落とす** | 全数625件と述べている文書に、200件を引く設計だった頃の seed 名が説明なしで残っていた |
| **見出しと中身が食い違う** | 見出しが「測定の対象」で、中身は観測と測定の両方だった |

**どれも検索では出ない**。変更した箇所の周りに無いためである。

**全文を読んでから、日本語の書き方の規約を当てる。**
**そのうえで、機械の検査を通す。**

### Step 3: 変更を3つ組にする

**1件ずつ、3つを揃える。**

| | 中身 |
|---|---|
| **どこ** | 文書名と節番号。読み手がその場所を開ける粒度で書く |
| **何から何に** | **変更前の原文をそのまま**。要約しない |
| **なぜ** | その変更をした判断。**何と食い違っていたか、何に揃えたか** |

**「なぜ」が書けない変更は、提示に含めない。**
書けないのは、変更の意図が自分でも掴めていないということである。
**掴めるまで、その変更は保留にする。**

**削除した箇所も1件として扱う**。本文から消えているので、
消えた場所に印を置き、押すと消した内容が出るようにする。

### Step 4: 作業コピーに当てて、全文を描画する

**正本を触らない**。作業コピーへ当ててから描画する。

```
正本      そのまま。まだ触らない
作業コピー 案を当てる。描画の材料にする
```

**断片だけを並べない**。前後の文脈が無いと、直しが読みやすくなったかを判断できない。

- マークダウンなら、見出し・表・引用・コードブロックを**描画した見た目**にする
- **生のマークダウン記法を貼らない**
- コードなら、変更後のファイルをそのまま置く

雛形は `references/change-view.html` にある。
マークダウンからの描画は `scripts/render.py` を使う。

**変更した文書が2つ以上あるなら、`scripts/tabs.py` で1枚にまとめる。**
**タブの中身は拡張子で決まる**。マークダウンは描画した見た目、HTML はそのままの見た目で置く。

```
python3 scripts/tabs.py <spec.json> <出力.html>
```

**HTML は `iframe` に流し込む**。そのままの見た目で見せるには、CSS を隔てるしかない。
親に混ぜると、両方の指定が打ち消し合う。届かなければ Shadow DOM へ落ちる。

**印が、その文書の内側のタブに隠れることがある。**
実際に4件とも隠れた。面の頭に変更の一覧を置き、押すとその印まで運ぶ。

### Step 5: 変更箇所に印を付ける

**変更後の本文のなかで、変わった箇所を `<mark>` で囲む。**

```
<mark class="chg" tabindex="0" role="button" aria-expanded="false"
      data-b="変更前の原文" data-w="なぜ変えたか">変更後の本文</mark>
```

- 押すと直下にパネルが開く。もう一度押すと閉じる
- キーボードでも辿れるようにする
- 上部に「すべて開く／閉じる」と、変更箇所の件数を置く

### Step 6: 開いて閉じることを確かめる

**描画して、実際に押す。**

```
1度押す   変更前と理由が出る
2度押す   閉じる
すべて開く／閉じる   両方向に効く
```

**`<span>` に block の見た目を期待したら、`display:block` を必ず書く。**
書かないと、`border-top` が折り返した行ごとに引かれて取り消し線に見える。

**`.pop[hidden]{display:none}` を忘れると閉じない。**
パネルに `display:block` を当てると、`[hidden]` に勝ってしまう。

### Step 7: 理由の欠けを確かめる

**3つ組が揃っていない件が残っていないかを見る。**

- 「なぜ」が「揃えるため」だけになっていないか。**何と何を揃えたかを書く**
- 「なぜ」が変更内容の言い換えになっていないか
- 変更前が要約になっていないか

### Step 8: 見せて、承認を得てから当てる

**Artifact を渡し、返事を待つ。**

```
承認された     作業コピーの内容を正本へ当てる
直しが入った   3つ組を直し、Step 3 からやり直す
止められた     当てない。正本はそのまま
```

**「当てました。確認してください」と書かない。**
それは承認ではなく追認を求めている。

---

## 出力形式

**Artifact の URL を渡し、チャットには次だけを書く。**

| 書くこと | 書き方 |
|---|---|
| 何件直したか | 数と、いちばん効いた1件 |
| いちばん効いた1件 | どこで、何が食い違っていて、何に揃えたか |
| 直していない箇所 | **理由が書けなくて保留にしたものがあれば、そう書く** |
| **何と照らしたか** | **Step 1 で外から取った先を書く。照らしていないなら、照らしていないと書く** |
| **全文を読んだか** | **読んだと書く。読んでいないなら、読んでいないと書く** |
| 正本の状態 | **まだ当てていないことを書く**。「当ててよいか」を聞く |

**変更の一覧をチャットに並べない**。それはArtifactの役目である。

## ガードレール

- **何を出す文書かを、外から取ってから直す**。文書の中の記述を、その文書を直す根拠にしない
- **骨格が合っていなければ、本文を直さない**。先に骨格の合意を取る
- **検査が見ていない範囲を、報告に書く**。直した件数だけを書くと、校正が済んだように読める
- **対象の全文を読んでから直す**。検索で当たりを付けて、その周りだけを読まない
- **正本へ当てる前に見せる**。当ててから見せない
- **理由を持たない変更を提示に含めない**。推測で理由を埋めない
- **変更前を要約しない**。原文をそのまま持たせる
- **断片だけを見せない**。変更後の全文を置く
- **生のマークダウン記法を貼らない**。描画した見た目にする
- **`.pop[hidden]{display:none}` を必ず添える**。無いと開いたまま閉じない
- **`<span>` を段落として見せるなら `display:block` を書く**。無いと罫線が行ごとに引かれる
- **描画して押すまで公開しない**。開閉が効くことを目で確かめる
- 外部のCDNやスクリプトを読み込まない。**1枚で完結させる**
