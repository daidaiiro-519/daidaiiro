# 設計判断を、この形で残す

**ADR は変更の記録である**。決めたことだけを書けば、差分ツールと同じものになる。
**決める前がどうだったかと、なぜ変えたかが要る。**

---

## 対応させる

| ADR の項目 | このSkillでどこに置くか |
|---|---|
| 決定 | **本文**。変更後の姿をそのまま置く |
| 背景 | **`data-b`**。決める前がどうだったか |
| 理由 | **`data-w`**。何と食い違っていて、何に揃えたか |
| 結果 | 本文の続き。決めたことで何が変わるか |

**選択肢と、採らなかった理由は別に置く。**
`data-w` に詰め込むと、押したときに読めない量になる。

---

## 1件の粒度

**決定1つにつき、印1つである。**
文書のどこが変わったかを、決定ごとに指せるようにする。

```
決定       条件2 に ADR を置く
本文       04 §2 の表の ADR の行
data-b     条件1 にも ADR を置いていた
data-w     条件1 に ADR があると、情報構造の支えが無い状態を作れない
```

---

## 書けないとき

**理由が書けない決定は、まだ決まっていない。**
**保留として、そう書く。**
決めたことにして理由を後から作ると、次に読む人が判断を追えなくなる。
