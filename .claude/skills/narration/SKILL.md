# 原稿から枚ごとの音声と尺を作るのを担当するSkill：narration

## 目的

スライドの原稿を、枚ごとの音声と尺にするときに使う。音声付きのスライド動画を作る場面で、
音声の側だけを受け持つ。動画への結合は、スライドを保持する側が受け持つ。

**このSkillが保持する知識は、声・読み方・合成の条件だけである。** スライドの並び方、
画像の置き場、動画の解像度は保持しない ── 保持すると、同じ知識が2か所に存在する。

---

## 役割

- 枚ごとの読み上げる文から、音声と、語と文の時刻を作る
- 音声の長さを測り、結合する側が画面を切るための尺として返す
- 文・声・エンジンからキーを作り、キーが在る枚を再合成せずに取り出す
- 読みの補正を辞書へ集約し、原稿と入力を書き換えない
- 手元での実行と、AWS側での実行の両方を、同じ命令で成立させる

---

## 処理対象と成果物

### 処理対象

枚の識別子と、読み上げる文を持つ入力（`narration.json`）。識別子は、スライドを保持する側が
出したものをそのまま使う ── **このSkillは採番しない。**

### 成果物

枚ごとの音声（mp3）と、語と文の時刻（marks）、および両者の場所と長さを持つ出力
（`narration.out.json`）。音声はキーの名前で置くので、名前そのものが再合成の判定になる。

---

## 入力の想定

| 受け取る情報 | 解釈・既定値 |
|---|---|
| `narration.json` を置いたフォルダ | 明示されなければ、いま作業しているフォルダを対象とする |
| 声 | 明示されなければ `narration.json` の指定を使う。指定が無ければ Takumi（日本語・ニューラル） |
| 読みの辞書 | 明示されなければ適用しない。`narration.json` の `lexicons` が名前を持つ |
| 音声の置き場 | 明示されなければ、入力のフォルダの下の `cache` とする |

---

## 実行手順

### Step 1: 入力を確認する

枚の識別子が、スライドを保持する側の識別子と一致するかを確認する。読み上げる文に読み仮名が
書かれていないかを確認する ── 読みの補正は辞書が持つ。

```
python3 scripts/cli.py plan <フォルダ>
```

合成せずに、どの枚が合成になり、どの枚が取り出しになるかが出る。

### Step 2: 合成する

```
python3 scripts/cli.py synth <フォルダ> [声]
```

キーが在る枚は取り出し、無い枚だけを合成する。出力に、音声・時刻・長さを書く。

### Step 3: 尺を確認する

出力の `durationMs` が、音声の長さと一致することを確認する。

```
python3 scripts/cli.py measure <音声のファイル>
```

**`durationMs` は音声の長さである。** 語と文の時刻の最後の印は、最後の語が始まる時刻であって、
音声の終わりではない ── 最後の印を長さとして扱うと、枚ごとに早く切り替わる。

### Step 4: 読みを直す

読み間違いが在れば、辞書へ登録する。原稿と入力は書き換えない。

```
python3 scripts/cli.py lexicon <辞書のファイル> <辞書の名前>
```

登録した名前を `narration.json` の `lexicons` へ書くと、合成の前に適用される。

### Step 5: 結合する側へ渡す

出力の枚の識別子で、スライドの画像と突き合わせる。映像の長さは `durationMs` で固定し、
通しは再符号化して繋ぐ ── 無変換で繋ぐと、時刻の差が累積する。

---

## 出力形式

| 出すもの | 形 |
|---|---|
| 合成の結果 | 枚数・合成した枚数・取り出した枚数・合計の長さ |
| 継ぎ目の出力 | `narration.out.json`（枚の識別子・キー・音声・時刻・形式・長さ） |
| 機械が読む形 | どの命令も `--json` を付けると出る。終了コードは 0 正常 ／ 1 検出あり ／ 2 誤用 |

## ガードレール

- **枚の識別子を、このSkillが採番してはならない。** 採番すると、枚の増減で識別子が他の枚へ移り、違う枚に音声が付く。しかもその誤りは機械では検出できず、動画を再生するまで判明しない
- **尺として、語と文の時刻の最後の印を使ってはならない。** 最後の印は最後の語が始まる時刻であり、音声の終わりではない。音声そのものから測る
- **読みの補正を、原稿と入力へ書いてはならない。** 原稿は人も読む文書であり、入力は音声専用の受け渡しである。どちらへ読み仮名を書いても、同じ語の修正が枚の数だけ発生する
- **再合成の判定を、ファイルの更新時刻で行ってはならない。** 取得のたびに時刻が変わる環境では、全部が新しいものとして扱われる。判定は、文・声・エンジンから作ったキーで行う
- **スライドの並び・画像の場所・動画の条件を、このSkillが保持してはならない。** 保持すると、スライドを保持する側と同じ知識が2か所に存在し、片方の変更がもう片方へ波及する
- **声を枚ごとに変えてはならない。** 聞き手は、声の変化を話者の交代として解釈する。教材の話者は1人である
- **環境を先に作ってはならない。同時に、環境の作り方を保持しない状態にしてもならない。** 既定は手元で実行し、AWS側で実行するための構成はテンプレートとして同梱する ── 先に作ると使っていない設備を保守することになり、作り方が無いと端末の状態に依存し続ける
- **結合の道具を、端末へ直接導入してはならない。** 版の差が動画の差になる。版を固定した公開のイメージを使う
- **道具に印字させてはならない。** 戻り値は `{ok, findings, data}` とし、印字と終了コードは入口が持つ ── 道具が印字すると、MCP から呼んだときに戻り値が空になる

## 参照

- `scripts/cli.py`: 唯一の入口。`plan` ・ `synth` ・ `lexicon` ・ `measure` を持つ
- `scripts/tools.py`: 道具の宣言。**能力の正本**であり、CLI と MCP はここから組む
- `scripts/lib/polly.py`: 合成の実行と、キーによる作り直しの判定
- `scripts/lib/mp3.py`: 音声の長さを、フレームの並びから測る。外部の道具に依存しない
- `scripts/tests/test_mp3.py`: 長さの測定を、実物の音声で検証する
- `references/narration.schema.json`: 入力の契約
- `references/narration.out.schema.json`: 出力の契約。`durationMs` の定義を含む
- `references/lexicon.example.pls`: 読みの辞書の例（W3CのPLS準拠）
- `infra/narration.yml`: AWS側で実行するための構成。`aws cloudformation deploy` で作る
- `.brainstorming-board/narration-skill/`: この設計を決めた5件の論点と、試作の記録
