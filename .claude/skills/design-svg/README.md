# svg-engine

宣言（節点・辺・囲み）から、その場でSVGを組み立てる描画エンジン。

**外部依存を保持しない。** 標準ライブラリ以外の import が1件も無く、配置アルゴリズムも
図形の重なりも自前で解いている。Python 3.9 以上があれば動く。

## 使う

```python
from svg_engine import render_figure

svg = render_figure(
    nodes=[{"id": "a", "label": "受付"}, {"id": "b", "label": "検証", "role": "focus"}],
    edges=[{"from": "a", "to": "b", "label": "渡す"}],
)
```

## 何を受け取れるか

```
python3 scripts/cli.py catalog   # 目録をJSONで出す
```

目録は、どの部品があり、それぞれがどんな値を読み、どんなトークンで見た目が決まり、
どの配置戦略が選べるかを持つ。**手で書いていない** ── 部品の関数が実際に読んでいる鍵を
構文木から抽出するので、部品を直せば目録も直る。

利用側の変換器を書く人は、これだけを参照すれば済む。**この目録が答えるのは「何を受け取れるか」
だけで、「何を表せるか」ではない。** 主張の名前と、それをどの部品でどう組むかの対応表は
利用側の持ち物である。

## 見た目を変える

3層で解決する。テーマの既定値 → 役割による上書き → その場の上書き。
役割の中身もテーマが `role.<名前>.<トークン名>` という平らな名前で持つので、
**新しい役割はテーマへ行を足すだけで増える**（エンジンには触れない）。

焼き上がったSVGは、生成後の外部CSSでも上書きできる。

## 配置

層状・環状・放射の木・格子の4つが同じ契約を返し、`layout=` で差し替える。
層状は Graphviz の `dot` と同じ系統（網状単体法で辺の長さの総和を最小化し、
等調回帰で層の中を詰める）。同じ図を `dot` にも解かせて突き合わせる物差しを
`scripts/tests/bench_layout.py` に持つ。

## 開発

```
pytest scripts/tests           # 試験
mypy                           # 静的検査（設定は pyproject.toml）
python3 scripts/tests/bench_layout.py    # 本家との突き合わせ
```

規律は3条 ── 下から上を呼ばない／層ごとに型が変わり前の層を飛ばせない／
契約は中立が所有し実装が所有しない。詳しくは design-svg Skill の
`references/knowledge/svg-engine-discipline.md` を読む。
