# 構造化データを正本として持つ基盤の Skill：schema-driven

## 目的

AI が扱うデータを、Markdown の文書ではなく、JSON Schema とそのインスタンスで持つときに使う。**いまは作成中で、道具はまだ無い。**

何を作るかは、宣言が持つ。宣言は `.brainstorming-board/schema-driven-base/product/decls/` にある。

---

## 役割

| 契約 | 何をするか |
|---|---|
| 作成 | スキーマから、必須のプロパティを持たないインスタンスを作り、足りないものを未記入として返す |
| 取得 | JMESPath 式でインスタンスから値を取り出す |
| 更新 | JSON Patch を適用し、未記入以外の検証エラーが無いときだけ書く |
| 削除 | インスタンスのファイルを消し、まだ指している参照を返す |
| 検証 | インスタンスをスキーマで検証する |
| 描画 | ページテンプレートとコンポーネントで、ディレクトリのインスタンスからページを組む |
| x-prompt | プロパティごとに、読むときと書くときの x-prompt を返す |

このほかに、注釈 x-ref と x-derive による参照と導出値の検査、承認記録、正本の複製の転写と差分の検査を持つ。

## 処理対象と成果物

### 処理対象

JSON Schema と、それに従うインスタンスのディレクトリ。

### 成果物

インスタンス、検証結果、検査結果、承認記録、ページ、転写した複製。

## ガードレール

- **道具ができるまで、ほかの作業から呼ばない**
- **core ではファイルを直接扱わない**。入出力は ports の trait を通し、`tool/core/clippy.toml` が std::fs を禁じる（ACDR 0121）
- **版は `tool/Cargo.lock` の1か所で決める**。ネットワークに出る機能を外す（ACDR 0122）

---

## 参照

- `tool/core/`: 中心。domain ・ application ・ ports を持ち、何にも依存しない
- `tool/adapters/`: 入ってくる側（CLI と MCP の受け口）と、出ていく側（ファイルシステム ・ jmespath）
- `tool/cli/` ・ `tool/mcp/`: 実行ファイル。アダプタを組み立てる
