# テーマ

**配色は、デッキごとに1本選ぶ。**
色の正本は `themes/<名前>.css` だけで、枚のCSSにも図のコードにも16進の値を書かない。

## 4本ある

| テーマ | 地 | 強調 | いつ選ぶか |
|---|---|---|---|
| `warm-paper` | 生成り | 赤茶 | 線画を多く置くとき。明るい地なので細い線が持ちこたえる |
| `deep-navy` | 濃紺 | 青緑 | 暗い会場で投影するとき。細い線は沈むので、面で見せる |
| `cool-paper` | 明るい灰青 | 藍 | 赤茶が題材と合わない技術寄りの回。強調が叫ばない |
| `print-mono` | 白 | 深い赤 | PDFにして刷る・配るとき。階層は2つまで |

**選ぶのは人ではなく、出力先である。**
投影なら会場の明るさが、配布なら紙が決める。題材の雰囲気で選ばない。

## 22のキーと、満たすこと

**4本とも同じ22のキーを持つ。**
1本だけ持つキーを作らない ── CSSの変数は未定義でも
エラーにならず、色が静かに欠落するだけなので、欠けは誰にも見えない。

| キー | 役割 | 満たすこと |
|---|---|---|
| `--ground` | ステージの地 | `--ink` を載せて 4.5:1 |
| `--surface` `--surface-2` | 表示面と、その2枚目 | `--ink` を載せて 4.5:1 |
| `--paper` | 明るい面 | `--on-paper` を載せて 4.5:1 |
| `--on-paper` `--on-paper-dim` | 明るい面の上の文字と補足 | 同上 |
| `--ink` `--dim` `--faint` | 本文・補助・最薄 | `--ground` の上で 4.5:1 |
| `--line` | 罫線・区切り | **比を課さない。情報を単独で担わせない** |
| `--accent` `--accent-dim` | 強調 | `--ground` と `--surface` の両方で 4.5:1 |
| `--on-accent` `--on-accent-dim` | 強調面の上の文字 | 対応する強調色の上で 4.5:1 |
| `--alert` `--gold` | 警告・補助の強調 | 比を課さない |
| `--mark` | 印（文字の背に敷く） | `--on-paper` を載せて 4.5:1 |
| `--canvas` | 図の下地 | `--diagram-line` を載せて **3:1** |
| `--diagram-line` | 線画の線 | `--canvas` と `--ground` の上で **3:1** |
| `--serif` `--sans` `--mono` | 書体 | ── |

数値の出どころは WCAG 2.2 で、文字が 4.5:1（達成基準 1.4.3）、
内容の理解に要る図形が 3:1（達成基準 1.4.11）である。

**`--line` にだけ比を課していない。**
罫線が情報を単独で運ぶなら、それは
`--diagram-line` を使う場面である。

## 検査

```
python3 references/themes/check.py <デッキのHTML...>
```

3つを検査する ── キーが4本のテーマで一致しているか、上の表の比を満たすか、テーマの区切りの外に
16進の直書きが残っていないか。

**検査するのは形だけである。**
配色が場に合うか、図が読めるかは、描画して目視で確認するしかない。

## 4本とも通っている

`check.py` は 2026-09-16 時点で0件である。

`warm-paper` は3件で止まっていたので、図の線を `#a8b09f` から `#6f7a63` へ、
強調を `#b64326` から `#ae3f23` へ濃くした（`--alert` も強調と同値のまま統一した）。
**4配色で同じ1枚を描いて見比べ、生成りの温かさも赤茶の印象も変わらないことを確認してから適用した。**

同梱していた ai-workshop の資料は、生成元に自分の色を持つ別の成果物である。
ここを直しても、あちらは変化しない。

## 新しいテーマを足すとき

`themes/` に1ファイル置き、22のキーすべてに値を与える。
`check.py` を実行してから使う。**足す前に、既にある4本のどれでも足りない理由を説明できるかを確認する。**
