# 助言型の手順：procedure

## 目的

助言型の Skill（advisor）を、原典の原文から作るときに使う（ACDR 0061）。
**判断基準の単位は、領域の原典が名前を付けて立てている概念である。** 章や文書の区切りで判断基準を作らない。

---

## advisor の条件

| 条件 | 中身 |
|---|---|
| 1つの advisor が扱う範囲 | 1つの領域（QA ・ DDD ・ ユースケースなど）の概念で括る |
| 原典 | その概念を立てた確立された原典。**原文を取得できるもの**に限る ── 概念を名付けた人や団体の一次文献、標準化団体や公的機関の文書、公式の枠組み、分野で定着した書籍 |
| 採らないもの | 原文を読まずに書いたまとめ、道具の説明書、個人の意見の記事、このリポジトリ独自の内容 |
| 原典の数 | 1つに限らない。1件の判断基準の中では、原典ごとに節を分け、原典どうしを総合した文を書かない |

---

## 9段の手順

| 段 | すること | 受け渡すもの |
|---|---|---|
| 1 | 原典の原文のファイルを受け取る。**取得は skills-creator の外で行う** | 原文のファイル。所在（書誌か URL）・ 取得した日 ・ sha256 を `references/archive/NOTES.md` に記録する |
| 2 | 章（文書）ごとの学習ノートを書く | `references/archive/notes/<番号>-<名前>.md`。原文のままの文は `>` の行（引用）にし、出どころを残す |
| 3 | ノートの節を、原典が立てている概念ごとに振り分ける | 概念の名前（原典の語）と、集める節の一覧。**この段で判断基準の単位が決まる** |
| 4 | 概念ごとに、集めた節の中身を構成要素へ分ける | 要素の並び。**原典の節の並びではなく、要素の種類（定義 ・ 規則 ・ 移行 ・ 比較 ・ 図 ・ 手順 ・ 例 ・ 注意 ・ 補足）の順に並べる** |
| 5 | 判断基準へ変換する | `references/criteria.json`。**どの文字列もノートの本文の一部にする**（ノートに無い文字列0件） |
| 6 | 図を SVG のファイルにして、判断基準に置く | `references/figures/*.svg`。描く道具は問わない。図の宣言は判断基準に置かず、ノートと同じ手元の置き場に置く |
| 7 | 形の後処理を適用する | 同じ内容の繰り返しと、表の形式の不整合を除去する |
| 8 | 回答の形 ・ 道具 ・ 試験を置く | `skills-creator scaffold <名前> --type advisor` が置く雛形のまま使う。変えてよいのは題 ・ 説明 ・ 判断基準の一覧だけである |
| 9 | 受け入れの検査を実行する | `skills-creator accept <advisor のフォルダ>` の7件と、人の目視 |

**他の Skill を名指しで呼ばない。** 原文の取得も図の描画も、どの道具を使うかは作る人が決める。

---

## 判断基準の書き方

| 扱い | 決まり |
|---|---|
| 確立された語彙（概念の名前 ・ 用語） | 原典の語のまま使う。言い換えない |
| 概念の要点 | 学習ノートの言葉（こちらの解釈）で書く。原典の文の並びをなぞらない |
| 原文のままの文（定義の引用など） | 学習ノートにだけ置く。判断基準へ持ち込まない |
| 原典の事例 | 丸ごと書かない。何を示す例かと、その構造 ・ 要点だけを書く |
| 作る側が作った例 | 置かない。原典に無い内容である |
| 出典 | 要素ごとに、原典 ・ 章と節 ・ 所在 ・ 取得した日 ・ 移し方を必須の欄にする |
| 見出し | 要素の種類の区分に、こちらで作った見出しを置かない。区分の名前はスキーマの種類の題が持つ |
| id | 概念の英語の短い名前（例：`aggregate` ・ `primary-actor`） |
| 関連する基準 | 原典が章どうしの参照を書いているときだけ置く |

---

## 受け入れの検査

**advisor の完成は、機械の7件がすべて合格し、人が目視したときである。**

| 番号 | 検査する対象 | 合格の条件 |
|---|---|---|
| 1 | 形 ── 判断基準と回答の例が、スキーマの検査に合格する | 検出0件 |
| 2 | ノートに無い文字列 ── 判断基準のすべての文字列が、学習ノートの本文の一部である | 0件（id ・ kind ・ svg ・ code と出典の欄は除く。Markdown の記法は外して照合する） |
| 3 | 取り込んだ引用 ── 学習ノートの引用（`>` の行）が、判断基準に無い | 0件 |
| 4 | 概念の単位 ── 各判断基準の題が、学習ノートの見出しに在る | 不一致0件 |
| 5 | 図の同梱 ── 判断基準が指す SVG が Skill の中に在り、SVG として読める | 欠け0件 |
| 6 | 他の Skill の名前 ── SKILL.md ・ スキーマ ・ 道具に、同じ置き場所の他の Skill の名前が無い | 0件 |
| 7 | 試験 ── 雛形の試験（5件）が通る | 失敗0件 |
| 8（人） | 判断基準と回答の頁を、1200px と 390px の幅で描画して読む | 表示の不整合 ・ 重複が無い |

**文字列の照合では、要点が原典の意味を正しく捉えているかまでは検査できない。** それは学習ノートを書く段で、原文を読んだ人が負う。
