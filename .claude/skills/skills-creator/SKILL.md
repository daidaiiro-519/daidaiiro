# 型に従う Skill を作り、検査する Skill：skills-creator

## 目的

どの AI ツールに置いても、正しいときに呼ばれ、手順どおりに動く Skill を作る。そのために、Skill が必ず持つものを型（`skills-creator/skill@v1` と `skills-creator/tool@v1`）で決め、作るときの雛形と、型に合うかの検査を持つ。

型が決めるのは、必ず書く項目と並びだけである。各項目の中身は、Skill を作る人が書く。

## 役割

- 新しい Skill のフォルダに、SKILL.md の雛形 ・ tool.json ・ スキーマの雛形を置く（scaffold）
- Skill のフォルダを、項目ごとに5つの結果で検査する（check）
- 型の判定は、SKILL.md を読み取った結果を基盤のエンジンに型のスキーマで検査させて得る。この Skill は判定を書き直さない
- スキーマの検査と、固有のツールの宣言の検査は、基盤の結果を返す

## 入力の想定

| 受け取る情報 | 解釈 ・ 既定値 |
|---|---|
| Skill のフォルダ | scaffold は、まだ無いフォルダを受け取る。フォルダの名前が Skill の name になる |
| 種類（`--kind`） | scaffold が置くスキーマの種類。a-z で始まる a-z ・ 0-9 ・ - で書く |
| 足すもの | ページテンプレート（`--pages`）・ 固有のツールの宣言（`--tools`）・ AI が読む文書（`--refs`）。求められたときだけ置く |
| 検査の段（`--level`） | 明示されなければ、書いたその場の段（`source`）を見る。実行ファイルが入ったあとは `dist` を渡す |

## 実行手順

### Step 1: 雛形を置く

```
scripts/skills-creator scaffold <Skill のフォルダ> --kind <種類> [--pages] [--tools] [--refs]
```

置くのは SKILL.md ・ tool.json ・ `assets/<種類>.schema.json` の3つと、求められたものだけである。空のフォルダは作らない。雛形の中身は [雛形の置き場所](assets/templates/SKILL.md.tmpl) が持つ。

### Step 2: 記入欄を書き換える

雛形は、記入する所を二重の波括弧で示す。全部を書き換える。

- 先頭の欄には、Agent Skills の仕様の欄（name ・ description ・ license ・ compatibility ・ metadata ・ allowed-tools）だけを書く
- 本文には、目的 ・ 役割 ・ 入力の想定 ・ 実行手順 ・ 出力形式 ・ ガードレールの6つの節を、この順に書く。ほかの節は足してよい
- ファイルは、Skill のフォルダからの相対パスで指す
- スキーマの各欄の書き方は、`scripts/schema-driven prompt` が x-prompt で返す

### Step 3: 検査する

```
scripts/skills-creator check <Skill のフォルダ> [--json]
```

項目ごとに、id と結果が返る。何を見るかは [型のスキーマ](assets/skill.schema.json) と [tool.json の型](assets/tool.schema.json) が持つ。

### Step 4: 不合格と判定不能を0件にする

不合格の項目は、中身に書かれた行を直す。判定不能は、基盤のエンジンが答えなかったことを示すので、エンジンが在るかと版を確かめる。警告は合否に入れない。名前が宛先になっているかは、人がレビューで見る。

### Step 5: 配布物を確かめる

実行ファイルが入ったあとで、配布物の段を見る。

```
scripts/skills-creator check <Skill のフォルダ> --level dist
```

書いたその場の段で合格していなければ、配布物の段の項目は対象外になる。

## 出力形式

| 結果 | 意味 |
|---|---|
| 合格（`pass`） | 型に合う |
| 不合格（`fail`） | 型に合わない。中身に、直す行か理由がある |
| 警告（`warn`） | 合否に入れない。件数と箇所だけを返す |
| 判定不能（`unknown`） | 基盤のエンジンが答えなかった |
| 対象外（`skip`） | 前提の項目が不合格か、その段で見ない |

合格は、不合格が0件かつ判定不能が0件のときだけである。終了コードは、合格なら 0、そうでなければ 1、使い方の誤りなら 2 である。`--json` を付けると、`ok` ・ `level` ・ `results`（`id` ・ `label` ・ `status` ・ `detail` ・ `from`）・ `counts` を持つ JSON を返す。

## ガードレール

- **型の判定を、この Skill の中で書き直さない**。判定は型のスキーマが持ち、基盤のエンジンが行う。2か所に置くと、片方だけ直されたときに結果が食い違う
- **公開した型の版を書き換えない**。中身を変えるときは、版を上げた新しい名前（`@v2`）で足す。前の版で作った Skill が、別の決まりで検査されるのを防ぐ
- **警告を不合格にしない**。名前の一覧は閉じないので、例として名前を挙げた正しい本文まで落とす
- **既に在るフォルダに雛形を置かない**。書いた中身が消える
- **本文に、特定の AI ツールの置き場所 ・ ツール専用の変数 ・ 絶対パスを書かない**。ほかの AI ツールでは解決しない
