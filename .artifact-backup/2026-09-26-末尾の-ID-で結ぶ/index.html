末尾の ID で結ぶ

シミュレーション ／ 3言語で実測

シナリオのテストが在るかを、名前の末尾で確かめる

テストの名前の末尾にシナリオID を置く。道具はソースを1行も読まず、申告（bind）も要らない ── 見るのは、テスト実行器が出した識別子の一覧だけである。

仕様の側 ── シナリオ2本

SC-01J7Q4M   明細が0件のとき、確定できない
SC-01J7Q4N   明細が1件あれば、確定できる

Go の識別子は - を使えないので SC_01J7Q4M になる。道具は _ を - に直してから、末尾であることを見る。

末尾に置くと、照合を厳しくできる。「含む」ではなく「末尾である」を要求できるので、TestSomething_SC-01J7Q4M_old のような紛れ込みを弾ける ── 先頭に置くと「含む」しか選べない。絞り込み（-run TestConfirm ・ -k 確定）が振る舞いの名前で効き、一覧も振る舞いの順に並ぶ。

実行器が列挙する ── これが道具への入力である

go test -list
example.com/shop/order.TestConfirmFailsWhenNoLines_SC_01J7Q4M
example.com/shop/order.TestConfirmSucceedsWithOneLine_SC_01J7Q4N
example.com/shop/order.TestConfirmBoundaries_SC_01J7Q4N
pytest --collect-only

tests/test_order.py::test_確定できる_境界_SC_01J7Q4N
tests/test_order.py::test_確定できる_明細が1件_SC_01J7Q4N
node --test (tap)

order.test.mjs::明細が1件あれば、確定できる SC-01J7Q4N
order.test.mjs::確定の境界 SC-01J7Q4N

SC-01J7Q4N には、境界値ごとに分けたテストが2本付いている。

道具の判定 ── 3言語とも同じ

① そろっている（1つのシナリオに2本付いていてもよい）

○ SC-01J7Q4M　1 本　TestConfirmFailsWhenNoLines_SC_01J7Q4M
○ SC-01J7Q4N　2 本　TestConfirmBoundaries_SC_01J7Q4N ・ TestConfirmSucceedsWithOneLine_SC_01J7Q4N

② テストを消した

○ SC-01J7Q4M　1 本
× SC-01J7Q4N　テストが無い

③ 名前から ID を落とした

○ SC-01J7Q4M　1 本
× SC-01J7Q4N　テストが無い
× 仕様の外に在るテスト　example.com/shop/order.TestConfirmOK_…　常時ゼロ（落とす）

④ ID のあとに何か付いている

含むで照合　○ pkg.TestSomething_SC-01J7Q4M_old　← 通ってしまう
末尾で照合　× テストが無い　← 弾ける

入れ子と分割は、渡す側の変換で揃う

実行器入れ子 ・ 分割を列挙に出すか変換
Go go test -list出さない ── 小分け（t.Run）は実行時だけ要らない
Python pytest --collect-only出す ── …_SC_01J7Q4N[lines0]sed 's/\[.*\]$//'
TypeScript node --test出す ── 字下げで親子が分かる字下げのある行を取らない

どれも利用者の側の変換1行で済む。道具は3言語とも同じコードのままである。

この形にすると、要らなくなるもの

いまの形名前で結ぶ形
AI が bind で申告する要らない
対応表 bindings.json を道具が持つ要らない ── 一覧から導ける
言語ごとの雛形要らない
ソースを読む ・ tree-sitterしない（変わらず）

ブレストボードの保留「AI が申告しないまま実装したと主張できる」が、そのまま消える ── 名前に ID が無ければ「テストが無い」と出るからである。

これでも見えないもの

カバレッジは、コードの性質ではなく仕様の性質になる ── シナリオにテストが無ければ「テストが無い」、テストにシナリオが無ければ「仕様の外」。足りないときは、シナリオを書き足すか、そのテストを消すかの二択である。

中身は1文字も見ていない。TestSC_01J7Q4M_… の本体を空にしても、一覧には載り、判定は ○ のままである（実測）。そこは規則（CodingSkills）と CI の領分で、道具の責務の外にある。

決めたこと

1つのシナリオに、テストは何本でもよい境界値ごとに分けるのは普通である ── 実測でも SC-01J7Q4N に2本付いた。0本だけを不合格にする
ID は名前の末尾に置く照合は「末尾である」。_ は - に直してから見る
シナリオを持たないテストは、落とす論点3 の「仕様の外に出られなくする」がそのまま効く ── テストを1本書くたびに、対応するシナリオが仕様に要る。両方向が塞がる

この頁の出力は、Go 1.27 ・ pytest 9.0.2 ・ Node 24 で実際に流したものである（2026-09-27）。道具の側は3言語とも同じコードで、言語を1つも知らない。
