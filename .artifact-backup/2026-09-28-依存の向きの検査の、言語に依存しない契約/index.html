なぜ、いま決めるのか

規則ファイルの依存の向きの規則12件は、すべて cargo build か go build を呼んでいた。Skill が保持する inward は1件も呼ばれておらず、依存の宣言をコンパイルで強制する道具が無い言語では、依存の向きの規則を書けなかった。inward に置き場所だけを渡すと、5言語で逆の並びを検出せず、層を宣言しないモジュールへの参照は9言語すべてで報告されなかった。no-more-spaghetti のブレストボードの論点11 〜 13 で検討し、2026-09-28 に3件とも決着した。

案採らなかった理由
言語の道具（cargo build ・ go build）だけで検査する依存の宣言をコンパイルで強制する道具が無い言語では、依存の向きの規則を書けない
層ごとに読み込みの名前を規則ファイルへ明示する書き忘れを検出できない。作業領域の中の名前を知る手段が無いので、どの参照が未解決かを判定できない
言語ごとの抽出器に、対応を個別に持たせる言語を足したときに何を満たせばよいかが決まらない。測った言語とリポジトリに合わせただけの仕組みになる
成果物ごとに規則ファイルを分ける論点10 で退けた。$schema の相対の経路が壊れ、分ける利点は実測で消えた
