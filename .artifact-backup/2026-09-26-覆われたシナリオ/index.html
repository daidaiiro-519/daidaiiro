覆われたシナリオ

完成イメージ ／ 試作に実装して、7言語で流した

道具が知るのは、2つの集合だけ

仕様が要るシナリオと、テストの側が覆ったシナリオ。道具はこの2つを引き算するだけで、テストをどう書いたか ・ どの言語か ・ どの実行器かを1つも知らない。

破線は利用者のリポジトリの側、実線は道具の側。覆った集合の作り方は利用者が選ぶ。

要件をどう満たすか

R1 シナリオのテストが在るか走ったシナリオが記録に載る
R2 言語を知らない道具が読むのは1行1ID の文字列だけ
R3 ソースを読まない書き出すのはテスト自身
R4 申告を信じない記録は、そのテストが実際に走ったときにしか出ない
R5 無い側へ倒れる忘れた ・ 飛ばした ・ 書き間違えた、どれも「無い」

ひと回り ── 利用者の CI で起きること

2

AI が、テストを書く ── シナリオを名乗る1行を入れる

AI ／ 利用者のリポジトリ 
func TestConfirm(t *testing.T) {
	t.Run("明細が0件なら確定できない", func(t *testing.T) {
		scenario("SC-01J7Q4M")

	})
	t.Run("明細が1件あれば確定できる", func(t *testing.T) {
		scenario("SC-01J7Q4N")
		…
	})
}

名乗る場所は、小分けの中でも分割の中でもよい。名前の規約は要らない。

3

CI が、テストを走らせる

CI ／ いつもの実行器 
$ SCENARIO_TRACE=covered.txt go test ./...
ok  	example.com/e/order	0.001s

$ cat covered.txt
SC-01J7Q4M
SC-01J7Q4N

名乗る関数は、利用者の側に置く補助1つ（標準ライブラリだけ）。

func scenario(id string) {
	if p := os.Getenv("SCENARIO_TRACE"); p != "" {
		f, _ := os.OpenFile(p, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0o644)
		defer f.Close()
		f.WriteString(id + "\n")
	}
}
4

CI が、道具に渡す

道具 ／ 引き算 
$ schema covered covered.txt AGG-01J7Q4K
○ SC-01J7Q4M　明細が0件のとき、確定できない
○ SC-01J7Q4N　明細が1件あれば、確定できる
覆った 2/2 ／ 見つかったこと 0 件

宣言ID を渡すと、その宣言のシナリオだけを要る集合にする ── 実装の PR の範囲である。終了コードは 0 ／ 1 で、CI はこれで止まる。

壊し方 ── どれも「無い」側へ倒れる

① 名乗る1行を忘れた
○ SC-01J7Q4M　明細が0件のとき、確定できない
× SC-01J7Q4N　明細が1件あれば、確定できる　── テストが無い
② テストを飛ばした（t.Skip）
○ SC-01J7Q4M　明細が0件のとき、確定できない
× SC-01J7Q4N　明細が1件あれば、確定できる　── テストが無い
③ ID を書き間違えた（SC-01J7Q4X）
○ SC-01J7Q4M　明細が0件のとき、確定できない
× SC-01J7Q4N　明細が1件あれば、確定できる　── テストが無い
× SC-01J7Q4X　── 仕様に無いシナリオを名乗っている
覆った 1/2 ／ 見つかったこと 2 件　（終了コード 1）

「在る」と偽る道は1つだけ ── 関係の無いテストに、実在する ID を名乗らせたとき。それは中身の保証で、道具の責務の外である。

道具の中身

pub fn coverage(required: &BTreeSet<String>, covered: &BTreeSet<String>) -> Coverage {
    Coverage {
        uncovered: required.difference(covered).cloned().collect(),
        unknown:   covered.difference(required).cloned().collect(),
    }
}

これで全部である。文字列の規則も、言語の知識も、実行器の知識も持たない。試験は3件足して、試作の全体で通っている。

選べる作り方

作り方手間壊れ方
既定 ── テストが走ったときに名乗る補助の関数1つ無い側だけへ倒れる
簡易 ── テストのファイルを文字列で探す1行在る側へも倒れる（註釈 ・ 飛ばしたテスト）

どちらでも道具に渡すものは同じ1行1ID のファイルで、道具はソースを読まない。Go 1.27 ・ pytest 9.0.2 ・ Node 24 ・ cargo 1.98 ・ Ruby 4.0.7 ・ PHPUnit 11.5 ・ JUnit 5.11（JDK 25）で実行した（2026-09-27）。
