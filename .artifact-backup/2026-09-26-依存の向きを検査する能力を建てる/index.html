依存の向きを検査する能力を建てる

提案まだ承認を得ていない。適用してはならない2026-09-26
決めること ── 承認か差し戻しを返すのは、この1件である
許可辺の正本を規則ファイルへ一本化し、依存の向きを検査する能力を、言語に依存しない部分と言語の具体へ分離して建てる。

なぜ、いま決めるのか

いまの検査は、許可辺を2か所が宣言している ── 層の並びは規則ファイルの order が宣言し、検査へは禁じる名前を引数で別途渡している。ずれても、どの検査も検出しない。実際にずれており、検査が禁じる contract と mcp_server の2つは、order にも layers にも1件も無い。加えて、いまの検査は取りこぼしを4件保持する。別名で束縛した動的な読み込み、脚本の実行、層を越える相対の参照、および空振り（対象が0件、禁じる名前の誤記）である。空振りが合格になるので、引数を書き間違えた規則は永久に合格する。取りこぼしは、違反をそのまま構造へ固着させ、誰も気づかない。

実現の形

検査を3つへ分ける。辺の導出は units を受領して「層名から、参照してはならない層」を導出し、言語を認知しない。走査は識別子をその言語の名前へ変換し、構文木で参照を集める。入口は両者を結び、終了コードを返す。入口が、両方を認知する唯一の場所である。新しい言語を足すとき触るのは入口の1か所で、対応表はこの時点では作らない（該当する言語が1つだけである）。偽陰性は2段で測る。経路表の各行へ違反を注入して検出を確認し、検査の側へ変異8件を注入して事例が殺せることを確認する。

適用先

no-more-spaghetti の契約（rules.schema.json）と、層を検査する部品（validate.py ・ init.py）。リポジトリの規則ファイル（.coding-rules/rules.json）の層の宣言と9件の規則。検査の実体（.coding-rules/tools/）。

案採らなかった理由
引数を正本とし、order と layers を除去するコンパイラが検査する成果物は引数を保持しないので、向きの宣言がどこにも残らない。規則ファイルから、向きが検査されていることを読めなくなる
禁じる名前を規則の採用範囲（散文）へ記述する採用範囲は自由記述で、機械が消費しない。引数とずれても検出しない ── いまの欠陥が残る
平らな配列を維持し、接頭辞を契約で強制する接頭辞は文字列の約束にとどまる。34件が1本の並びである以上、成果物をまたいだ辺が許可されていると読める状態が解消しない
外部の道具（import-linter）へ戻す文字列でモジュールを読み込む箇所を見ない。実測で、9つの成果物すべてを合格と判定した
検査の実体を Skill へ配置するSkill は道具を保持しない。構文木の走査は言語の具体であり、2つ目の言語で分岐が Skill の内部に発生する
9件の規則を1件へ統合するどの成果物がどの言語かを検査の側が判定することになり、言語の対応表をいま作ることになる。コンパイラが検査する成果物の形とも不整合になる
件数や網羅率を完了の基準にする件数の取得には道具の出力の解析が要る。網羅率は「実行したか」しか測らず、取りこぼしは網羅率が満ちても残る

承認後に実施すること

  • 契約へ units を新設し、平らな order と layers を除去する
  • validate の層の検査を units へ対応させ、layers のキーのうち order に無いものを検出する
  • init を units へ対応させる
  • 検査を .coding-rules/tools/inward/ の3つへ分け、取りこぼし4件を塞ぐ
  • 空振りと符号化の誤用を、終了コード2へ移す
  • 事例と変異8件を .coding-rules/tools/inward/tests/ へ置く
  • 規則ファイルの units を書き直し、9件の規則から引数の許可辺を除去する
  • 検査自身を検査する規則を1件足す
  • contract と mcp_server を層として宣言する
  • skills ・ board ・ docs の3層の扱いを決める（検査を付けるか、宣言から除去するか）
