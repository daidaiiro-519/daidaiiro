なぜ、いま決めるのか

論点5 で、人が承認するときに読むのはシナリオの射影だけと決めた。しかし試作の仕様では、ユースケース4件のうち3件がシナリオを1件も保持せず、操作17件のうち11件に、その操作を実行するシナリオが無かった。validate はそれを1件も検出しなかった。シナリオが操作を値（when）で指す形では、対応が形の検査の外に在るためである。論点12 として立て、2026-09-27 に決着した。その過程で、論点1 ・ 2 ・ 3 ・ 4 ・ 5 ・ 8 の記述が、論点11 で採用しなかった対応表の形のまま残っていることが判明した。

比較した案

案採らなかった理由
シナリオは宣言の直下に置いたまま、拡張の語 x-each-in で値の対応を照合する項目の構造で表せることを、値の対応で書くことになる。基盤に拡張の語が1つ増え、対応は形の検査の外に残る
ユースケースだけに、シナリオを1件以上求める操作ごとには検査しない。2操作のうち1つにしかシナリオが無いユースケースが通過し、集約の操作7件も対象にならない
ユースケースの射影に、書き換える集約のシナリオを集めて出す集約のシナリオは集約の規則を検査するもので、ユースケースの目的を検査しない
書いている途中も、ゼロを求める論点4 と矛盾する。宣言を書いてからシナリオを足すまでは、正当にこの状態になる

承認後に実施すること

  • 状態を accepted にして組み直し、記録をコミットする
  • 試作の形を正本へ起こすときに、節の置き場所（操作の下）を基盤の契約として移す
  • AI が11件のシナリオを足し、ユースケースの射影で人が承認できるかを確認する

下に並ぶのは、この決定を採ったときに何がどう変わるかである ── 上の決定の具体である。

シナリオを操作の下に置いて操作ごとに1件以上を求め、決着済みの論点の記述を論点11 の結び方に統一する提案である。

328/// 仕様の木を読む ── **走査する場所は、この根1つだけである**（契約）。
329///
330/// **読むのは仕様だけである。** ソースも成果物も走査しない ──
331/// 成果物の一覧は外から受け取る。
332///
333/// 並びは道から決める ── **同じ木からは、同じ並びが出る**（冪等である）。
334pub fn read_spec_tree(root: &std::path::Path) -> Result<Vec<SpecFile>, String> {
335 if !root.is_dir() {
336 return Err(format!("仕様の根が無い： {}", root.display()));
337 }
338 let mut out = Vec::new();
339 let mut stack = vec![root.to_path_buf()];
340 while let Some(dir) = stack.pop() {
341 let entries =
342 std::fs::read_dir(&dir).map_err(|e| format!("読めない： {} ── {e}", dir.display()))?;
343 for e in entries {
344 let p = e
345 .map_err(|e| format!("読めない： {} ── {e}", dir.display()))?
346 .path();
347 if p.is_dir() {
348 stack.push(p);
349 continue;
350 }
351 if p.extension().and_then(|x| x.to_str()) != Some("json") {
352 continue;
353 }
354 let text = std::fs::read_to_string(&p)
355 .map_err(|e| format!("読めない： {} ── {e}", p.display()))?;
356 let decls = read(&text).map_err(|e| format!("形が違う： {} ── {e}", p.display()))?;
357 let rel = p
358 .strip_prefix(root)
359 .map_err(|_| format!("根の外に在る： {}", p.display()))?
360 .to_string_lossy()
361 .replace('\\', "/");
362 out.push(SpecFile { path: rel, decls });
363 }
364 }
365 out.sort_by(|a, b| a.path.cmp(&b.path));
366 Ok(out)
367}

385pub fn root_findings(files: &[SpecFile], root_kind: &str) -> Vec<Finding> {
386 let mut out = Vec::new();
387 let mut at_root = Vec::new();
388 for f in files {
389 for d in f.decls.iter().filter(|d| d.kind == root_kind) {
390 if f.at_root() {
391 at_root.push(d.id.clone());
392 } else {
393 out.push(Finding::NotAtRoot(format!("{} は {} に在る", d.id, f.path)));
394 }
395 }
396 }
397 match at_root.len() {
398 0 => out.push(Finding::RootMissing(root_kind.to_string())),
399 1 => {}
400 _ => out.push(Finding::RootDuplicated(at_root.join(" ・ "))),
401 }
402 out
403}

405// ── ⑧ 節と、対応表 ──────────────────────────────────────────
406//
407// **基盤が知るのは、ID を持つ節と、外の識別子だけである。**
408// その節を何と呼び、識別子が何を指すかは、注入する側が決める。
409 
410/// ID を持つ節。基盤は `id` と `name` しか読まない。
411#[derive(Debug, Deserialize, Serialize)]
412#[serde(deny_unknown_fields)]
413pub struct Node {
414 pub id: String,
415 pub name: String,
416 /// 注入する側だけが読む中身。基盤は形を見ない。
417 #[serde(default)]
418 pub body: serde_json::Value,
419}
420 
421/// テストの一覧を読む ── **契約は、1行1識別子のテキストである。**
422///
423/// 空行と `#` で始まる行は無視する。**それ以外は、1文字も解釈しない。**
424/// 実行系の生の出力をそのまま渡してはならない ── 一意な識別子を作るのは渡す側である
425/// （Rust の `--list` は関数名だけを出し、crate の道を出さない。実測）。
426pub fn read_test_list(text: &str) -> BTreeSet<String> {
427 text.lines()
428 .map(|l| l.trim())
429 .filter(|l| !l.is_empty() && !l.starts_with('#'))
430 .map(|l| l.to_string())
431 .collect()
432}

434/// 対応表 ── 節の ID と、外の識別子を結ぶ。
435///
436/// **結ぶのは、外から申告された文字列である。**基盤は外を走査しない。
437#[derive(Debug, Default)]
438pub struct Bindings {
439 map: BTreeMap<String, BTreeSet<String>>,
440}
441 
442impl Bindings {
443 pub fn new() -> Self {
444 Self::default()
445 }
446 /// 1行入れる。同じ節へ複数の識別子を結べる。
447 pub fn bind(&mut self, node_id: &str, external: &str) -> &mut Self {
448 self.map
449 .entry(node_id.to_string())
450 .or_default()
451 .insert(external.to_string());
452 self
453 }
454 /// 表の中身を、そのまま並べる ── 書き出す側が形式を決める。
455 ///
456 /// **基盤は、どの形式で保存するかを知らない。**
457 pub fn pairs(&self) -> Vec<(String, String)> {
458 self.map
459 .iter()
460 .flat_map(|(k, vs)| vs.iter().map(move |v| (k.clone(), v.clone())))
461 .collect()
462 }
463 pub fn node_ids(&self) -> BTreeSet<String> {
464 self.map.keys().cloned().collect()
465 }
466 pub fn externals(&self) -> BTreeSet<String> {
467 self.map.values().flatten().cloned().collect()
468 }
469}
470 
471/// 宣言の中の、ID を持つ節を全部集める。
472pub fn node_ids(decls: &[Decl]) -> BTreeSet<String> {
473 decls
474 .iter()
475 .flat_map(|d| d.nodes().into_iter().map(|x| x.id.clone()))
476 .collect()
477}

479/// 3つの引き算。**推論は1つも要らない。**
480#[derive(Debug, PartialEq, Eq)]
481pub struct Drift {
482 /// 宣言にあって、対応が無い
483 pub unbound_nodes: BTreeSet<String>,
484 /// 外にあって、対応が無い
485 pub unbound_externals: BTreeSet<String>,
486 /// 対応表にあるが、外に無い（消えたか、名前が変わった）
487 pub dangling: BTreeSet<String>,
488}
489 
490impl Drift {
491 pub fn is_empty(&self) -> bool {
492 self.unbound_nodes.is_empty()
493 && self.unbound_externals.is_empty()
494 && self.dangling.is_empty()
495 }
496}
497 
498/// 節の ID・対応表・外から受け取った識別子の列を、引き算する。
499pub fn drift(nodes: &BTreeSet<String>, b: &Bindings, externals: &BTreeSet<String>) -> Drift {
500 let bound_nodes = b.node_ids();
501 let bound_ext = b.externals();
502 Drift {
503 unbound_nodes: nodes.difference(&bound_nodes).cloned().collect(),
504 unbound_externals: externals.difference(&bound_ext).cloned().collect(),
505 dangling: bound_ext.difference(externals).cloned().collect(),
506 }
507}
508 
509/// 引き算の結果を、見つかったことへ移す。
510pub fn audit_bindings(
511 nodes: &BTreeSet<String>,
512 b: &Bindings,
513 externals: &BTreeSet<String>,
514) -> Vec<Finding> {
515 let d = drift(nodes, b, externals);
516 let mut out = Vec::new();
517 out.extend(d.unbound_nodes.into_iter().map(Finding::UnboundNode));
518 out.extend(
519 d.unbound_externals
520 .into_iter()
521 .map(Finding::UnboundExternal),
522 );
523 out.extend(d.dangling.into_iter().map(Finding::Dangling));
524 out
525}
