# AI活用ワークショップのアンケート・効果測定案

目的の明確化率（AIで実現したい目的を、視聴前より明確に書けたか）と目的達成率の2つを主軸にし、業務別のAI活用、チームでの振り返り、個人とチームの変化を併せて報告する。AI活用を促進する基盤づくりの指標は、終了時アンケートとポータルの記録から取る。段階評価による自己申告、具体的な行動の説明、チームで使ってもらった記録を組み合わせる。人気投票は共有会の表彰として扱う。

本書は運営がMicrosoft Formsへ転記するための設問案である。フォームの作成・配信はまだ行っていない。回答の所要時間は8分を目安にし、開始前に少人数で試して設問量を調整する。この設問と尺度は今回の企画に合わせて作ったもので、妥当性を検証済みの標準尺度ではない。

## 実施時点と回答の扱い

| 項目 | 設計案 |
|---|---|
| 事前 | 10月、準備期間の希望者が、教材を視聴する前に回答する |
| 参加申込 | 1月、教材をすべて視聴したあとに回答する。事前と同じ設問で目的を書き、参加を申し込む。人は具体を知って初めて目的を思い描けるため、目的は教材のあとに決める |
| 終了時 | 3月の最終共有会のあとに回答する |
| 回答者の同定 | Microsoft Forms の Record name で回答者名を記録し、時点ごとのフォームを氏名で突き合わせる。手入力のIDは設けない |
| 冒頭の属性 | 現在の職種（開発／PM／PL／その他）、職種変更の有無。回答者名と回答日時は Forms が記録する |
| 必須と任意 | 共通・業務別の選択項目を基本とする。自由記述は短文とし、回答しにくい内容は省略できる |
| 利用目的 | ワークショップの改善と成果報告。人事評価には使わない運用を提案する |
| 共有範囲 | 個別回答は運営が確認し、部長向けには集計を示す。事例の引用は本人に確認する |

回答者名が記録されるため、完全匿名とは案内しない。15名程度では職種や記述から本人が推測される可能性もあるため、少人数の職種別内訳を必要以上に公開しない。

## 全員が回答する共通項目

設問の文言と尺度は、事前と終了時で固定する。現在の状態を回答してもらい、終了時に事前の回答を上書きしない。

| ID | 設問 | 回答形式 |
|---|---|---|
| F1 | 過去4週間に、実務でAIを使った日は何日ありましたか。研修の演習だけに使った日は含めません。 | 0日／1〜3日／4〜7日／8〜15日／16日以上／実務の機会なし |
| C1 | AIを使えそうな仕事を思いつけますか。 | 能力尺度C |
| C2 | 仕事で困っている理由を整理できますか。 | 能力尺度C |
| C3 | AIに、してほしいことを伝えられますか。 | 能力尺度C |
| C4 | AIに、いくつかの作業をまとめて頼めますか。 | 能力尺度C |
| C5 | 作ったものの使い方を、他の人にも分かるように説明できますか。 | 能力尺度C |
| C6 | AIの答えが間違っていないか確認できますか。 | 能力尺度C |
| C7 | 他の人からの感想をもとに、作ったものを直せますか。 | 能力尺度C |

F1には任意の補足欄を付ける。休暇、業務変更、利用制限など、活用機会が変わった事情を記録できるようにする。

### 能力尺度C

| 値 | 参加者に表示する選択肢 |
|---|---|
| 0 | まだやり方が分からない |
| 1 | やり方は分かるが、まだできない |
| 2 | 手助けがあればできる |
| 3 | 一人でできる |
| 4 | 状況に合わせてやり方を変えられる |
| 対象外 | 試す機会がない |

対象外は0点に変換しない。本人の感覚による回答なので、客観的な習熟度として断定しない。終了時の自由記述で、できると判断した根拠を一つ挙げてもらう。

## 個人とチームの変化

事前と終了時に同じ文面で聞き、同じ人の回答を比べる。期待する効果（個人：毎回ねらいどおりの結果が返る、チーム：品質がそろい、新しく入った人もすぐ使える）を、回数や状態で答えられる形にした。評価の言葉で聞くと、答える人によって読み方が変わるためである。

| ID | 設問 | 選択肢 |
|---|---|---|
| T1 | この1か月、AIに仕事を頼んだとき、手直しせずに使える結果は、どのくらい返ってきましたか。 | ほとんど無い／3回に1回／半分／たいてい／ほぼ毎回 |
| T2 | あなたのチームでは、AIに頼むときの書き方（指示の型やSkillなど）を、チームで共有していますか。 | 共有していない／一部の人だけが持っている／共有しているが使われていない／共有していて使われている |
| T3 | チームに新しく入った人や、案件に入って間もない人が、AIの仕組みを使って仕事を始められるまで、どのくらいかかりますか。 | 数日以内／1〜2週間／1か月くらい／1か月より長い／該当する人がいない |

T1は個人コースの人、T2・T3はチームコースの人（参加申込のJ2）の中で比べる。T1とT2は、事前より上の選択肢へ移った人の割合を取る。T3は、期間が短くなった人の割合を取る。「該当する人がいない」は比較から除く。本人の回答であるため、報告では成果物と振り返りの記録を添える。

## 業務別の項目

担当する業務について、AIをどの程度使っているかを回答してもらう。対象は特定の業務に限らない。PM・PLと開発の業務は項目を固定し、それ以外の業務は、業務名と作業を本人が書く。PMとPLの担当範囲は組織によって異なるため、職位だけで全項目の経験を前提にしない。兼務者は両方の表から実際に担当する項目を選ぶ。

### 業務活用尺度B

質問は「過去4週間に、次の業務でAIをどの程度使いましたか。」で固定する。業務別の項目は同じ回答形式にし、能力の自己評価Cとは分ける。

| 値 | 選択肢 |
|---|---|
| 0 | 使っていない |
| 1 | 試したが、実務には使っていない |
| 2 | 実務で1回使った |
| 3 | 実務で複数回使った |
| 担当外 | この業務を担当していない |
| 機会なし | 担当しているが、この4週間は実施機会がなかった |

実務で使った場合はAIの結果を人が確認して利用した経験を回答する。未利用と、実施機会がなかった場合を区別する。付録では0 未利用／1 試用のみ／2 実務で1回／3 実務で複数回と短縮表示する。

### PM・PLの業務

提供された管理・リーダー業務の例（[IMG_0588.jpeg](../src/IMG_0588.jpeg)）に対応する。顧客提案だけを制作課題として指定する意味ではない。

| ID | 業務 |
|---|---|
| P1 | 複数資料から情報を集めて集計する |
| P2 | 週次・月次報告や予実を可視化する |
| P3 | 会議・チャットから課題・担当・期限を整理する |
| P4 | 品質・障害・リスクの傾向を分析する |
| P5 | 改善案・効果の見込み・提案資料を作る |
| P6 | 過去の会議・成果物・トラブル事例を探して再利用する |

### 開発の業務

| ID | 業務 |
|---|---|
| D1 | 要求を整理して仕様をまとめる |
| D2 | 設計案を作り、選択肢を比較する |
| D3 | コードを作成・修正する |
| D4 | コードや設計をレビューする |
| D5 | テスト項目・テストコードを作り、結果を確認する |
| D6 | ログや不具合を調べ、運用・保守に役立てる |

兼務者は両方に回答する。

### その他の業務

PM・PL・開発以外の業務を担当する人が回答する。

| ID | 設問 |
|---|---|
| O1 | 担当している業務の名前 |
| O2 | その業務で、AIを使った作業、または使ってみたい作業 |
| O3 | 過去4週間に、その業務でAIをどの程度使ったか（業務活用尺度B） |

業務ごとの集計に使い、業務間の総合点・順位は作らない。工程内で利用内容に差がある場合は具体例欄へ記入する。

## 困りごとと学びたいこと

| ID | 設問 | 回答形式 |
|---|---|---|
| N1 | 今、AI活用で特に困っていることを選んでください。 | 下の選択肢から最大3つ。困りごとなし・その他も用意 |
| N2 | 今後、AIを使ってできるようになりたい業務を選んでください。 | 自分が回答したP／D項目、またはO1の業務から最大2つ。その他・まだ思いつかないも用意 |
| N3 | その業務の、どんな場面で困っていますか。 | 一つの場面を短文で記入。具体的な案件名は不要 |
| N4 | どの支援があると、次に進めそうですか。 | 考え方を学ぶ動画／操作の説明／使い方のヒント／ブログ／Teams投稿での相談／会話での相談／使うツールの準備／学習時間／その他。最大2つ |

N1の選択肢は、使いどころ／依頼方法／結果の確認／共有／環境／時間／なし／その他。「なし」は他の選択肢と同時選択しない。具体的な困りごとはN3へ記入する。N4は付録で概念動画／操作説明／事例／ブログ／Teams相談／会話／環境／時間／その他と短縮表示する。

## 時点別の短い自由記述

| 時点 | 設問 |
|---|---|
| 事前・参加申込 | 実現したい目的（G1〜G4）。まだ決まっていない場合も、今考えていることを書く |
| 終了時 | 新しくできるようになったこと、または試したがうまくいかなかったことを一つ挙げてください。入力した情報・出力・確認や修正の方法を教えてください。 |
| 終了時 | その変化に影響したものは何ですか。教材、相談、実務経験、他の研修、ツールの更新などから教えてください。 |
| 終了時 | 今後も実務で使いたいものと、まだ支援が必要なことを教えてください。 |

変化なし・未実施・悪化もそのまま回答できるようにする。改善した話だけを選ばせない。

## 個人目標と成果物の記録

目指すのは、実現したい目的を言語化し、AIで仕組みを作り、その目的を達成することである。目的は本人のものに限らず、チームの目的でもよい。自分の知識・手順・判断の目安を仕組みに組み込み、他の人も使えればなおよい。説明や初回の支援があることは不合格条件にしない。

| ID | 事前（10月）と参加申込（1月）に同じ文面で聞くこと |
|---|---|
| G1 | 何を実現したいですか（目的）。実現したいことと、誰のためかを記入する |
| G2 | どんな仕組みをAIで作りますか。作るものと使う知識・手順を記入する |
| G3 | 誰に使ってもらいますか。利用者と試す場面を記入する |
| G4 | 何が変われば達成ですか。結果・確認方法・期限を記入する |
| J1 | ワークショップに参加しますか（参加申込のみ）：参加する／今回は見送る。目的を書けた人を先着15名で受け付ける |
| J2 | 個人コースとチームコースのどちらを選びますか（参加申込のみ）：個人コース／チームコース。個人でまだ目的を達成できていない人は個人、既にできている人はチームを選ぶ |

途中で変更してよいが、終了時に当初の目標・変更理由を残す。終了時に都合のよい達成条件へ置き換えない。

| ID | 終了時に聞くこと |
|---|---|
| R1 | 参加申込で書いた目的を、AIで達成できたか：達成／一部達成／未達／未実施 |
| R2 | 何を作ったか。名称と、組み込んだ知識・手順（最大3件） |
| R3 | 2月に、チームで振り返りの場を何回開いたか：0回／1回／2回以上。話し合った問題と、直したことを記入する |
| R4 | 3月のあとも、その話し合いの場を続けるか：日程が決まっている／続けるつもりだが日程は未定／続けない |
| R5 | うまくいかなかった点（複数選択）：導入／入力準備／業務との不一致／確認の手間／なし |
| R6 | 未解決の点、続けたいこと、必要な支援 |
| R7 | ポータルで、探していた仕組みやノウハウにたどり着けたか：すぐたどり着けた／時間がかかったがたどり着けた／たどり着けなかった／探していない |
| R8 | たどり着けなかったとき、何を探していたか |

**使ってもらった相手には、アンケートを配らない。** 成果物を使うのは参加者に限らず、社内の同僚やチームである。その人たちへ回答を依頼する筋も義務も無いため、回答は集まらない。チームで使った結果と振り返りは、参加者本人がR3とR5に書く。

参加者以外（ポータルの希望者）からは、アンケートではなくポータルの画面と記録で取る。仕組みのページの「試した」、探し終えたときの1問（R7と同じ4択）、希望者が載せたノウハウや使い方の記録である。

本人の報告であることは明示する。運営は、最終共有会のデモと成果物で内容を確認し、確認できた範囲を報告へ添える。時間短縮を示す場合は、比較条件と確認・修正の手間も記入してもらう。

## 最終成果物発表・交流会と人気投票

コミュニケーション施策として、参加者がざっくばらんに交流できる場にする。人気投票は以下の提案であり未確定。後日の試用期間は置かない。他の人に使ってもらうのは、2月に自分のチームで行う。会場・軽食費・日程は別途調整する。

| 段階 | 運営案 |
|---|---|
| 発表 | 軽食を囲むオフライン交流会で、短いデモと会話を通じて成果物を紹介する |
| 投票 | 共有会で紹介されたデモのうち「自分の仕事でも使いたい」ものへ1人1票を投じ、理由を添える。自作品への投票は行わない |
| 選べない場合 | 該当なしを選べる。無理に1票を求めない |
| 表彰 | 得票数が最多の作品を人気作品として表彰する。同数なら同時受賞とする |
| 結果表示 | 得票数を並べる。人気投票であることを明示する |

デモの紹介だけにもとづく投票なので、票数を品質や汎用性の客観順位として扱わない。表彰されなかった成果物も、チームで使った結果と改善内容をポータルに保存する。

## 推奨KPI案

### ワークショップ

| 指標 | 定義 |
|---|---|
| 主KPI：目的の明確化率 | G1とG4の記述で、書けた観点（何を実現するか・誰のためか・何が変われば達成か）が1月に増えた人数／事前と参加申込の両方に回答した人数。観点の数え方は、事前と参加申込で同じ基準を用いる。判定基準を文書にし、AIが全件を同じ基準で判定し、運営が抜き取りで確認する |
| 主KPI：目的達成率 | 参加申込で書いた目的を、AIで達成できたと回答した（R1で「達成」）参加者数／ワークショップに参加した人数（先着15名、開始時点で固定）。一部達成・未達・未実施・未回答は内訳として示す |
| 補助：実務でAIを使う人の増加 | 個人コースの人（J2）のうち、P・D・Oの各業務で、前後とも担当・実施機会がある同じ人の、段階2・3の人数変化 |
| 補助：振り返りの実施 | チームコースの人（J2）のうち、チームで使う期間に振り返りの場を1回以上開いた人数（R3）／チームコースの人数 |
| 補助：個人の変化 | 個人コースの人（J2）のうち、T1で事前より上の選択肢へ移った人数／個人コースの人のうち、事前と終了時の両方に回答した人数 |
| 補助：チームの変化 | チームコースの人（J2）のうち、T2で上の選択肢へ移った人数と、T3で期間が短くなった人数。分母は、チームコースの人のうち、それぞれ比較できた人数 |

### AI活用を促進する基盤づくり

| 指標 | 定義 |
|---|---|
| チームでの改善の継続 | 3月のあとも振り返りの場を続け、日程が決まっている参加者数（R4）／開始時の参加者数 |
| 参加者以外での再利用 | ポータルの希望者のうち、見つけた仕組みを自分の業務で試した人数（「試した」の記録）／希望者数 |
| 必要なナレッジの見つけやすさ | 探していたものにたどり着けた人数／探した人数。参加者はR7、希望者はポータルの画面の1問から取る。たどり着けなかった用途（R8）は一覧にする |
| ナレッジを出す人の広がり | ポータルに、自分のノウハウや使い方を1件以上載せた希望者数／希望者数 |

主KPIと補助の割合は、一人が複数作っても一人として数え、未回答は分母から外さず内訳を併記する。うまくいかなかった点（R5）も件数で報告する。うまくいかなかった記録を残さないと、次の期に同じ原因を繰り返す。共同制作では本人が具体化した知識・手順や担当を確認する。業務活用の分母は同じ業務で比較できた人数とし、除外人数も示す。主KPIの分母とは異なる。

AI活用を促進する基盤づくりの指標は、次の期にポータルを部内へ広げるか、何を作るか、カテゴリとタグをどう直すかの判断に使う。ポータルの掲載数や閲覧数は、成果として数えない。

目標値は事前調査と運営条件を踏まえ、開催前に設定する。現時点では割合の目標を決定していない。交流会の参加人数と「今後相談したい相手ができたか」は運営改善用の参考情報として扱い、制作のKPIと混ぜない。

## 部長向け報告の構成

| 報告すること | 集計・提示の方法 |
|---|---|
| 回答状況 | 各時点の回答者数／対象者数と、比較できた人数を示す |
| 実務での利用 | F1の各段階の人数分布と、同じ人の事前→終了時の移動を示す |
| 自力でできる範囲 | C項目ごとに向上・同段階・低下の人数を示す。必要に応じて中央値も添える |
| 業務別の活用 | P／D項目ごとに段階2・3の人数／当該業務の有効回答者数を示す。O3は業務名ごとに件数を示す。業務の間で点数を混在させない |
| 実際にできたこと | 本人の説明に、出力や実行の記録を添える。未確認の説明は自己申告と表示する |
| 目的の達成 | 達成・一部達成・未達・未実施・未確認の人数と、達成条件と結果の照合の実例を示す |
| 振り返り | 1回以上開いた人数と、持ち寄った問題・直したことの実例を示す |
| 個人とチームの変化 | T1〜T3ごとに、上がった（短くなった）・同じ・下がった人数を示す |
| 成果物 | 提出数、チームで使われた数、対象業務と限界を示す |
| AI活用を促進する基盤づくり | チームでの改善の継続、参加者以外での再利用、必要なナレッジの見つけやすさ、ナレッジを出す人の広がりと、たどり着けなかった用途の一覧を示す |
| 表彰 | 投票結果と利用者の感想を示す |
| 今後の支援 | N項目の変化と、未解決の困りごとから教材・相談の改善を決める |

比較には、同じ回答者名で事前と終了時の両方に回答した人を用いる。比較対象人数を明示する。未回答・対象外は補完せず、対応する分母から除く。職種が変わった人の職種別項目は同じ業務か確認し、比較できないものを分ける。

C（0〜4）とB（0〜3）とF1は意味の異なる段階なので合算しない。0〜4を等間隔とみなした「能力が何％伸びた」という表現もしない。少人数のため、割合だけでなく人数を必ず示す。

この設計で示すのは、期間中の変化と実例である。業務経験やツール更新の影響もあり、変化のすべてを研修だけの効果とは断定しない。学習が進んで自己評価が厳しくなる場合もあるため、点数が下がった項目は自由記述と実例を併せて読む。

## Microsoft Formsでの実装

回答はMicrosoft Formsで集める。フォームは3本で、事前は準備期間の希望者が、参加申込と終了時は参加者が回答する。

| フォーム | 時期 | 内容 |
|---|---|---|
| 事前 | 10月（教材の前） | 利用頻度・能力・業務別の活用・個人とチームの状態（T1〜T3）・目的と達成条件（G1〜G4）・困りごと |
| 参加申込 | 1月（教材の後） | 目的・作る仕組み・利用者・達成条件（G1〜G4、事前と同じ文面）・参加の希望（J1）・コース（J2：個人／チーム） |
| 終了時 | 3月 | 同じ設問と、目的の結果・作ったもの・振り返り・ポータル（R1〜R8） |

`One response per person` が制限するのは、1つのフォームにつき1回の回答である。事前と終了時を1本のフォームで実施すると、2回目以降の回答を受け付けない。時点ごとに分ける理由はここにある。ワークショップを3か月にしたため、中間の測定は置かない。

| 設問 | 質問の種類 |
|---|---|
| F1・N1・N2・N4・O3・T1〜T3・R1・R3・R4・R5・R7 | `Choice` |
| C1〜C7 | `Likert`。行に7問、列に0〜4と「機会なし」 |
| P1〜P6・D1〜D6 | `Likert`。行に6業務、列に0〜3と「担当外」「機会なし」 |
| N3・O1・O2・G1〜G4・R2・R6・R8 | `Text`。R3の補足（話し合った問題と直したこと）も `Text` |

業務別の設問は `Section` で分け、担当業務を尋ねる設問から `Add branching` で分岐させる。分岐は後ろの設問へしか飛べないため、業務のセクションは担当業務の設問より後ろに置く。兼務者は両方のセクションを通過させる。

配布時は `Only people in my organization can respond` と `Record name` を選び、`One response per person` を上表のとおり設定する。回答期間は `Start date` と `End date` で指定する。集計は `Open results in Excel` から `Download a copy` を取得し、氏名の列で時点間を突き合わせる。

Microsoft Formsの[質問の種類](https://support.microsoft.com/en-us/office/create-a-form-with-microsoft-forms-4ffb64cc-7d5d-402f-b82e-b1d49418fd9d)・[設定](https://support.microsoft.com/en-us/forms/adjust-your-form-or-quiz-settings-in-microsoft-forms)・[分岐](https://support.microsoft.com/en-us/forms/use-branching-logic-in-microsoft-forms)・[集計](https://support.microsoft.com/en-us/office/check-your-form-results-02859424-341d-406f-b32a-9a0fbaf357af)を2026-09-20に確認した。上記の設定名と質問の種類は、原文の表記をそのまま用いている。フォームを3本に分ける構成と、兼務者をセクションへ通す順序は、今回の設計判断である。
