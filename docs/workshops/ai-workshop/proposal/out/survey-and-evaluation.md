# AI活用ワークショップのアンケート・効果測定案

主KPIは、目的の明確化率（AIで実現したい目的と、その達成に必要なことを、教材の視聴前より明確に説明できるようになったか）と、目的達成率の2つである。補助の指標は、参加申込で選んだコース（個人／チーム）ごとに2つずつ測る。AI活用を促進する基盤づくりは先行トライアルとして、参加者と、参加しなかった希望者の終了時アンケートと、ポータルの掲載記録から検証する。人気投票は共有会の表彰として扱う。

設問は、指標から逆算して置く。どの指標にも使わない設問は、結果を読む軸と、教材と支援の調整に使うものに限る。本書は運営がMicrosoft Formsへ転記するための設問案である。設問の文面は `src/survey.json` と一致させ、スライドの回答フォームはそのデータから組む。フォームの作成・配信はまだ行っていない。この設問と尺度は今回の企画に合わせて作ったもので、妥当性を検証済みの標準尺度ではない。開始前に、参加者に近い人に回答してもらい、答えにくい設問を直す。

## 実施時点と回答の扱い

| 項目 | 設計案 |
|---|---|
| 事前アンケート | 10月2週目、準備期間の希望者が、教材を視聴する前に回答する |
| 参加申込 | 1月、教材をすべて視聴したあとに回答する。事前と同じ設問で目的を書き、取り組む目的・参加・コースを選ぶ。人は具体を知って初めて目的を思い描けるため、目的は教材のあとに改めて書く |
| 参加者の終了時アンケート | 3月の最終共有会のあとに、参加者が回答する |
| 参加しなかった希望者の終了時アンケート | 3月に、事前アンケートに回答しワークショップに参加しなかった人が回答する |
| 回答者の同定 | Microsoft Forms の Record name で回答者名を記録し、4本のフォームを氏名で突き合わせる。手入力のIDは設けない |
| 並び | 事前と参加申込は、1ページ目に目的の設問だけを置く。目的を書く前に他の設問を見せないためである |
| 利用目的 | ワークショップの改善と成果報告。人事評価には使わない運用を提案する |
| 共有範囲 | 個別回答は運営が確認し、部長向けには集計を示す。事例の引用は本人に確認する |

回答者名が記録されるため、完全匿名とは案内しない。15名程度では業務や記述から本人が推測される可能性もあるため、少人数の業務別内訳を必要以上に公開しない。

**使ってもらった相手には、アンケートを配らない。** 成果物を使うのは参加者に限らず、社内の同僚やチームである。その人たちへ回答を依頼する筋も義務も無いため、回答は集まらない。チームで使った結果と振り返りは、参加者本人が終了時に書く。

## 目的の記述の判定

目的の明確化率は、目的と、その達成に必要なことの記述を、4つの観点で判定する。

| 観点 | 書けたとみなす記述の例 |
|---|---|
| 何を実現するか | 議事録を、会議の翌朝までに全員へ共有する |
| 誰のためか | チームのメンバーのため |
| 何が変われば達成か | 担当と期限が漏れずに共有され、確認の手間が減る |
| 達成に何が必要か | 会議の録音の文字起こしと、担当と期限の書き方の決まりをAIに渡し、抜き出した結果を書記が確認する手順 |

観点ごとに書けたとみなす条件と実例を判定基準の文書にし、AIが全件を同じ基準で判定し、運営が抜き取りで確認する。1人が書いた目的（最大3つ）のうち、最も多くの観点を書けたもので、その人の事前と参加申込を比べる。事前と参加申込で1つ目に書く目的が入れ替わっても、同じ人の変化として比べるためである。観点を設問文に出さないのは、設問そのものが観点を教え、事前の時点で書けてしまうのを避けるためである。

## 推奨KPI案

### ワークショップ

| 指標 | 定義 |
|---|---|
| 主KPI：目的の明確化率 | 最も明確に書けた目的の観点の数が、事前より参加申込で増えた人数／事前と参加申込の両方に回答した人数。事前で4観点を書けていた人は、内訳として示す |
| 主KPI：目的達成率 | 参加申込で選んだ目的を、終了時にAIで「達成」と答えた参加者数／ワークショップに参加した人数（先着15名、開始時点で固定）。一部達成・未達・未実施・未回答と、取り組まなかった目的の結果は内訳として示す |
| 補助：実務でAIを使う人の増加 | 個人コースの人のうち、過去4週間の実務での利用が「月に1〜3回」以上の人数を、事前と終了時で比べる。両方に回答した人数を示す |
| 補助：手戻りの減少 | 個人コースの人のうち、手直しせずに使える結果の頻度が事前より上の選択肢へ移った人数／事前と終了時の両方に回答した人数。「AIに仕事を頼んでいない」は比較から除く |
| 補助：チームでの改善の実施 | チームコースの人のうち、チームで使う期間に振り返りの場を1回以上開いた人数／チームコースの人数 |
| 補助：やり方のチームへの定着 | チームコースの人のうち、書き方の共有が上の選択肢へ移った人数と、立ち上げ期間が短くなった人数。分母は、それぞれ比較できた人数。「該当する人がいない」は比較から除く |

### AI活用を促進する基盤づくり

| 指標 | 定義 |
|---|---|
| チームでの改善の継続 | ワークショップの終了後も振り返りの場を続け、日程が決まっている参加者数／開始時の参加者数 |
| 参加者以外での再利用 | 参加しなかった希望者のうち、ポータルで見つけた仕組みやノウハウを自分の業務で試した人数／参加しなかった希望者数。未回答は内訳として示す |
| 必要なナレッジの見つけやすさ | 探していたものにたどり着けた人数／探した人数（「探していない」を除く）。参加者と、参加しなかった希望者の両方から取る。たどり着けなかったときに探していたものは一覧にする |
| ナレッジを出す人の広がり | ポータルに、自分のノウハウや使い方を1件以上載せた、参加しなかった希望者の数／参加しなかった希望者数。ポータルの掲載記録から数える |

主KPIと補助の割合は、未回答を分母から外さず内訳を併記する。本人の回答である指標は、報告で成果物と振り返りの記録を添える。

AI活用を促進する基盤づくりの指標は、次の期にポータルを部内へ広げるか、何を作るか、カテゴリとタグをどう直すかの判断に使う。ポータルの掲載数や閲覧数は、成果として数えない。

目標値は事前アンケートと運営条件を踏まえ、開催前に設定する。現時点では割合の目標を決定していない。交流会の参加人数は運営改善用の参考情報として扱い、KPIと混ぜない。

| 表彰 | 投票結果と利用者の感想を示す |
| 今後の支援 | 困りごと・欲しい支援・未解決の点から、教材と相談の改善を決める |

比較には、同じ回答者名で両方の時点に回答した人を用いる。比較対象人数を明示する。未回答・対象外は補完せず、対応する分母から除く。業務やツールの違いで結果を読むときは、事前アンケートの担当業務と使えるAIツールで分ける。

意味の異なる段階の選択肢は合算しない。選択肢を等間隔とみなした「何％伸びた」という表現もしない。少人数のため、割合だけでなく人数を必ず示す。

この設計で示すのは、期間中の変化と実例である。業務経験やツール更新の影響もあり、変化のすべてを研修だけの効果とは断定しない。学習が進んで自己評価が厳しくなる場合もあるため、下がった回答は記述と実例を併せて読む。

## 最終成果物発表・交流会と人気投票

コミュニケーション施策として、参加者がざっくばらんに交流できる場にする。人気投票は以下の提案であり未確定。後日の試用期間は置かない。他の人に使ってもらうのは、2月に自分のチームで行う。会場・軽食費・日程は別途調整する。

| 段階 | 運営案 |
|---|---|
| 発表 | 軽食を囲むオフライン交流会で、短いデモと会話を通じて成果物を紹介する |
| 投票 | 共有会で紹介されたデモのうち「自分の仕事でも使いたい」ものへ1人1票を投じ、理由を添える。自作品への投票は行わない |
| 選べない場合 | 該当なしを選べる。無理に1票を求めない |
| 表彰 | 得票数が最多の作品を人気作品として表彰する。同数なら同時受賞とする |
| 結果表示 | 得票数を並べる。人気投票であることを明示する |

デモの紹介だけにもとづく投票なので、票数を品質や汎用性の客観順位として扱わない。表彰されなかった成果物も、チームで使った結果と改善内容をポータルに保存する。

## Microsoft Formsでの実装

回答はMicrosoft Formsで集める。フォームは4本である。

| フォーム | 時期 | 回答する人 |
|---|---|---|
| 事前アンケート | 10月2週目（教材の前） | 準備期間の希望者 |
| 参加申込 | 1月（教材の後） | 準備期間の希望者 |
| 参加者の終了時アンケート | 3月 | 参加者 |
| 参加しなかった希望者の終了時アンケート | 3月 | 事前に回答し、参加しなかった希望者 |

`One response per person` が制限するのは、1つのフォームにつき1回の回答である。時点ごとにフォームを分ける理由はここにある。ワークショップを3か月にしたため、中間の測定は置かない。

| 設問 | 質問の種類 |
|---|---|
| 選択肢で答える設問（利用頻度、手戻り、共有、立ち上げ期間、振り返りの回数と継続、たどり着けたか、試したか、取り組む目的、参加、コース、担当業務、ツール、作業、困りごと、欲しい支援） | `Choice`。複数選択の設問は、複数の回答を許す |
| 目的ごとの結果 | `Likert`。行に1つ目〜3つ目、列に達成・一部達成・未達・未実施・書いていない |
| 記述で答える設問（目的、必要なこと、根拠、目的の変更、振り返りの内容、探していたもの、教材で知りたいこと、未解決の点） | `Text`。長い回答を許す |

ページは `Section` で分ける。事前アンケートの「AIを使っている作業」は、利用頻度の設問から `Add branching` で分岐させ、「使っていない」を選んだ人は次のページへ進める。

配布時は `Only people in my organization can respond` と `Record name` を選び、`One response per person` を設定する。回答期間は `Start date` と `End date` で指定する。集計は `Open results in Excel` から `Download a copy` を取得し、氏名の列で時点間を突き合わせる。参加申込の回答内容は、開始時に本人へ送り、終了時に手元で照合できるようにする。送り方（受信確認の機能か、運営からの送付）は配布前に決める。

Microsoft Formsの[質問の種類](https://support.microsoft.com/en-us/office/create-a-form-with-microsoft-forms-4ffb64cc-7d5d-402f-b82e-b1d49418fd9d)・[設定](https://support.microsoft.com/en-us/forms/adjust-your-form-or-quiz-settings-in-microsoft-forms)・[分岐](https://support.microsoft.com/en-us/forms/use-branching-logic-in-microsoft-forms)・[集計](https://support.microsoft.com/en-us/office/check-your-form-results-02859424-341d-406f-b32a-9a0fbaf357af)を2026-09-20に確認した。上記の設定名と質問の種類は、原文の表記をそのまま用いている。フォームを4本に分ける構成と、目的の設問を1ページ目に置く並びは、今回の設計判断である。
