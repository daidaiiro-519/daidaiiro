# 企画書の見直しの開始と構成案

利用者から、オリエンテーションと同じ進め方で企画書を修正するよう指示を受けた。作業コピーと比較ページを用意し、構成見直し案を作成した。構成案は利用者確認待ちで、スライドと原稿は未修正である。

## 用意したもの

| 対象 | 置き場所 |
|---|---|
| 変更前 | proposal-20261026/before/proposal/src（2026-10-26 の正本 proposal/src の複製） |
| 変更後の編集元 | proposal-20261026/after/proposal/src の build_deck.py、visuals.py、survey.json |
| 生成 | proposal-20261026/build_proposal_review.py の後、common-intro-20261019/workspace/build_review.py --publish |
| 構成案 | proposal-20261026/story-plan.md |
| 変更理由 | proposal-20261026/revisions.json。枚のラベルで記録し、詳細版と要点版の枚番号へ割り当てる |

置き場所は review/proposal-orientation-20261024/ からの相対パス。生成スクリプトは正本の out/ へ書かない。変更前の生成元から生成した結果は、正本の director-deck.html と書籍の表紙の参照を除いて一致し、要点版の原稿は完全に一致した。

共通の生成元 build_review.py に、担当情報の proposal_review_input を読み、比較ページの「企画書 · 詳細版」「企画書 · 要点版」を差し替える処理を加えた。生成後のHTMLは直接編集していない。

## 構成案の要点

二施策の構成と、背景から依頼事項までの順序は残す。旧い到達像（目的を言葉にしてAIに伝える、言葉の定義、AIに1回で依頼できる大きさ）を、共通方針と、正式版にしたオリエンテーションの到達像へ合わせる。利用者に確認したい点は3つある。5枚目の例を共通の「はじめに」の事例にするか、効果測定の指標の中身をどう変えるか、協力者の時間の依頼をどう言い換えるかである。

## 文章の10判定

1. 読み手：他担当が、企画書の作業の置き場所と状態を読み取れる。
2. 主張：企画書の見直しを始め、構成案が確認待ちである。
3. 論：用意したもの、構成案、公開先、確認の順にした。
4. 構造：置き場所は表、公開先は列挙で示した。
5. 文：何をどこへ置いたかを書いた。
6. 文体：常体で統一した。
7. 語彙：教材の紹介名と到達像は共通方針の語で書いた。
8. 重複：構成案の各枚の内容は story-plan.md に任せた。
9. 表記：パスの基準を明記した。
10. 根拠：一致の確認の範囲（書籍の表紙の参照を除く）を書いた。
