# 2026年10月25日：上段のAgentが各工程でSkillsを使用する図へ変更

利用者が、変更前の上下レイアウトを使い、上段のSkillsをAgentsへ変更して、その下に各工程で使用するSkillsを置く構図を希望した。工程ごとに別のエージェントを呼ぶ構成は勧めたくない、という方針も明示した。

共通方針revisionを2026-10-25-10へ更新した。この教材の基本例は、作業を進めるAgentが工程に応じてSkillsを使用する形とし、工程ごとに別Agentを配置するマルチエージェント構成を勧めない。あらゆるマルチエージェント構成が不適切とする一般論には広げない。別担当の進捗や確認状態は変更していない。

## 図と原稿の変更

表示8枚目の図を、上段に一つのAgent、下段に要件定義・設計・実装・テストの四つの工程を配置する上下レイアウトへ変更した。Agentから各工程へ線をつなぎ、工程内には使用するSkillsの書類だけを置いた。複数のAgentが工程を分担する表現は削除した。

Skillsの具体例は、目的・範囲の確認、既存仕様との照合、業務モデルの反映、変更の影響の検討、設計に沿った実装、要件に沿ったテストとした。最下段には各工程でのレビューと、人の根拠確認・改善を残した。warm-paperの配色を維持し、上段の枠のみ強調した。

原稿は、工程に応じて必要なSkillsを使用する主体がAgentであることを明記し、工程ごとのAgent分担を勧める説明ではないことも補足した。前回までの、不具合や設計複雑化の可能性を下げる目的と、品質を保証するものではないという説明は維持している。

## 文書の10判定

1. 指し先：作業主体のAgent、各工程、使用するSkillsを明示。
2. 型：使用関係を上下の配置と線で示す。
3. 数：四工程を同じ形で列挙。
4. 見出し：上段のAgentと各工程でのSkills使用を明示。
5. 結論：利用者の指定と変更方針を先に記載。
6. 形：工程とSkillsはそれぞれ同じ形、Agentは一つだけ表示。
7. 用語：工程と使用する手順を混同しない。
8. 読み手：用途を短いラベルで示し、細部は原稿で説明。
9. 量：各工程のSkillsは二つの観点に絞った。
10. 比喩：実際の工程と確認する対象で記述。
