# 5枚目　受講者（Haiku 5.5）レビュー

## 読み取れたこと
- AIが作った成果物も、人が元の情報や要件と照合してから仕事で使う、という一点が言いたいことだと読めた。
- 成果物が増えると照合する対象も増え、作成時間が減っても確認時間は同じように減るとは限らない、と受け取った。

## 図で分かりにくかったところ
- 左の「AIで作った成果物」の枠は、資料とコードの束とロボットだけで、右の照合の図とどう対応するかが読み取れない。左から右への矢印は、何が右へ渡るのかを示していない。
- 右の図は上段（元の情報 と 計画書・説明資料・報告書）と下段（要件・仕様 と 設計書・コード・テスト）に分かれるが、段の意味（資料向けと開発向けの区別）が枠線だけでは伝わらない。
- 虫眼鏡と「－」の記号が何を表すのか（照合なのか、検索や比較なのか）が分からない。
- 「必要な情報があり、事実と合うか」の文が、上段のどの照合を指すのか曖昧。下段の問いとの区切りも弱い。
- 下部の赤い結論文が、図の説明より強く目に入り、読み手には図の主張より結論が先に届く。

## 図と原稿が合っていないところ
- 原稿の「成果物どうしで内容が食い違っていないか」は図に描かれていない。図の照合は元の情報・要件との対だけに見える。
- 原稿の「必要なレビューやテストは、これからも欠かせません」「示し方にも目を向ける」は図に無い。
- 原稿の「テスト」は、図では成果物の1つとして並んでおり、照合の相手として扱われない（原稿の「テストが要件や仕様を満たしているか」とは読み方が合わない）。

## 日本語として不自然・読みにくい表現
- 「必要な情報があり、事実と合うか」：主語が無く、何が必要なのか、何と何が合うのかが取れない。
- 「作成の時間が短くなっても、確認と修正の時間が、同じように減るとは限らない」：「同じように減る」が、作成時間と同じ割合で減るという意味か、単に減るという意味か読み取れない。
- 「作れる成果物が増えたとき、」（見出し）：「作成できる」の方が自然に感じた。
- 原稿が「です・ます」で統一されているのに、図の中は「照合するか」「問題はないか」と疑問形で、文体が図と原稿で揃っていない（補足として記録）。

## 意味が分からない語・初めて見る語
- 「成果物」：資料やコードを指すと分かるが、何を含むのか（テストや設計書も入るのか）が初見では定まらない。
- 「照合」：「確かめる」と何が違うのか、読み比べのことか、データの突き合わせのことか、図だけでは分からない。
- 「要件・仕様」：PMには馴染みがあるが、両者の違いが示されていない。
- 「示し方」（原稿末尾）：この枚で初めて出てきて説明がなく、次の枚へ渡される語として唐突に見えた。

## 前後の枚とのつながりで引っかかったこと
- 前の枚の結び「それを確認する作業はどうなるでしょうか」は、この枚の見出しと問いが重なり、同じ問いを2度聞かされる感覚になった。
- 次の枚の見出し「確認・判断ができる形になっていますか？」へは、原稿末尾の「示し方」で自然に渡されている。ただし「示し方」が本枚で説明されないまま次へ進むため、橋が1本しか無い。

## 自分で補った前提
- 照合は人が手で行う作業で、AIが自動で照合するわけではないと補った（原稿の「人が確かめる」から推測）。
- 資料は計画書や説明資料などの業務文書、開発は設計書・コード・テストを指すと補った（図の箱の名前から推測）。
- 成果物どうしの食い違いの確認は、元の情報との照合とは別の作業だと補った（原稿の文の並びから推測）。

## 受講者として知りたいと思ったこと
- 照合の手間を減らす方法は、この先の枚で扱われるのか（AIによる自動検証などが使えるのか）。
- 「示し方」とは具体的に何を指すのか（書き方の工夫か、資料の形式か）。
- テストもAIが作るなら、そのテストの正しさは誰がどう確かめるのか。
- 照合にどれくらい時間がかかるのか、作成時間との比較の数字はあるのか。
