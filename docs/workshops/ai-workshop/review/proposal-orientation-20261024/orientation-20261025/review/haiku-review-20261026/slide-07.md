# 7枚目　受講者（Haiku 5.5）レビュー

## 読み取れたこと
- AIのAgentが、作業の情報とSkillsを使って成果物を作り、人が根拠と結果を確認する流れ。確認の結果を受けてSkillsを改善し、次の同種の作業で使い回す。

## 図で分かりにくかったところ
- 「Skills」の箱に何が入るかが図の中で定義されていない。「参照する情報・判断の観点」と書かれても、受講者には中身が分からない。
- 成果物の6枚（計画書・説明資料・報告資料・設計書・コード・テスト）が、すべて作られるように見える。原稿の「図の成果物は例で」という断りが図には無い。
- 人が確認 → Skills の矢印は「Skillsの観点と手順を改善」という文字の箱を通るため、改善がSkillsだけに向かうのか、成果物にも向かうのかが読みにくい。
- 「照合」の矢印が図に無い。Agentの箱に「結果の照合も行う」とあるが、何と何を照合するのかが図に出ていない。

## 図と原稿が合っていないところ
- 原稿は「目的や要件に合わないところがあれば成果物を修正」と述べるが、図には成果物（または Agent）へ戻る矢印が無い。戻る先はSkillsだけである。
- 原稿は「成果物を、スキルの観点で元の情報や要件と照合する」と述べるが、図では成果物から元の情報へ向かう線が無い。
- 原稿は「スキル」「エージェント」と言うが、図は「Skills」「Agent」と書く。用語の対応が受講者に示されていない。

## 日本語として不自然・読みにくい表現
- 「図の成果物は例で、毎回すべてを作るのではなく」：「図」は音声では「ず」と聞こえ、図解の図か図面の図かが分からない。「この枚の成果物は例で」などにすると聞き取りやすい。
- 「何のために、何を作り、何を確かめるのか。これを、…まとめたものが、スキルです。」：「確かめる」「確認」「照合」「観点」が続けて出てきて、どの動作を指すかが曖昧。
- 「何を参照し、どう判断し、何を確かめるかという、判断の観点と手順を含めます」：入れ子が深く、耳で聞くと主語が追えない。
- 「根拠と結果を確認して使います」：「根拠」が何を指すのかが語られていない。

## 意味が分からない語・初めて見る語
- Skills（スキル）：この枚の中では定義されていない。前の枚で説明済みか、次の枚で説明されるのか、原稿からは判断できない。
- 観点（判断の観点）：「視点」「基準」と同じ意味で使われているか、受講者には確定できない。
- 照合：何と何を比べるのかが語られていない。
- 根拠：成果物の何を指すのかが語られていない。

## 前後の枚とのつながりで引っかかったこと
- 前の枚の結びは「何のために、何をどこまで作り、何を確かめればよいのか」と問いかけている。この枚はそれに答えるように、スキルの説明へ入るが、「確かめる」の内容を前の枚の問いとつなげる言葉が無い。
- 次の枚の見出し「目的と要件、業務の設計、AIでの実践」は、この枚の「三つの教材」と対応するが、この枚の原稿は三つの教材の内容を言わずに「三つの教材で順に学びます」と述べるだけ。

## 自分で補った前提
- 図の矢印の向きは画像から読み取った（人が確認 → 下の Skills へ、Skills → Agent へ）。音声だけで聞いた場合は、この矢印の向きは届かない前提で判断した。
- 「観点」は「判断の基準・着眼点」として読んだ。作り手の定義は資料に無い。
- 「図」は図解の図として読んだ。

## 受講者として知りたいと思ったこと
- Skillsは、ファイルなのか、手順書なのか、それとも仕組みなのか。どこに置くかも知りたい。
- 「照合」は具体的に何をするのか。元の情報と成果物を、AIが自動で比べるのか。
- 人が確認して修正を指示する経路はどうなっているのか。成果物の修正は、誰が、どの画面で行うのか。
- 6種類の成果物は、どれも同じ仕組みで作れるのか。コードとテストは、計画書と同じ手順なのか。
