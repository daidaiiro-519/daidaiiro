# AIワークショップ初級編 現行オリエンテーションの受講者レビュー

## 読み方

AIを仕事で使い始めたい初級者として、指定された画像を表紙1〜14の順に確認し、その後に各スライドの見出し・導入・原稿を読んだ。表紙1の専用原稿は記録されていないため、原稿の意図は推測していない。画像は本書に複製・埋め込みしていない。過去のレビューや改訂方針は参照していない。

「画像だけで分かること」は画面上の文字・図から読み取れる内容、「原稿で補えること」は読み上げ原稿で説明されている内容を指す。

## 受講者としての結論

仕事でAIを使って成果物を作れるようになった一方、確認・修正に時間がかかる人には、受講する理由が分かる。目的と条件を決め、AIに伝え、結果を確認し、繰り返す作業に使う手順を改善する、という到達点も伝わる。

ただし、AI初心者全般に向けた案内として読むと、困りごとが「成果物を作った後の確認負荷」に狭く見える。AIをまだ使っていない人や、使っているが目的設定・指示の仕方・結果の選び方に困っている人にも自分向けだと分かる説明は弱い。また、何ができれば受講後の成功なのかは、実践課題の例や判断基準をもう少し示さないと決めにくい。

三教材の考え方は原稿で説明されているものの、なぜAIを使うために三教材が必要かは、教材1・2が教材3をどう支えるかを短く言い切ると理解しやすい。三冊の書籍紹介は、初級者には「読まないと受講できないのか」という疑問を生みうるが、原稿後半に「先に読む必要はない」とあり解消される。実践案内から次の「はじめに」への接続は明確である。

## 理解を妨げる必須の問題

| 表紙 | 画像だけで分かること | 原稿で補えること・残る問題 |
|---|---|---|
| 2〜6 | 仕事の成果物をAIで作りやすくなったが、作成後の確認・修正や、確認しやすい成果物の形も考えよう、という問題提起。 | 原稿で「作成時間が短くても仕事全体が速く進むとは限らない」と説明する。ただし、困りごとの中心が確認負荷に寄っている。作成に不慣れな人、AIに何を指示すればよいか分からない人にも向くのかが伝わりにくい。対象となる困りごとを、AI初心者にも身近な例で示す必要がある。 |
| 5 | PM・PLは計画書や説明資料など、開発者は設計書・コード・テストを確認する構図に見える。 | 原稿は「例えば」と説明しており、例示のつもりと分かる。しかし画面は役職別の確認分担として読める。確認責任を職種へ固定しているように見え、PM・PLでも開発成果物を確認する場合や、開発者が資料を確認する場合を含まない。役割ラベルを外すか、職種に関係なく担当者が確認する例だと明示したい。 |
| 8〜10 | 三教材が「目的」「言葉」「仕組み」の順で並び、資料作成・開発に活かす流れは見える。 | 原稿は、目的と条件、用語の意味、確認条件を考えてからSkillに記録する、と関係を説明する。初級者には「なぜAIを使うのに業務の目的や言葉の意味まで学ぶのか」がまだ抽象的。教材1・2を省くとAIの出力や確認で何が困るかを、ひとつの作業例でつないで説明してほしい。表紙10は三冊の書籍紹介に見えるため、教材そのものと参考書籍の区別を画面でも明確にしたい（原稿には書籍を先に読む必要がないとある）。 |
| 12 | 10〜3月の準備・実践の時期、先着15名、実務で試して共有する流れが見える。 | 原稿で「目的達成」を確認すると説明するが、受講者が何を持ち帰れば達成なのかは幅がある。全員が仕組みを作るのか、仕事で使える状態まで求めるのか、初級者向けの到達例を示すと参加判断がしやすい。 |

上のうち、特に表紙5の役割の固定化は、画面だけで受講者の仕事の分担を決めつけて見えるため、必須修正と考える。対象者と受講後の到達点も、参加判断に直結するので必須である。

## 任意の改善

| 表紙 | 気づいたこと | 改善の方向 |
|---|---|---|
| 1 | 画像から「仕事でAIを使い続ける」「目的・言葉・Agents・Skills」の概要は分かる。表紙専用原稿は未記録なので、説明原稿の内容は評価できない。 | 原稿を作る場合は、専門語を説明し、参加対象と持ち帰れることを一文で補う。 |
| 2 | 「自分の仕事の目的をAIで達成する」は目標として大きく、どんな作業を扱うのかは次の画面まで分からない。 | 「自分の仕事の一つの作業で試す」など、講座内で扱う単位を導入で示す。 |
| 3〜4 | 「仕事全体の生産性」という大きな問いから、成果物を短時間で多く作る図へ進む。作成物の量が増えることと生産性向上が別であることは原稿で補う。 | 「作る速さ」だけでなく「使える状態までの時間」を見る、と問いを具体化する。 |
| 6〜7 | 「確認・判断」「目的」「条件」「手順」「仕組み」など抽象語が短い間隔で続く。図を見ながら原稿を聞く初級者には、何をどう決めるかの具体例が必要。 | 例えば「誰が何を決める資料か」を一貫した例として、目的から確認条件まで追う。 |
| 8 | 「目的の把握」「言葉の定義」「仕組みの構築」は章名としては揃っているが、日常の作業に結び付く前は意味が取りにくい。 | カード内に「何のため？」「言葉は何を指す？」「同じ条件で繰り返すには？」のような受講者の問いを置く。 |
| 9 | 資料作成と設計・開発の例が並ぶ。開発以外の仕事にも適用できるかは図だけでは分からない。 | 「どの職種でも、繰り返す作業を一つ選ぶ」と原稿か画面で補う。 |
| 10 | 表紙画像の小さい書籍カバーと著者・出版社情報があり、書名よりも書籍を読むことが必要に見える可能性がある。 | 「教材内容の参考書籍」「購入・事前読書は不要」を画面上にも短く置く。 |
| 11〜13 | ポータル、Teams、Kiro、AWSなどの利用環境は具体的。アカウント発行対象や閲覧範囲は原稿にあるが、画面で拾える情報は多い。 | 受講者に必要な行動（教材を見る、質問する、実践する）と、必要な人・時期を優先して目立たせる。 |
| 14 | 三教材の要約と「はじめに」への導線があり、オリエンテーションの締めとして機能している。 | 「目的を決め、必要な内容を伝え、結果を確かめる」という三段階を、全編で同じ表現に揃えると記憶しやすい。 |

## 7つの確認項目への回答

1. **何に困っている人向けか** — 主には、AIで成果物を作れるが、必要な内容を決めることや、出力の確認・修正に困っている人向けと読める。AIを使い始めたばかりの人向けかは明示が足りない。
2. **なぜ受けるとよいか** — 自分の仕事の目的を考え、AIに必要な内容を伝え、結果を確かめ、繰り返し使う手順を改善するところまで実務で試せるから。画像では全体像が分かり、原稿で理由が補われる。
3. **受講後何ができるか** — 自分の仕事の作業を一つ選び、目的・必要条件・確認方法を考え、AIで実行し、出力と目的達成を確かめ、条件や手順を改善すること。具体的な完成例と合格基準は不足。
4. **AIを使うためになぜ三教材が必要か** — 原稿では、目的と必要な内容を考える、使う言葉の意味を揃える、その上でAgents・Skillsに条件や手順を記録するため、と説明している。筋は通るが、画像だけでは前二教材とAIの関係が弱く、実例があると納得しやすい。
5. **導入から次の「はじめに」まで** — 導入、AIで成果物を作る変化と確認負荷、作業の進め方、三教材、仕事への適用、参考書籍、ポータル、実践日程、支援、まとめの順。画像と原稿の双方で、最後に経費精算システム刷新の題材を使う「はじめに」へつながる。
6. **役割への仕事の割当** — 表紙5のPM・PL／開発者の例は固定分担に見えるため不自然さがある。他の画面は概ね役職を限定していない。PM・PLや開発者に特定の役割を割り当てる必要性はこの資料からは読み取れない。
7. **日本語・主語・語彙・認知負荷** — 「目的」「条件」「内容」「仕組み」「改善」が広い意味で繰り返され、何を指すかが文脈により動く。「Agents」「Skills」「Skill」「Agent」の単複・表記も初見では分かりにくい。「自分の仕事の目的を、AIで達成」は目的そのものをAIが達成するようにも読める。導入原稿の「今回のワークショップを企画しました」は運営側の主語で、受講者にとっての利点へ移るまで少し距離がある。具体例を一つ通し、主語と対象を明示すると読みやすい。

## 優先して見直す点

1. 表紙5の役職別の確認分担に見える図を直し、確認する人を職種で限定しない。
2. 初級者も対象だと分かる困りごとの例を導入に足す。
3. 受講後の到達点を、成果物または実践の例で具体化する。
4. 教材1・2が教材3の実行と確認にどう必要か、一つの作業例で説明する。参考書籍と必須教材の区別も画面に示す。
5. 「目的」「必要な内容」「条件」「確認方法」など、何を考えるかを一貫した言葉で示す。

## 文書検査

以下はこのレビュー文書に対する doc-writing-skills の10判定である。機械検査（ゲート1）は実行済みで、1ファイルが0件で通過した。10判定すべてを適用した。

| 判定 | 適用結果 |
|---|---|
| 1 読み手の復元作業 | 「画像だけ」「原稿」「受講者」など、各節の対象を冒頭で定義した。画面番号と記述を対応させた。 |
| 2 情報の型 | 比較・複数指摘・段階のある判断を表と番号付きリストにした。 |
| 3 数に応じた形 | 3件以上の指摘・確認項目は表または番号付きリストにした。 |
| 4 見出し | 見出しを順に読むと、結論、問題、改善、個別回答、検査の順に分かる構成にした。 |
| 5 結論先行 | 「受講者としての結論」と各節の冒頭に判断を置いた。 |
| 6 文体 | 常体に揃えた。表の記述も常体または名詞句に揃えた。 |
| 7 用語 | 画面番号、画像、原稿、受講者の語を区別して使った。Agents/Skills等の画面用語は必要な箇所で維持した。 |

| 9 一度に扱う量 | 長い説明を見出し・表・短い項目に分けた。 |
| 10 比喩・定型句 | 評価は画面と原稿の具体的な要素に結び付け、慣用表現を根拠として使わなかった。 |
