# 「はじめに」の通し確認：2026年10月25日

「はじめに」全8枚の図と原稿を確認し、完成を妨げる矛盾は見つからなかった。受講者Lunaと開発案件の観点での独立確認も実施した。2枚目を補強し、Lunaによる再確認まで終えている。内容の最終確認へ提示できる状態であり、利用者による承認や正本への適用は別である。

## 今回修正した箇所

2枚目のPR条件「承認後は変更不可」に、「どの承認段階かは、PRに記載なし」を追加した。原稿も同内容を補い、変更を取り込んだ後に結合テストを行う時系列を明確にした。3枚目の比較と8枚目の構図は、今回の確認では変更していない。

LunaからはPR条件を「上長承認後」へ変更する案もあったが、それでは曖昧な条件がレビューを通る事例の前提が変わるため採用しなかった。曖昧さがあることを示す補強にとどめた。旧教材1へ橋渡し文を追加する案も、共通題材を使う方針への反映にはならないため採用していない。

## 確認したストーリー

| 接続 | 結果 |
|---|---|
| 案件の説明から不具合発覚 | AIで資料・実装・テストを速く作っても、承認段階と確認結果の対応が示されず、AIと人が見逃したと理解できる。 |
| 不具合修正から設計の問題 | 変更を禁止する時点の修正と、二つの業務判断を表せない設計の残存を区別している。 |
| 設計の問題から追加変更 | 関係を把握せず同じルールを複数実装へ追加した場合に、照合対象が増えるという想定として理解できる。 |
| 教材1から教材3 | 目的・要件、業務モデル・設計、AgentがSkillsを使う作業とAIレビューへ進む。工程ごとの別Agentを勧めていない。 |

## 資料間に残る差分

| 対象 | 残る差分と対応 |
|---|---|
| オリエンテーション8・10・11・14枚目 | 教材2の紹介が「言葉の定義」に寄っている。目的・要件から業務モデルと設計へ進む学びとして、担当セッションへ共有する。該当資料の入力は今回変更していない。 |
| 教材1の本編 | 「はじめに」は経費精算システム刷新を共通題材とするが、現行本編は議事録から課題を整理する旧題材。橋渡し文だけではなく、本編の題材と学習内容を最新方針へ見直す必要がある。 |
| 正本・音声・動画 | 今回の変更は未反映。スライドと原稿の利用者確認、ACDRと承認を経て進める。 |

したがって、「はじめに」単体の図と原稿は最終確認へ進められるが、現行教材1へそのままつないだ教材全体を完成とはしない。
