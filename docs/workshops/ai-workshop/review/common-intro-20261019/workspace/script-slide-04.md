# 結合テストで、承認済みの申請も変更できると分かりました

この案件では、承認済みの申請内容を、申請者が直接変更できない仕様です。

人によるレビューは承認されましたが、変更はまだマージしていません。この案件では、業務の一連の流れを確かめる結合テストへ進みます。

上の図を、左から見てみましょう。まず、申請者が一万二千円の経費を申請します。続いて、承認者がその申請を承認します。そのあと、申請者が同じ申請を開き、金額を一万八千円に変更して保存する操作を試しました。

左下は、期待する動作です。この案件では、承認済みの申請を、申請者が直接変更できない仕様になっています。そのため、金額は一万二千円のまま変わらないはずです。

ところが、右下のように、一万八千円に変更して保存できてしまいました。承認後の変更制限が、実装から抜けていたのです。

単体テストで確かめていたのは、下書きの申請の金額を変更して保存する動作でした。承認済みになったあとのケースは含まれていませんでした。そのケースが単体テストに含まれていれば、そこで発見できた不具合です。今回は、結合テストで申請から承認後の再変更までを試したことで、初めて発覚しました。

この変更はマージせず、制御とテストを修正し、もう一度テストとレビューを行うことになりました。コードやテストを速く作れても、後から修正と確認が必要になったわけです。

必要な条件は、既存の仕様書やコードにありました。それでも、実装やテストから抜け、レビューでも見逃したのはなぜでしょうか。次は、この作業を振り返って考えてみます。
