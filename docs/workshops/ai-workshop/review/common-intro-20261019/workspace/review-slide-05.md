# 内容5枚目の確認

表紙から6ページ目を、事例から三つの教材へつなぐ問いのページに変更した。確認済み1〜4枚目は変更していない。

## 文書の10判定

1. 主語と対象：開発者とレビュー担当者、それぞれが使うAIを明記。
2. 型：存在する資料と、作業についての問いを分けて配置。
3. 列挙：問いを三つに分ける。
4. 見出し：資料も確認もあったのに条件が抜けた理由を問う。
5. 先頭文：抜けた条件は資料にもコードにも存在したと説明。
6. 文体：ナレーションは敬体。
7. 用語：目的、業務の言葉、AIと人の確認を区別。
8. 語彙：一般的な開発用語を使用。
9. 量：改善策の詳細は三つの教材へ分け、ここでは問いを提示。
10. 比喩：使用なし。

## スライドの7観点

- 一貫性：warm-paperと既存の人物・コードの部品を使用。
- ストーリー：不具合の発見を受け、作業の目的、言葉の意味、確認方法の三つを振り返り、教材1の紹介へ接続。
- 日本語：新しい開発者が確認していなかったという説明はしない。目的は大きいほどよいという説明もしない。
- 見出し：実装と確認のどこを振り返るのかを提示。
- 図：資料にある条件と、AIを使う二つの役割を対応させる。
- 配置：図検査1〜4通過。文字のはみ出しなし。描画した画像を目視。
- 動画：今回は対象外。
