# 新しい展開の確認

| 判定 | 結果 |
|---|---|
| 1 指し先 | 上長の支出承認、経理の証憑確認、維持する判断とやり直す判断を明示した。 |
| 2 情報の型 | 各枚の意図と図の関係を表、案件の経緯を構造化データにした。 |
| 3 列挙 | 不具合修正、経理差し戻し、証憑再提出という順序を示した。 |
| 4 見出し | 不具合から追加対応の確認負担、三教材の役割へ進む構成にした。 |
| 5 結論 | 各枚で伝えることを原稿の前に置いた。 |
| 6 文調 | 構成案と原稿案は敬体にした。 |
| 7 用語 | 業務の役割、文脈、集約を同じ意味で扱わなかった。 |
| 8 語彙 | 初級編では操作と業務判断で説明し、専門用語の暗記を求めなかった。 |
| 9 情報量 | 集約の境界の設計は初級編の説明に含めなかった。 |
| 10 比喩 | モデルの大きさを比喩で批判せず、条件の分散と確認範囲を示した。 |

未適用の判定はない。最初の不具合は修正してから追加開発へ進む設定とした。単にフラグや条件分岐が増えることを悪い設計とはしなかった。文書検査とDDD判断の構造・根拠の検査は通過した。今回は構成と原稿案の更新であり、新しい図や動画の完成とは扱わない。
