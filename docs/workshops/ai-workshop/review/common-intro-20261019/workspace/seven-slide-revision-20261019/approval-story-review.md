# 承認段階を取り違える構成の確認

7枚の構成と原稿案を更新した。図は1枚ずつ確認するため、今回は2枚目以降の図を更新していない。

| 判定 | 確認結果 |
|---|---|
| 1 指し先 | 本来の上長承認後と、開発者が理解した経理承認後を明示した。 |
| 2 情報の型 | 各枚の目的・図・次への接続を表にした。 |
| 3 列挙 | 7枚を番号で分け、役割を各欄に記載した。 |
| 4 見出し | 案件紹介から速い承認、不具合、取り違え、教材紹介の順にした。 |
| 5 結論 | 何を伝える枚かを先に示し、原稿案を後に置いた。 |
| 6 文調 | 原稿と構成案の説明は敬体にした。 |
| 7 用語 | 業務の上長承認・経理承認と、人のレビュー承認を区別した。 |
| 8 語彙 | ナレーションではプルリクエスト・エージェント・スキルを発音できる表記にした。 |
| 9 情報量 | 2枚目で承認の意味を説明しすぎず、3枚目で現象、4枚目で解釈を説明した。 |
| 10 比喩 | 取り違えた対象を業務状態として明示し、比喩で説明しなかった。 |

未適用の判定はない。文書検査は通過した。構成案を比較HTMLに掲載し、画面の切り替えと原稿の表示を確認した。新しい図や音声を確認したとは扱わない。
