# AI活用ワークショップのアンケート・効果測定案

主KPIは、目的の明確化率（AIで実現したい目的と、その達成に必要なことを、教材の視聴前より明確に説明できるようになったか）と、目的達成率（取り組むと選んだ目的のうち、1つ以上をAIで達成したか）の2つである。補助の指標は、参加時アンケートで選んだコース（自分で達成する／チームに広げる）ごとに2つずつ測る。AI活用を促進する基盤づくりは先行トライアルとして、参加者と、参加しなかった希望者の終了時アンケートと、ポータルの掲載記録から検証する。人気投票は共有会の表彰として扱う。

設問は、指標から逆算して置く。どの指標にも使わない設問は、結果を読む軸と、教材と支援の調整と、ポータルのアカウントの発行に使うものに限る。本書は運営がMicrosoft Formsへ転記するための設問案である。設問の文面は `src/survey.json` と一致させ、スライドの回答フォームと、Formsの Copilot に渡すプロンプト（[forms-copilot-prompts.md](forms-copilot-prompts.md)）はそのデータから組む。フォームの作成・配信はまだ行っていない。この設問と尺度は今回の企画に合わせて作ったもので、妥当性を検証済みの標準尺度ではない。開始前に、参加者に近い人に回答してもらい、答えにくい設問を直す。

## 実施時点と回答の扱い

| 項目 | 設計案 |
|---|---|
| 事前アンケート | 10月、オリエンテーションと教材の動画を公開する前に、準備期間の希望者が回答する。Teamsやメールで案内し、最後の設問でポータルのアカウントの発行を希望した人にアカウントを発行する |
| 参加時アンケート | 12月中、教材をすべて見たあとに回答する。目的と、その達成に必要なことを1組ずつ書き、参加するかを答える。参加する人は、取り組む目的（いくつでも）とコースを選ぶ |
| 参加者の終了時アンケート | 3月の最終共有会のあとに、参加者が回答する |
| 参加しなかった希望者の終了時アンケート | 3月に、事前アンケートに回答しワークショップに参加しなかった人が回答する |
| 回答者の同定 | 4本とも `Only people in my organization can respond` と `Record name` にし、回答者名で4本を突き合わせる。手入力のIDは設けない |
| 並び | 事前アンケートは、目的があるかを最初に聞いて分岐させる。目的を書く前に他の設問を見せないためである。Formsの分岐は後ろへしか移動できないので、全員に聞く設問を後ろに置く |
| 利用目的 | ワークショップの改善と成果報告。人事評価には使わない運用を提案する |
| 共有範囲 | 個別回答は運営が確認し、部長向けには集計を示す。事例の引用は本人に確認する |

回答者名が記録されるため、完全匿名とは案内しない。15名程度では業務や記述から本人が推測される可能性もあるため、少人数の業務別内訳を必要以上に公開しない。

**使ってもらった相手には、アンケートを配らない。** 成果物を使うのは参加者に限らず、社内の同僚やチームである。その人たちへ回答を依頼する筋も義務も無いため、回答は集まらない。使った結果と振り返りは、参加者本人が終了時に書く。

## 指標と設問の対応

| 指標 | 設問 | フォーム |
|---|---|---|
| 主KPI：目的の明確化率 | AIで実現したい目的があるか、目的と、その達成に必要なこと | 事前 ・ 参加時 |
| 主KPI：目的達成率 | 取り組む目的の選択（いくつでも）、目的ごとの結果、判断の根拠 | 参加時 ・ 参加者の終了時 |
| 補助：実務でAIを使う人の増加 | 過去4週間の実務でのAIの利用頻度 | 事前 ・ 参加者の終了時 |
| 補助：手戻りの減少 | AIが出した結果に、不満やストレスを感じた頻度 | 事前 ・ 参加者の終了時 |
| 補助：チームでの改善の実施 | 振り返りの場を開いた回数 | 参加者の終了時（チームに広げるコース） |
| 補助：やり方のチームへの定着 | 書き方の共有の状態、新しく入った人の立ち上げ期間 | 事前 ・ 参加者の終了時 |
| 基盤：チームでの改善の継続 | 終了後も振り返りの場を続けるか | 参加者の終了時（チームに広げるコース） |
| 基盤：参加者以外での再利用 | ポータルで見つけたものを業務で試したか | 希望者の終了時 |
| 基盤：必要なナレッジの見つけやすさ | 探していたものにたどり着けたか、何を探していたか | 参加者の終了時 ・ 希望者の終了時 |
| 基盤：ナレッジを出す人の広がり | （アンケートでは聞かない）ポータルの掲載記録 | ― |
| 結果を読む軸 | 担当している業務、使えるAIツール、活用の段階 | 事前 ・ 参加者の終了時 |
| 教材と支援の調整 | 目的がまだ無い理由、AIでやってみたいこと・できそうだと思うこと、不満を感じた場面、困りごと、欲しい支援、教材で知りたいこと、未解決の点 | 事前 ・ 参加者の終了時 |
| ポータルのアカウントの発行 | 発行を希望するか | 事前 |

| 14 | ポータル | たどり着けなかったとき、何を探していましたか。 | 長いテキスト・任意 | 見つけやすさ（届かなかった用途） |

### 参加しなかった希望者の終了時アンケート（3月・参加しなかった希望者・3問。うち任意1問）

事前アンケートは、目的のある人が23問、まだ無い人が16問に答える。参加時アンケートの目的は、1組ずつ出し、最大5組と、6つ目以降をまとめて書く欄1つにする。参加者の終了時アンケートは、チームに広げるコースの人が15問、自分で達成するコースの人が12問に答える。

## 目的の記述の判定

目的の明確化率は、目的と、その達成に必要なことの記述を、4つの観点で判定する。

| 観点 | 書けたとみなす記述の例 |
|---|---|
| 何を実現するか | 議事録を、会議の翌朝までに全員へ共有する |
| 誰のためか | チームのメンバーのため |
| 何が変われば達成か | 担当と期限が漏れずに共有され、確認の手間が減る |
| 達成に何が必要か | 会議の録音の文字起こしと、担当と期限の書き方の決まりをAIに渡し、抜き出した結果を書記が確認する手順 |

「達成に何が必要か」は、**目的に対して必要なこと**（情報・手順・判断の基準・関係者など）を書けているかで判定する。自分のAIのスキル（「AIの使い方を覚える」など）だけを書いた回答は、書けていないと判定する。事前アンケートで目的がまだ無いと答えた人は、観点の数を0として扱う。

観点ごとに書けたとみなす条件と実例を判定基準の文書にし、AIが全件を同じ基準で判定し、運営が抜き取りで確認する。1人が書いた目的のうち、最も多くの観点を書けたもので、その人の事前と参加時を比べる。事前と参加時で1つ目に書く目的が入れ替わっても、同じ人の変化として比べるためである。観点を設問文に出さないのは、設問そのものが観点を教え、事前の時点で書けてしまうのを避けるためである。

## 推奨KPI案

### ワークショップ

| 指標 | 定義 |
|---|---|
| 主KPI：目的の明確化率 | 最も明確に書けた目的の観点の数が、事前より参加時で増えた人数／事前と参加時の両方に回答した人数。事前で4観点を書けていた人は、内訳として示す |
| 主KPI：目的達成率 | 参加時アンケートで取り組むと選んだ目的のうち、1つ以上を終了時に「達成」と答え、根拠を書いた参加者数／ワークショップに参加した人数（先着15名、開始時点で固定）。報告には、達成した目的の合計と1人あたりの数を添える。これは指標にしない |
| 補助：実務でAIを使う人の増加 | 自分で達成するコースの人のうち、過去4週間の実務での利用が「月に1〜3回」以上の人数を、事前と終了時で比べる。両方に回答した人数を示す |
| 補助：手戻りの減少 | 自分で達成するコースの人のうち、AIが出した結果に不満やストレスを「ほぼ毎回」「たびたび」感じた人数を、事前と終了時で比べる。「AIを使っていない」は比較から除く |
| 補助：チームでの改善の実施 | チームに広げるコースの人のうち、振り返りの場を1回以上開いた人数／チームに広げるコースの人数 |
| 補助：やり方のチームへの定着 | チームに広げるコースの人のうち、書き方の共有が上の選択肢へ移った人数と、立ち上げ期間が短くなった人数。分母は、それぞれ比較できた人数。「該当する人がいない」は比較から除く |

目的達成率を、達成した目的の数を取り組んだ目的の数で割って数えないのは、多く取り組む人ほど率が下がり、少なく選ぶほうが得になるからである。多く取り組んだ成果は、添える数で示す。

### AI活用を促進する基盤づくり

| 指標 | 定義 |
|---|---|
| チームでの改善の継続 | ワークショップの終了後も振り返りの場を続け、日程が決まっている参加者数／チームに広げるコースの参加者数 |
| 参加者以外での再利用 | 参加しなかった希望者のうち、ポータルで見つけた仕組みやノウハウを自分の業務で試した人数／参加しなかった希望者数。未回答は内訳として示す |
| 必要なナレッジの見つけやすさ | 探していたものにたどり着けた人数／探した人数（「探していない」を除く）。参加者と、参加しなかった希望者の両方から取る。たどり着けなかったときに探していたものは一覧にする |
| ナレッジを出す人の広がり | ポータルに、自分のノウハウや使い方を1件以上載せた、参加しなかった希望者の数／参加しなかった希望者数。ポータルの掲載記録から数える |

主KPIと補助の割合は、未回答を分母から外さず内訳を併記する。本人の回答である指標は、報告で成果物と振り返りの記録を添える。

AI活用を促進する基盤づくりの指標は、次の期にポータルを部内へ広げるか、何を作るか、カテゴリとタグをどう直すかの判断に使う。ポータルの掲載数や閲覧数は、成果として数えない。

目標値は事前アンケートと運営条件を踏まえ、開催前に設定する。現時点では割合の目標を決定していない。交流会の参加人数は運営改善用の参考情報として扱い、KPIと混ぜない。

## 部長向け報告の構成

| 報告すること | 集計・提示の方法 |
|---|---|
| 回答状況 | 4本のフォームごとの回答者数／対象者数と、比較できた人数を示す |
| 目的の明確化 | 観点の数が増えた人数と、事前と参加時の記述の実例を示す。事前で目的がまだ無かった人の内訳も示す |
| 目的の達成 | 1つ以上を達成した人数と、達成した目的の合計、判断の根拠の実例を示す |
| 補助の指標 | コースごとに、事前と終了時の選択肢の移り方を人数で示す |
| 振り返り | 1回以上開いた人数と、話し合った問題・直したことの実例を示す |
| AI活用を促進する基盤づくり | 4つの指標の人数と、たどり着けなかったときに探していたものの一覧を示す |
| 表彰 | 投票結果と利用者の感想を示す |
| 今後の支援 | 目的がまだ無い理由・やってみたいこと・不満を感じた場面・困りごと・欲しい支援・未解決の点から、教材と相談の改善を決める |

比較には、同じ回答者名で両方の時点に回答した人を用いる。比較対象人数を明示する。未回答・対象外は補完せず、対応する分母から除く。業務やツールの違いで結果を読むときは、事前アンケートの担当業務・使えるAIツール・活用の段階で分ける。

意味の異なる段階の選択肢は合算しない。選択肢を等間隔とみなした「何％伸びた」という表現もしない。少人数のため、割合だけでなく人数を必ず示す。

この設計で示すのは、期間中の変化と実例である。業務経験やツール更新の影響もあり、変化のすべてを研修だけの効果とは断定しない。学習が進んで自己評価が厳しくなる場合もあるため、下がった回答は記述と実例を併せて読む。

## 最終成果物発表・交流会と人気投票

コミュニケーション施策として、参加者がざっくばらんに交流できる場にする。人気投票は以下の提案であり未確定。後日の試用期間は置かない。作った仕組みは、2月に、選んだコースに合わせて自分の業務かチームで使う。会場・軽食費・日程は別途調整する。

| 段階 | 運営案 |
|---|---|
| 発表 | 軽食を囲むオフライン交流会で、短いデモと会話を通じて成果物を紹介する |
| 投票 | 共有会で紹介されたデモのうち「自分の仕事でも使いたい」ものへ1人1票を投じ、理由を添える。自作品への投票は行わない |
| 選べない場合 | 該当なしを選べる。無理に1票を求めない |
| 表彰 | 得票数が最多の作品を人気作品として表彰する。同数なら同時受賞とする |
| 結果表示 | 得票数を並べる。人気投票であることを明示する |

デモの紹介だけにもとづく投票なので、票数を品質や汎用性の客観順位として扱わない。表彰されなかった成果物も、使った結果と改善内容をポータルに保存する。

## Microsoft Formsでの実装

回答はMicrosoft Formsで集める。フォームは4本である。

| フォーム | 時期 | 回答する人 |
|---|---|---|
| 事前アンケート | 10月（動画の公開前） | 準備期間の希望者 |
| 参加時アンケート | 12月中（教材の後） | 準備期間の希望者 |
| 参加者の終了時アンケート | 3月 | 参加者 |
| 参加しなかった希望者の終了時アンケート | 3月 | 事前に回答し、参加しなかった希望者 |

`One response per person` が制限するのは、1つのフォームにつき1回の回答である。時点ごとにフォームを分ける理由はここにある。ワークショップを3か月にしたため、中間の測定は置かない。

| 設問 | 質問の種類 |
|---|---|
| 選択肢で答える設問（目的の有無、ほかにも目的があるか、目的がまだ無い理由、できそうだと思うこと、利用頻度、活用の段階、不満やストレス、不満を感じた場面、担当業務、ツール、共有、立ち上げ期間、困りごと、欲しい支援、アカウントの希望、参加、取り組む目的、コース、振り返りの回数と継続、たどり着けたか、試したか） | `Choice`。複数選択の設問は、複数の回答を許す |
| 目的ごとの結果 | `Likert`。行に1つ目〜5つ目と6つ目以降、列に達成・一部達成・未達・取り組まなかった・書いていない |
| 記述で答える設問（目的、必要なこと、6つ目以降の目的、やってみたいこと、根拠、目的の変更、振り返りの内容、探していたもの、教材で知りたいこと、未解決の点） | `Text`。長い回答を許す |

設問のまとまりは `Section` で分け、答える人は `Add branching` の分岐で分ける。分岐の移動先は、[forms-copilot-prompts.md](forms-copilot-prompts.md) の表に置く。

配布時は `Only people in my organization can respond` と `Record name` を選び、`One response per person` を設定する。回答期間は `Start date` と `End date` で指定する。集計は `Open results in Excel` から `Download a copy` を取得し、氏名の列で時点間を突き合わせる。参加時アンケートの回答内容は、開始時に本人へ送り、終了時に手元で照合できるようにする。送り方（受信確認の機能か、運営からの送付）は配布前に決める。

Microsoft Formsの[質問の種類](https://support.microsoft.com/en-us/office/create-a-form-with-microsoft-forms-4ffb64cc-7d5d-402f-b82e-b1d49418fd9d)・[設定](https://support.microsoft.com/en-us/forms/adjust-your-form-or-quiz-settings-in-microsoft-forms)・[集計](https://support.microsoft.com/en-us/office/check-your-form-results-02859424-341d-406f-b32a-9a0fbaf357af)を2026-09-20に、[分岐](https://support.microsoft.com/en-us/forms/use-branching-logic-in-microsoft-forms)（後ろの設問へしか移動できないこと・セクションにも分岐を付けられること）と `Record name` を2026-10-01に確認した。上記の設定名と質問の種類は、原文の表記をそのまま用いている。フォームを4本に分ける構成と、分岐の組み方は、今回の設計判断である。
