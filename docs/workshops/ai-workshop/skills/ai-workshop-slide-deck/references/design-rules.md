# スライドの設計規則

**この規則が立っている考え方は `knowledge/visual-design-for-slide-decks.md` にある。**
**規則の理由が要るときは、そちらを読む。**

**この文書は、実際に読み手の承認を得た枚から取り出した規則である。**
印象ではなく、通った枚の実測から書いている。

---

## 1. 1枚1主張

**見出しは主張を断定形で書く**。問いの形にしない。1〜2行に収める。

```
書かない   移行の進捗について
書く       移行が終わっているのは、読み取り側だけである
```

**枚を作る前に、その枚で言い切ることを1文で書く**。1文にならないなら、その枚は2枚に割れている。

### 一覧を見せる枚は、名詞句の見出しにする

**主張ではなく、何の一覧かを示す枚がある。**
道具の一覧・制約の一覧・分類の一覧がこれにあたる。
**そこへ断定形をあてると、一覧が支えていない主張が立つ。**

```
一覧の枚   仕様の性質を示す11項目の観点
           本研究では問わないこと

主張の枚   母集団は、OpenSpec を対象に決めてから作った
           依頼書には、実装の探し方を書かない
```

**見分け方は、下に置くものが根拠か中身かである。**
根拠なら主張の枚、中身なら一覧の枚である。

## 2. 量の上限

```
大きい要素    2つか3つ。数値・太い1行・図のどれか
              4つ以上あると、どれが主張か消える

各要素の下    条件を1行  →  但し書きを1〜2行  →  出典を1行
              この順を崩さない。出典は要素から離さない

締め          枚の下に1〜2行。次の枚へ渡す

色            強調は1か所だけ
```

**「情報量が多い」の境目は、行数ではなく大きい要素の数である。**
情報が多くても、大きい要素が2つに収まっていれば読める。

---

## 3. 3つの型から選ぶ

### 型A 列挙と図解

```
左   数を宣言して、同じ形で並べる。「この3つだ」と言い、3項目を同じ見出し＋2行で書く
右   その3つのどこが壊れるかを、図で示す。言葉で繰り返さない。図の下に結論を1つ置く
```

**使いどころ**。左で「何を言うか」を宣言でき、右でその一部を図にできるとき。

### 型B 数値2つの対

```
左   大きい数値1つ。下に条件を1行、但し書きを1〜2行、出典を1行
右   同じ入れ子で、もう1つの数値。左と字数も段数も揃える
```

**使いどころ**。2つの実測を突き合わせるとき**。3つ目を足さない。**

### 型C 種類を分ける

```
左   数値の対
右   段階を追う箇条3つ。1つずつ強くなり、最後の1つだけ色が付く
```

**使いどころ**。情報量が多いとき**。左右で情報の種類を変えると、量があっても読める。**
同じ種類を左右に置くと、量がそのまま重さになる。

---

## 4. 左右の扱い

**左右を対称にする必要はない**。揃えるのは大きい要素の数と、根拠の置き方だけである。

**ただし、対比を語るときは部品を揃える。**
同じことを比べたいのに左右で違う部品を使うと、どう調整しても見た目が合わない。

```
部品を揃える     対比の枚。左右で同じ枠・同じ段数にし、色だけを変える
部品を変えてよい  対比ではない枚。それぞれに適した形で書き、高さだけを近づける
```

**同形式にすると決めたら、行数まで揃える**。段数が同じでも、片方の見出しが2行で
もう片方が1行なら、その下の全部がずれる。

```
揃える   ラベルの有無 ／ 見出しの行数 ／ 根拠の数 ／ 補足の行数 ／ 締めの有無
違ってよい 色だけ
```

**字数を数えて、同じ行数に収まる文にする**。収まらないなら、両方とも同じ行数まで削る。

**高さを強制的に揃えない**。`margin-top:auto` で締めを下端に落とすと、
高さは揃うが不自然な余白が空く。**中身を減らすか、置き方を変えて揃える。**

```
悪い   縦に長い要素を、余白で押し広げて相手に合わせる
良い   横に広い帯に置き直す、要素の数を減らす、別の枚に分ける
```

---

## 5. 列に役割を割り当てたら、全枚で守る

**繰り返すものと、変えるものを分ける**（概念3）。

```
繰り返す   目印になる要素を1つ。列に割り当てた役割
変える     枚ごとの組み方。中身の形
```

**両方を繰り返すと単調になり、両方を変えるとばらばらになる。**

**「左＝いま起きていること、右＝提案」のように列へ役割を与えたら、その割り当てを崩さない。**

**幅いっぱいの帯で横断させない**。帯は左右どちらの話でもあるように見えるため、
片側だけの材料を帯に置くと、読み手が誤解する。

---

## 6. 主従を守る

```
大きい文字   主張
小さい文字   ラベル・出典・術語
```

**色も同じである**。均等に配ると、見る順序が消える（概念2）。

```
支配する色    1つ。枚の見た目の6割から7割を占める
支える色      1つか2つ
際立たせる色  1つだけ。ここが目を引く
```

### 既定値のままにしない

**色は題材から決める**。既定の青は、題材について何も言わない（概念4）。

```
置かない   見出しの下の線
           色の帯
           縁の縞
```

**これらは、AIが作った見た目として知られている。**
**目印にするなら、題材に結びついた要素を1つ選ぶ。**

**英語の術語は従に置く**。日本語の説明が主である。

```
悪い   cold start
       初回だけ応答が遅くなる

良い   初回だけ応答が遅くなる
       cold start
```

## 7. 文の書き方は、日本語の文書と同じ規約に従う

**スライドと文書で、日本語の規約は変わらない。**
主語述語・目的語・指示語・1文の長さ・名詞の連結・曖昧語は、
**読み手に組み立て直す作業をさせない**という一点から出ている。

**数値も同じである**。原典の文字列で確認してから載せる。要約経由で引かない。

**日本語の文書を書く規約が、この場に別に在るなら、それを当てる。**
無いなら、次の3つだけを当てる。

| 見るもの | 判定 |
|---|---|
| 文 | 頭から一度読んで、戻らずに意味が取れるか |
| 並んだ項目 | 語尾が揃っているか |
| 文体 | 1枚のなかで、敬体と常体が混ざっていないか |

**この節に規約を写さない**。写せば、直すたびに2か所を直すことになる。

## 8. 締めの前に確かめる

```
1  この枚の主張を1文で言えるか
2  大きい要素は2〜3個に収まっているか
3  出典は、その要素の直下にあるか
4  強調は1か所か
5  列の役割は、他の枚と同じか
5b 目印になる要素は、全枚で同じか
5c 見出しの下の線・色の帯・縁の縞が無いか
6  英語の識別子・術語が、日本語より大きい文字になっていないか（§6）
7  描画して、枠から出ていないか

文の書き方と語彙は、§7 の判定を別に当てる
```

### 注釈を、列の下にぶら下げない

**補足したいことがあるなら、本体の一部にする。**
列の末尾に1行足すと、どこにも属さない字が浮く。

```
悪い   列の中身
       （空き）
       補足の1行

良い   見出しの直下に置く       主張の理由なら、読む前に要る
       表の1行として足す       同じ枠に入るなら、行にする
       要素の直下に置く        その要素だけの話なら、そこに付ける
```

---

**7 は、描画した画像を見て数える。**
`NO_INTERNAL_REFERENCE` `under-promise` のような識別子が
行の頭で大きく出ていたら、日本語の説明と入れ替える。
