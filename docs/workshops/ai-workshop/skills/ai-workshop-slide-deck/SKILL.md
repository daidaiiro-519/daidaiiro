# AIワークショップのスライドを作る

## 対象と資料の場所

このSkillは `ai-workshop/skills/ai-workshop-slide-deck/` に同梱されている。
資料の基点はこのフォルダの2階層上の `ai-workshop/`。別の場所へSkillを
インストールした場合は、ユーザーが指定した展開先を基点にする。

- `build_deck.py`: `SLIDES` が順序・見出し・本文・発表原稿、`CSS` が現在の外観を持つ。
- `visuals.py`: 同じ配色のSVG図解と部品。
- `director-deck.html` / `director-deck.pdf`: 現在の完成例。
- `workshop-plan.md`: 開催条件と運営提案。
- `survey-and-evaluation.md`: 設問と評価の正本。
- `previews/`: 現在の見た目を確認する画像。

## 作成・編集

1. 指定された資料・変更範囲を確認し、該当する原典と現在のスライドを読む。
   開催条件と提案を区別し、題材を変えるときは元の人数・費用・日付を流用しない。
2. [デザイントークン](references/design-tokens.md) と
   [設計規則](references/design-rules.md) を読む。現行資料の配色・寸法には
   デザイントークンの記述を優先する。設計の理由が必要なら
   [背景](references/knowledge/visual-design-for-slide-decks.md) を参照する。
3. 1枚で伝えることと順序を決め、`SLIDES` の対象項目と必要なSVGを編集する。
   表紙は題名、主張を伝える枚は1文の見出し、設問一覧は内容を示す見出しにする。
   図解・比較・表を内容に応じて選び、大きい要素は2〜3個を目安にする。
   強調色は主張を支える1か所に集める。数値には原典・条件を添える。
4. 既存デッキの更新は生成元を編集する。新しい題材なら資料フォルダを作業先へ
   複製してから編集する。同梱テンプレートと `visuals.py` も保持する。
5. 資料フォルダで `python3 build_deck.py` を実行する。Python 3の標準ライブラリだけで
   HTMLと `speaker-notes.md` を再生成できる。生成HTMLだけを編集すると次の生成で消える。
   枚数を変えたら原稿冒頭の本編・付録の枚数説明も更新する。
6. [描画確認](references/render-check.md) に沿って変更した枚を画像で見て、
   全枚のはみ出し、順序、ラベル、通し番号、発表原稿を確かめる。
   1280×720の固定ステージ、矢印・ボタン・スワイプ・ハッシュによる移動を保つ。
   縦長・横長画面でも確認する。文字を小さくして詰め込まず、内容を減らすか枚を分ける。

## 配布

HTMLはブラウザで直接開ける。フォントは端末依存なので、見た目を固定した配布には
PDFも出す。ブラウザの印刷で背景を有効にし、ヘッダー・フッターを無効にして、
CSSのページ寸法（1280×720）を使う。PDF出力後にページ数と切れを確認する。
PDF・プレビュー・確認記録は `build_deck.py` では更新されないため、内容変更時は別途更新する。
報告には成果物の場所、変更内容、実施した確認と未確認事項を短く記す。

## 同梱テンプレートの扱い

`assets/deck-template.html` は既存ビルダーが使う土台であり、元の暗色テーマを含む。
現行の外観は `build_deck.py` の後続CSSが上書きしている。
テンプレート単体を完成例とみなさず、同梱ビルダーを使う。
別の生成方法では [assets/design-tokens.css](assets/design-tokens.css) を基底CSSの後に適用し、
現行デッキの余白・書体・図解も合わせる。色を変える際はCSSとSVGの固定色の両方を確認する。
