全体像

JSON Schema を Semantic に拡張し、その型で作成・更新・削除・検証・描画・検索する基盤。どんな Concrete を作るかは使う側が決める。

SAS は能力・記録（動いているセッションを回すため）・公開する形と、一般の能力の契約まで。製品は作らずに差し込む。目的ごとに進める営みは使う側。

使う側目的のセッション・承認・まとめ・コミット・PR
一般の製品Git・コーディングエージェント・検査器・テンプレートの処理系。アダプターで差し込む

事業領域と文脈

事業領域 SAS を分解して業務領域を見つけ、SAS 自身の4つを、意味の境界の内側の広い1つの文脈「契約とインスタンス」に置く。一般の4つと使う側は外の文脈。

業務領域は見つけるもの、文脈は設計するもの。区分は仮で、確かめるときに実装の方法から逆に判定する。

中核を含む文脈「契約とインスタンス」は、変わりやすいツールと Git にモデル変換装置を置く。使う側へは公開された言葉（Abstract と CLI の出力）だけを出す。

ドメインモデル

集約は3つ。Concrete・インスタンス（契約への適合）と、SAS が立てたセッション（意味の操作）。上から決め、下から確かめて同じ形になったものだけを domain に置く。

契約への適合の domain は何にも依存しない。意味の操作の domain はその値を使う。操作の記録と描画は domain を持たない（スクリプト）。点線の箱は use_cases に残すもの。

ファイルの中身は Git。操作の記録は集約にせず、追記する行のまま。

Rust の決まり（一次情報の頁と行）
  • 依存の向きを強制したい境界と、外のライブラリを閉じ込めたい所だけを crate にし、それ以外はモジュールで分ける。crate の数の基準は原典に無い（Book ch07-01:186・ch14-03:187（基準の記述が無い）・ch07-03:296・Reference visibility:476）
  • domain は業務領域ごとに crate を分ける（conformance-domain と semantic-operations-domain）。1つの crate の中では子のモジュールが祖先の項目を使えるので、集約の間の向きはモジュールでは止められない（Book ch07-03:296・ch14-03:299）
  • 根の Cargo.toml は virtual manifest。[workspace] に members と resolver = "3" を書く（Cargo workspaces:241・258、Book ch14-03:207〜211）
  • 外のライブラリの版は [workspace.dependencies] に置き、各 crate は workspace = true で継承する（optional にはできない）。SAS の中の crate どうしは path dependencies（Cargo workspaces:359・363、specifying-dependencies:425）
  • crate が使えるのは自分の Cargo.toml に書いた crate だけ。これで domain の無依存と、ライブラリの閉じ込めを強制する（Book ch14-03:299・390）
  • lib.rs は pub mod aggregates; pub mod values; pub mod services;（events は作らない）。crate の中だけで使う部品は pub(crate)（Book ch07-02:273、Reference visibility:390・476）
  • mod.rs を使わない。src/aggregates.rs と src/aggregates/concrete.rs・instance.rs・agent_session.rs、src/aggregates/agent_session/turn.rs の形にする（Book ch07-05:251・265・268）
  • application の ports.rs が、ポートで使う domain の型を pub use で再公開する。adapters は application だけに依存する（Book ch07-04:392、Reference visibility:564）
  • 組み立ては cli の main.rs。outbound の crate に依存してよいのは cli だけ（Book ch14-03:299（推論：実装の型の名前を書くので依存が要る））
  • ポートは trait で、9つとも dyn で使う。dyn compatible に保つ：型引数のあるメソッド・async fn・関連定数を持たず、Self を receiver 以外で使わない。sealed にしない（Reference traits:412・429・445・459、API Guidelines C-OBJECT:322・324・321、C-SEALED:169）
  • 集約の欄は private、メソッドだけ pub。ID・指紋は newtype で区別する（Book ch07-03:477、API Guidelines C-STRUCT-PRIVATE:218・C-NEWTYPE:169）
  • adapters で外の trait（rusqlite・serde など）を domain の型に実装しない（orphan rule）。sqlite の crate は自分の行の型を持って変換する（Book ch10-02:302・309・313、Reference implementations:658・659・669）
  • 依存のグラフは循環させない（Cargo resolver:568・585）
