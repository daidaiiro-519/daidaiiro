Q1

描画の契約は、見た目について何を正本として持ち、何を検査するか

見た目はトークン（3層）と CSS（直値を持たない）の2つの正本で持ち、描画の道具は値を差し込むだけにする。トークンと CSS は validate が検査する
  • view.tokens.json ── 共通のトークンは色だけにする。色味の違う数パターン（パレット）を、明暗の両方で持つ。字の大きさ ・ 余白は、共通の view.css が固定の値で持つ
  • view.css ── セレクタと規則だけを持つ。色 ・ 寸法 ・ 字の大きさは、トークンの変数だけを参照する
  • 描画の道具（view） ── 3つの正本を読み、値を差し込むだけにする。雛形のコードに見た目の文字列を持たない
  • 検査（validate） ── トークンの形、CSS に色の直値が無いこと、CSS が参照する変数がすべてトークンに在ること、文字と地の色の比、の4つを検査する
この答えの完成イメージ ── UI ・ 図

描画の道具は、トークン ・ CSS ・ 型 ・ 中身の4つを読んで頁を組むだけにする。トークンと CSS は validate が検査する

Q2

トークンと CSS の正本をどこに1つ置き、5言語の描画と各 Skill へどう行き渡らせるか

正本は skills-creator の references/view/ に1つ置き、scaffold が各 Skill の references/ へ写す。描画の道具は Skill 自身の写しを読み、コードに見た目の既定値を持たない。check が写しと正本の差を報告する
  • 正本 ── skills-creator の references/view/ に1組だけ置く。中身は、トークン ・ トークンのスキーマ ・ CSS ・ 頁の型の4つである
  • 配り方 ── scaffold が、Skill を作るときに4つを Skill の references/ へ写す。判断基準のスキーマを写すのと同じ扱いにする
  • 描画 ── 5言語の view は、Skill 自身の references/ から4つを読むだけにする。コードに見た目の既定値を持たない。4つが無ければ、描かずに理由を返す
  • 同期 ── check が、Skill の写しと正本の差を報告する。正本を直したら、報告に従って各 Skill の写しを直す
この答えの完成イメージ ── UI ・ 図

正本は skills-creator に1つ置き、scaffold が各 Skill へ写す。描画の道具は Skill 自身の写しを読み、check が写しと正本の差を報告する

コードに見た目を持たないこと見た目の正本はトークン ・ CSS ・ 型の3つで、描画の道具は値を差し込むだけにする決まり論点1（Round 1 で承認）
Skill を単独で配れることSkill は他の Skill に依存しない決まりskills-creator の決まり（ACDR 0066）

Q3

共通の色のトークンを何パターン持ち、表とコードブロックをどの規則で描くか

差し色の違う3つのパレット（緑 ・ 藍 ・ 橙）を明暗つきで持ち、Skill はそのうち1つを選ぶ。表は見出しの行に面の色を敷いて太字にし、行ごとに面の色を交互に敷いて枠で囲む。コードブロックは等幅の書体にし、枠と差し色の縦線で本文と分ける
  • パレット ── 差し色の違う3つ（緑 ・ 藍 ・ 橙）を、明と暗の両方で持つ。Skill は写しの palette の欄で1つを選ぶ
  • 色の役割 ── どのパレットも同じ10の役割を持つ。頁の地 ・ 面 ・ 帯 ・ 文字 ・ 薄い文字 ・ 線 ・ 差し色 ・ 差し色の淡い地 ・ 注意 ・ 注意の淡い地である
  • 表 ── 見出しの行は面の色の地に太字で書き、下に太い線を引く。行ごとに面の色を交互に敷き、表全体を角の丸い枠で囲む
  • コードブロック ── 等幅の書体にし、面の色の地と枠を付け、左に差し色の縦線を引いて本文と分ける
この答えの完成イメージ ── UI

Q4

Skill 固有の見た目をどう持たせ、acdr ・ ブレストボードと雛形から作った Skill を契約の形へどう移すか

Skill 固有の見た目は、共通の写しとは別の2つのファイル（view.skill.tokens.json ・ view.skill.css）に持ち、描画は共通の後ろに重ねる。移すのは3段で、skills-creator と14の Skill の描画を先に、acdr とブレストボードの独自の出力をそれぞれ後に移す
  • Skill 固有の見た目 ── 要る Skill だけが、view.skill.tokens.json（固有のトークン）と view.skill.css（固有の規則）を references/ に置く。固有の規則も色の直値を持たず、共通の色の役割か固有のトークンを参照する
  • 描画 ── 共通の3つを読み、固有の2つが在れば後ろに重ねる
  • check ── 共通の写しだけを正本と比べる。固有の2つは比べない
  • 移す順 ── 段1で skills-creator（正本 ・ 雛形 ・ scaffold ・ check）と、雛形から作った14の Skill の描画を移す。段2で acdr、段3でブレストボードの独自の出力（記録 ・ ボード）を移す。段ごとに ACDR を1件起こす
この答えの完成イメージ ── UI ・ 図

共通の写しは正本と一致させ、Skill 固有の見た目は別の2つのファイルで後ろに重ねる。check は共通の写しだけを比べる
