schema 駆動の一日

仕様を書いてから、壊れて、直るまでを実際に動かした記録である ── 画面の枠の中身は、試作が出力した文字列そのもので、1文字も書き換えていない。 コマンド名（schema）だけは、まだ無い道具の呼び名として置いた。

3人が承認する ── 読むのは HTML だけである

人が実際に見る画面（射影をそのまま描画した）

出荷指示（集約）

不変条件

  • 明細の合計は、引当済の数量を超えない　sum(lines.qty) <= allocatedQty

操作

  • 作成する ── 事前 [] ／ 事後 ["status == 準備中"] ／ 書き換える ["出荷指示"]
  • 明細を足す ── 事前 ["status == 準備中"] ／ 事後 ["lines が1増える"] ／ 書き換える ["出荷指示", "出荷明細"]
  • 確定する ── 事前 ["status == 準備中", "lines.length > 0"] ／ 事後 ["status == 確定済"] ／ 書き換える ["出荷指示", "出荷明細"]

シナリオ

  • SC-01J7Q4M　明細が0件のとき、確定できない
  • SC-01J7Q4N　明細が1件あれば、確定できる

承認したのは、シナリオ SC-01J7Q4M と SC-01J7Q4N の2本である。

4AI が実装し、テストを書き、結んだと申告する

申告は MCP の1操作で行う。道具はソースを1行も読まない。

> bind(node="SC-01J7Q4M", external="usecase::tests::明細が0件のとき確定できない")
> bind(node="SC-01J7Q4N", external="usecase::tests::明細が1件あれば確定できる")
対応表へ2行入った
対応表は、道具が持つ1つのファイルである。形式はまだ決めていない ── ここでは JSON で書き出した。
$ cat .schema/bindings.json
{
  "bindings": {
    "SC-01J7Q4M": ["usecase::tests::明細が0件のとき確定できない"],
    "SC-01J7Q4N": ["usecase::tests::明細が1件あれば確定できる"]
  }
}
