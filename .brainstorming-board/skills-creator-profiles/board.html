Q4

5つの組の雛形が、契約を満たし続けることを、どこでどう試験するか

このリポジトリの CI で、skills-creator が変わるたびに5つの組すべてを試験する。組ごとに、雛形から Skill を生み、そのまま組み立て、check（1段目と外部の道具の直書きの検出）と共通の事例（論点2）に合格することを確かめる。そのために、雛形は差し込み場所を埋めなくても組み立てられる形（動く見本の道具を1つ持つ形）にする
  • skills-creator を組み立てる
  • 組ごとに、雛形から見本の Skill を生む（scaffold に言語を渡す）
  • 生んだ Skill を、手を加えずに組み立てる
  • check に合格することを確かめる（1段目と、外部の道具の直書きの検出）
  • 共通の事例（論点2）を当て、CLI の出力が期待どおりであることを確かめる
  • 外部の道具の名前を直書きした行を足し、check が検出することを確かめる（検査が効いていることの確認）
この答えの完成イメージ ── UI ・ コード
skills-creator scaffold sample-py --language python --path work/
cd work/sample-py && （組の組み立てのコマンド）
skills-creator check work/sample-py              → 不合格 0 件
skills-creator conform work/sample-py            → 共通の事例 すべて一致
（外部の道具の直書きを1行足す）
skills-creator check work/sample-py              → 「外部の道具の名前を直書きしている」を検出

処理系が無いことを合格と扱わないこと古いものを黙って返さないのは、「検査していないのに合格と出る」と同じ型の欠陥である。決まり.claude/skills/skills-creator/references/tool-contract.md（経路 ・ 大きい出力 ・ 保持）

案採らなかった理由
雛形の形（ファイルの在り処）だけを静的に試験する生んだものが組み立てられるかを確かめない。実際に、いまの Rust の雛形は差し込み場所を埋めないと組み立てられない
見本の Skill を組ごとにリポジトリへ置いて試験する雛形と見本が2か所になり、雛形を直しても見本が古いまま合格する
