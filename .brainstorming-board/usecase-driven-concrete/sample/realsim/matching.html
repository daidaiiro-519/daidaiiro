テスト条件 ID の突き合わせ

仕様に書いた条件が、Python と Go のどちらのテストにもあるかを、道具 concrete がどうやって確かめるか。値は、実際に流したリポジトリのもの（テスト条件27件のうち8件を抜粋）。

1件の流れ

例は、調理枠の「確保する」の事前条件1（空きが足りなければ拒否する）。ID とハッシュ値が、仕様からテストの記録まで同じ文字列のまま運ばれる。

人が書く（宣言）

① 仕様の条件

AGG-2 調理枠
 commands[0] 確保する
  preconditions[0] PRE-1
   condition: 空き ≥ 引数
   reject: 調理の空きが足りない
道具が出す（concrete conditions）

② テスト条件

AGG-2.CMD-1.PRE-1
hash  42258840
level component

ID は「宣言.コマンド.事前条件」。ハッシュ値は、期待する結果を決める欄（条件 ・ 拒否の理由 ・ 例）から計算する。

AI が書く（テストのソース）

③ テストの先頭で記録する

Python
trace("AGG-2.CMD-1.PRE-1",
      "42258840","component")

Go
trace(t, "UC-1.EXT-2",
      "ed3c2076", "system")

trace は各言語で数行の補助の関数。環境変数 CONCRETE_TRACE のファイルへ1行追記するだけ。

テストを流すと書かれる（build/trace.jsonl）

④ 記録ファイルの1行

{"condition":"AGG-2.CMD-1.PRE-1",
 "hash":"42258840",
 "level":"component",
 "test":"tests/test_domain.py::
   test_reserve_rejects_short"}

pytest と go test が同じファイルへ追記する。合否は書かない。

1ID で引き当てる仕様の ID ごとに、記録ファイルに同じ ID の行があるかを見る。無ければ欠け。記録にあって仕様に無い ID は余り。
2ハッシュ値を比べる行のハッシュ値（テストを書いたときの仕様の版）と、今の仕様のハッシュ値が違えば古い。
3レベルを比べる求めるレベル（実装方法の表から道具が決める）の行が無ければレベル違い。3つとも合えば対応あり。

道具は、テストのソースも、何語で書いたかも、テストが通ったかも見ない。照らすのは文字列の ID とハッシュ値とレベルだけなので、どの言語でも同じに動く。テストが通るかは、pytest と go test がそれぞれ判定する。

仕様が変わると、ハッシュ値が変わる

業務の変更で、調理枠は予備の1食を残すことになった。比較する値だけが変わり、ID は変わらない。

変更の前 
{"c": {"target": "ST-2", "op": "ge",
       "value": "ARG-1"},
 "r": "TERM-19",
 "ex": {"before": {"ST-2": 0}, "args": {"ARG-1": 1}}}

ハッシュ値 42258840

→
変更の後 
{"c": {"target": "ST-2", "op": "ge",
       "value": {"call": "VO-5.OP-1", "args": ["ARG-1", 1]}},
 "r": "TERM-19",
 "ex": {"before": {"ST-2": 0}, "args": {"ARG-1": 1}}}

ハッシュ値 77d3e427

テストのソースに書いた 42258840 は、テストを書いたときの版の印になる。仕様の版が変わったのにテストが追いついていないことを、テストを読まずに文字列の比較だけで見つけられる。この条件を扱う拡張 4a（UC-1.EXT-2）のハッシュ値も、上流の1段として同時に変わる。
