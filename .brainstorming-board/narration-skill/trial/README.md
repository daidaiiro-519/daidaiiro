# 試作：原稿から音声付きスライド動画まで

ブレストボード「学習教材の音声を作るSkill」の5件の決着を、実際に通して検証した記録である。
2026-09-22に初回を実行し、2026-09-23に Skill 経由で再実行した。

## 何を検証したか

| 論点 | 検証した内容 | 結果 |
|---|---|---|
| 受け持ち範囲 | 原稿から、枚ごとの音声と尺までを出力する | `narration.out.json` に音声・時刻・長さが揃う |
| 実行の場所 | 結合の道具を手元へ導入せずに動画を作成する | コンテナの中の ffmpeg で `lesson.mp4` を出力した |
| 継ぎ目の形 | 枚のidだけで、画像と音声を突き合わせる | `slide-01` で `previews/slide-01.png` と対応した |
| 作り直しの単位 | キーが在る枚を、再合成せずに取り出す | 1回目は3枚とも合成し、2回目は3枚とも取り出した |
| 声と読み方 | ニューラルの日本語の声を比較する | Takumi ・ Kazuha ・ Tomoko を同じ文で合成し、Takumi を採用した |

## 判明した誤りと、その訂正

初回の動画で、映像と音声が1.821秒ずれた。原因は2つである。

1つ目は尺の定義である。出力の `durationMs` に、語と文の時刻の最後の印を使用していた。これは
最後の語が開始する時刻であり、音声の終わりではない。実測で3枚とも0.53〜0.58秒不足していた。
音声そのものから測る実装へ変更し、ffprobe の値と完全に一致することを確認した。

2つ目は結合の手順である。映像の長さを秒の途中で切らず、通しを無変換で繋いでいた。映像の長さを
尺で固定し、フレーム数を固定して、通しを再符号化する形へ変更した。

| 測定 | 初回 | 訂正後 |
|---|---|---|
| 映像の長さ | 79.680秒 | 96.133秒 |
| 音声の長さ | 77.859秒 | 96.148秒 |
| 差 | 1.821秒 | 0.015秒（30フレーム毎秒の1フレーム未満） |

合成の道具にも誤りが1件在った。値を複数取る引数が、後続の出力先の指定まで飲み込む。`=` で
1つの引数にまとめる形へ変更した。

## 置いてあるもの

| 場所 | 中身 |
|---|---|
| `narration.json` | 入力。発表原稿の1〜3枚目から作成した。枚のidと読み上げる文を持つ |
| `narration.out.json` | 出力。枚のidごとに、キー・音声・時刻・長さを持つ |
| `synth.sh` | 初回の合成の手順。Skill を起こす前に使用した |
| `mkmovie.sh` | 結合の手順。尺で映像を固定し、通しを再符号化する |
| `cache/` | キーの名前が付いた音声と時刻。名前がキーそのものである |
| `movie/lesson.mp4` | 結合した動画（96秒）。1〜3枚目を順に再生する |
| `voice-*.mp3` | 声の比較。同じ文（1枚目）を3つの声で合成した |

## 実行の方法

```
aws sso login --profile dev
AWS_PROFILE=dev AWS_REGION=ap-northeast-1 \
  python3 ../../../.claude/skills/narration/scripts/cli.py synth .
./mkmovie.sh
```
