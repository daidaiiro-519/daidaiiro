# 層を指す名前の解決の試作（論点13）

no-more-spaghetti の `inward` に、参照の名前空間と置き場所の名前空間をつなぐ対応表を足した試作である。
正本の Skill には適用していない。

| 置いてあるもの | 中身 |
|---|---|
| `names.patch` | 正本との差分。`parts/src/inward/names.rs` を新設し、`syntax.rs` ・ `mod.rs` ・ `declare/src/lib.rs` ・ `parts/Cargo.toml`（`toml` を追加）を変更する |
| `fixtures/` | 9言語の見本（最初の実測）。各言語で、内側の core ・ 外側の adapter ・ 層を宣言しない stray を持つ |
| `contract-fixtures/` | 契約の試験の見本（10言語）。`names.patch` の `declare/tests/contract.rs` が使う |
| `repositories.txt` | 測った実在のリポジトリと、その commit |
| `measure.py` | 実在のリポジトリを測った手順（経路は作業用の場所のまま） |

## 対応表の出どころ

| 言語 | 読む設定 |
|---|---|
| Rust | 各 `Cargo.toml` の `[package] name`、`[lib] name` ・ `path` |
| Go | 各 `go.mod` の `module` |
| TypeScript | 各 `package.json` の `name`、各 tsconfig の `paths` ・ `baseUrl` ・ `extends`（適用範囲はその tsconfig の下）、package の source root（`rootDir`、無ければ `src`） |
| Python | `pyproject.toml` の setuptools ・ hatch ・ poetry の書き方、無ければ `src` |
| Ruby | gemspec の `require_paths`、無ければ `lib` |
| C++ | `CMakeLists.txt` の `include_directories` ・ `target_include_directories`（生成式と変数を展開する）、`compile_commands.json` の `-I` |
| Java ・ Kotlin ・ C# ・ PHP | 不要（ソースが自分の名前を宣言する） |

**読めなかった設定は、層に属す点がその下に在るときだけ、判定できなかった範囲として報告する。**

## 契約

依存の向きの検査を、言語に依存しない4段と、7つの義務で定める。**言語に依存するのは、言語の表の契約の欄だけである。**

| 段 | Skill が決めること | 言語の表の欄 |
|---|---|---|
| 点 | ファイルごとに「どこに在るか」の名前を1つ持つ | `here`（宣言から取るか、置き場所から取るか） |
| 辺 | 読み込みごとに「何を指すか」の名前を1つ持つ | `imports` ・ `dynamic` |
| 正規化 | 点と辺を、1つの名前空間にそろえる | `bridge`（別名 ・ 探索路の出どころ。宣言で書く言語は無し） |
| 判定 | 層への所属は識別子の頭で、向きは並びで決める | なし |

| 義務 | 無い言語の扱い |
|---|---|
| 1. 正しい並びでは違反を出さない | ─ |
| 2. 作業領域の中を指すのに、どの層にも属さない参照を報告する | ─ |
| 3. 層を指すのに、その層に点が無い参照を報告する | 名前が記号まで含む言語は、確認できるのが点の単位までである |
| 4. 名前を実行時に決める読み込みを、抜け道として報告する | `dynamic` に理由を書いて外す |
| 5. 条件で分かれる読み込みは、すべての分岐を辺にする | `branches` に理由を書いて外す |
| 6. 逆の並びでは違反を出す | ─ |
| 7. 名前空間をつなぐ設定を読めなければ報告する | `bridge` が無い言語は対象外 |

`declare/tests/contract.rs` が、言語の表のすべての言語へ7つの義務を課す。**表に言語を足して見本を足さなければ、試験が失敗する。**
義務3の報告を消すと、10言語すべてで試験が失敗することを確認した。

| TypeScript ・ Python ・ Ruby ・ C++ ・ Go | 合格（検出しない） | 合格（検出しない） | 違反を検出 | 未解決を報告 |

### 実在のリポジトリ

層は、各リポジトリの package ・ crate ・ module の単位で宣言した。

| リポジトリ | 言語 | 辺 | 層どうしの辺（対応表なし → あり） | 層に属さない | 実在しない | 実行時に決まる | 名前を宣言しない |
|---|---|---|---|---|---|---|---|
| ripgrep | Rust | 404 | 73 → 152 | 0 | 0 | 0 | 0 |
| opentelemetry-go（go.mod 29件） | Go | 5,875 | 14 → 2,380 | 0 | 0 | 0 | 0 |
| trpc（monorepo） | TypeScript | 3,592 | 1,257 → 1,985 | 13 | 0 | 1 | 0 |
| black（src の配置） | Python | 710 | 9 → 118 | 0 | 0 | 0 | 0 |
| rubocop | Ruby | 451 | 288 → 345 | 0 | 0 | 8 | 0 |
| fmt | C++ | 168 | 22 → 37 | 0 | 0 | 0 | 0 |
| gson | Java | 2,683 | 1,060（対応表は不要） | 1 | 0 | 3 | 3 |

報告はすべて、実際に層の外を指す参照か、実際に名前を実行時に決める読み込みか、名前を宣言しない `module-info.java` だった。

既存の11のまとまり（Rust の Skill 10件と Go の見本）も、置き場所の名前だけで、正しい並びは合格し、逆の並びは検出した。
既存の試験48件と契約の試験2件は成功し、clippy の警告は0件だった。

## 実在のリポジトリで判明し、直した不具合

| 不具合 | 直し方 |
|---|---|
| 外の部品名 `vitest` が、根のファイル `vitest.config.ts` に一致した | 経路で書く言語は、区切りを `/` だけにした |
| 読み込みの文の拡張子（`vitest.shared.ts`）で、点と一致しなかった | 経路で書く言語は、両側の拡張子を外して比べた |
| package の subpath が、組み立ての出力（dist）を指した | package の source root の下も探すようにした（実在しない先が494件から2件へ） |
| 例ごとに別の包みを指す tsconfig の `paths` を、全体へ適用した | `paths` の適用範囲を、その tsconfig の下に限定した |
| 層の外の、生成物を指す tsconfig を読めないと報告した | 層に属す点がその設定の下に無ければ、報告しない |
| `require "rubocop/#{feature}/version"` を、静的な経路として扱った | 埋め込みを含む文字列は、図に現れない読み込みとして別に出す |
| `v1.43.0` ・ `types.gen` の末尾を、拡張子として外した | その言語のソースの拡張子だけを外す |
| `mod tests { use super::escape; }` の super を、ファイルの位置から数えた | 入れ子の mod から数える |
| 走査しない包み（vendor）の中のファイルを、実在しないと報告した | 経路で書く言語は、ファイルが在れば実在とする。走査しない包みを限界として申告する |
| `FeatureLoader.load(...)` を、Kernel の load と数えた | 受け手の無い呼び出しだけを読み込みとする |
| `autoload :名前, "経路"` の1つ目の記号を見て、抜け道と誤った | autoload は2つ目の引数で判定する |
| `"#{__dir__}/経路"` を、名前を実行時に決める読み込みと誤った | `__dir__` はそのファイルの包みなので、相対経路として辺にする |
