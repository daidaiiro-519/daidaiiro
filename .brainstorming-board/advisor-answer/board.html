Q1

advisor の回答のうち、何を全部の advisor で同じにし、何を advisor ごとに決めるか。完成イメージを、どの相談で、どんな頁で返すか

advisor の回答の頁は、結論で承認してほしいことを短くまとめ、確認する順にパネルへ案内する形にする。ux は完成イメージを具体の見本で返し、ほかの5つの advisor は承認のポイントを3〜5件だけ返す。全部の advisor で同じにするのは、Orchestrator が読む3つの欄と、頁の構造と表示の部品だけにする。
  • 共通の欄：結論 ・ 根拠（判断基準の id と引用）・ ai_cautions。Orchestrator が場面ごとに読む（論点2）のはこの3つである
  • 共通の欄「決まらないところ」は、頁では「相談した人が決めること」と書く
  • 頁の構造：結論のパネル → 確認の手順のパネル → 参照のまとまりの順に並べる。中身は完成イメージの「頁の構造」の表が持つ
  • 結論のパネル：結論の1文 ・ 確認してほしいこと ・ 決めてほしいこと ・ 次にすることを置き、最後に「次：①…」を目立たせて置く
  • 確認の手順のパネル：勧める順に置き、末尾に「次：…」と「結論に戻る」を置く。サイドバーに手順の番号と見た印を出す
  • 参照のまとまり：相談の前提 ・ 提案と根拠 ・ advisor が決めないことを置き、手順の番号を付けない
  • ux：完成イメージ（ユーザーフロー ・ 画面 ・ 受付メール ・ デザインシステム ・ エクスポート一式）を、合意した見本のまま返す
  • ux のデザインシステムは、この相談に適用した具体と汎用の資料の2つで出し、各項目を見本 → 使う場所 → トークンの名前と値の順に並べる
  • ほかの5つの advisor：仕様を正しく書けるかを決める承認のポイントを3〜5件返す。1つの手順に1つのポイントを置く
  • 1つのポイントのパネル：最小の図 → 「このポイント」1行 → 「これで決まること」1〜3項目 → 閉じた根拠の順にし、ほかは置かない
  • 成果物の全文は頁に出さず、結論の「次の工程で書くもの」に名前だけ書く。承認したポイントから、別の作業が定めた形式で書く
  • 根拠：1件ずつ開閉でき、閉じると id と原典の正式な名前、開くと引用 ・ 「ここでは」・ 出典のリンクが出る
  • ヘルプアイコン（ⓘ）：分野の用語に、パネルごとに最初の1か所だけ付け、data-help-src を持たせる
  • ヘルプアイコンの中は、ふだん使う言葉の説明を先に出し、原典の全文を「原文を見る」に置く
  • 原典の語が分かりにくいとき（書籍の比喩など）は、こちらの文をふだん使う語で書き、引用は削らず全文を「原文を見る」に置く
  • 誤解される略記を使わない。In / Out は「システムが担当すること」「システムの外」と書く
  • 各手順のパネルは、見える形（ストーリーボード ・ ワイヤーフレーム ・ 図 ・ 見本）を先頭に置き、文はその説明にする
  • 共通の表示の部品：カード ・ 表 ・ 図 ・ 直す前と直したあとの組 ・ コピーのボタンつきのファイルのタブ ・ 見本の種類のバッジ ・ 開閉する根拠 ・ ヘルプアイコン。雛形の描画の型が持つ
  • advisor ごと：完成イメージか承認のポイントで何を見せるかを SKILL.md に書く。その advisor だけが必要とする部品は、その advisor が持つ
  • 完成イメージと承認のポイントは、設計相談と、相談者の案を直す判断相談で必ず返す。概念相談では返さない
  • 作る順：雛形を先に直し、ux を UI の見本どおりに作る。ほかの5つの advisor は、ACDR 3 でまとめて入れる（論点4）

ux-advisor を雛形より先に直すux の refs.rs と頁の型は雛形の複製である。先に直すと、雛形へ戻す差分が別に出る
advisor ごとに頁の描画を書く論点1で、頁の構造と表示の部品は雛形が持つと決めた。描画が6つに分かれ、同じ部品の見た目がずれる
見本との比較を、利用者に見せたあとにする見本との違いを利用者に探させることになる。見せる前に、パネルごとに撮って並べる
ヘルプアイコンの説明を、AI が回答ごとに書く同じ用語の説明が回答ごとに変わる。主アクターのような用語の意味は回答によらず変わらないので、判断基準に1回だけ書いて承認を得る
