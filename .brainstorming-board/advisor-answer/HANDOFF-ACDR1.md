## ACDR 1 に入れるもの

| 項目 | 中身 |
|---|---|
| answer.schema | 承認のポイント ・ これで決まること ・ 次の工程で書くもの ・ 相談した人が決めること（共通の欄 undecided の頁での名前）・ 用語の参照 |
| 用語の参照 | 判断基準の id と用語の組で指す（1件の判断基準に用語が2つ以上あるため。例：開始基準と終了基準）※利用者の承認待ち |
| criteria.schema | 用語ごとの「ふだんの言葉の説明」の欄。description に何を書くかを書く |
| ヘルプアイコン | 説明は変わらないデータ。欄の名前は answer.schema の description から、用語は criteria.json から。説明を先に出し、原典の全文は「原文を見る」に置く。x-prompt は AI だけが読み、頁に出さない |
| 頁の部品 | 番号と確認済みの印が付くサイドバー ・ 次の手順の案内と「結論に戻る」・ 開閉する根拠と「原文を見る」・ ヘルプアイコン ・ カードと比較 ・ 狭い幅で積み重ねる表 |
| ux 以外の advisor | 承認のポイントを3〜5件だけ返す。手順1つ＝ポイント1つ：最小の絵 →「このポイント」→「これで決まること」→ 閉じた根拠 |

## qa-advisor が見つけた、論点4 に足りない点（利用者の判断待ち）

| 点 | 提案 |
|---|---|
| refs.rs.tmpl と view.* は Rust の15の Skill が写している（advisor 以外に acdr ・ design-svg ・ slide-deck など） | ACDR 1 の中で15すべてに写し直す。新しい頁の形は、回答が新しい欄を持つときだけ描く。変える前後で15の頁を保存して比べ、style の中以外に差が無いことを確かめる |
| 見本のヘルプアイコンの形が揃っていない（合意した形は meta-thinking の v2 だけ。usecase は引用を直に、qa は引用が先） | ACDR 1 の前に usecase と qa の見本を合意した形に直す |

## テスト方針（qa-advisor の要点）

| レベル | 確かめ方 |
|---|---|
| コンポーネント | 新しい処理ごとにテストと契約のケース |
| コンポーネント統合 | 15の Skill に check --cases 1 |
| システム | 見本と比べる。1段目 DOM の構造、2段目 画素。10の状態 × 1200 ・ 390 × ライト ・ ダーク。図のように雛形が描き方を持たない範囲だけを隠し、一覧を ACDR に書く。撮るたびに新しいブラウザのコンテキストで localStorage を空にする |
| 受け入れ | 利用者の承認 |

| 境界値 | 検出 | 通る |
|---|---|---|
| 承認のポイントの数 | 2件 ・ 6件 | 3件 ・ 5件 |
| 「これで決まること」の数 | 0件 ・ 4件 | 1件 ・ 3件 |
| 説明の長さ | 0文字 | 1文字 |

## 利用者が繰り返し求めたこと（実装と見せ方で守る）

| 決まり | 中身 |
|---|---|
| UI の合意が先 | 実装の前に見本で合意を取る。見本と違うものを「違いの一覧付き」で出さない |
| 語彙 | 分野で通っている名前を使う。描写の和語（段 ・ 面 ・ 地 ・ 当てる など）・作った語・比喩を使わない |
| 構造 | 散文にせず、表と意味ごとの箇条書き。見出しの順に中の要素を並べる |
| 情報を落とさない | 見せ方を変えるとき、根拠 ・ 引用 ・ 説明を削らない。引用は全文で |
| 見せる前に確かめる | 1200 と 390、ライトとダークで撮って目視してから出す |
