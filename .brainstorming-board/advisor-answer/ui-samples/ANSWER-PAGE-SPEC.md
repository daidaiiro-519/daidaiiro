# advisor の回答の頁の見本を作る担当への指示

## 何を作るか

- ux-advisor の回答の見本 `ux-answer-sim.html` と同じ構造で、ほかの advisor の回答の見本を1枚ずつ作る。
- `ux-answer-sim.html` が、利用者の合意した UI である。最初に全文を読む。CSS ・ JS ・ 部品をそのまま流用してよい。

## 頁の構造（合意済み。崩さない）

| 部分 | 中身 |
|---|---|
| 結論のパネル | 結論1文<br>確認してほしいこと：見る順番のカード。各カードに、パネルへのリンク・判断すること1行・量を持たせる<br>決めてほしいこと：候補と、決める場所へのリンク<br>次にすること：短く<br>最後に目立つ「次：①…」 |
| 確認の手順のパネル | 完成イメージを見る順に並べる<br>各パネルは図・表・見本から始まり、文は図の説明だけにする<br>最後に「次：…」と理由1行、控えめな「結論に戻る」を置く |
| サイドバー | 結論 → 確認の手順（番号付き。見たら ✓） → 参照（番号なし） |
| 参照 | 相談の前提（項目と値の表）と、提案と根拠（列は 対象・提案・効果・根拠）。advisor が決めない理由の表も、ここに置く |
| 根拠 | 1件ずつ `<details>` にする<br>閉じた状態：id と判断基準の題<br>開いた状態：判断基準の文の引用・「ここでは」1行・出典 |

## 書き方の決まり

| 決まり | 中身 |
|---|---|
| 散文を構造にする | 表と、意味ごとの箇条書きにする。1文は短く。要点は落とさない |
| 並びの順 | 見出しの順に、中の要素を並べる |
| 重複させない | 同じ中身を2つのパネルに置かない |
| 語彙 | 分野で通っている名前を使う。作った語 ・ 和語への言い換え ・ 比喩を使わない<br>例：地 → 背景色、部品 → コンポーネント、前置き → 相談の前提<br>使わない語：タッチポイント・接点・前置き・決まらないところ<br>`.doc-writing/retired-words.json` の語も使わない |
| 背景に直接文字を置かない | 白い枠の面の中に置く。配色は今の頁と同じにする |

## 根拠の出どころ

- 判断基準の id は、その advisor の `.claude/skills/<advisor>-advisor/references/criteria.json` に実在するものだけを使う。platform は `grades.json` も使ってよい。
- 引用は、その判断基準の `summary` か本文の文字列をそのまま使う。言い換えない。
- 出典欄には、判断基準の id と原典名を書く。原典名は SKILL.md の冒頭にある。

## 図

- 完成イメージの図は、ギャラリーの断片 `gallery/frag-<advisor>.html` にある resolve 済みの SVG を使ってよい。
- 新しく描くときの手順：
  1. `.claude/skills/design-svg/references/exemplars.json` から近いテンプレートを選ぶ
  2. class の形で書く
  3. `.claude/skills/design-svg/bin/design-svg resolve` を通す
- 検査の結果は0件にする。ラベルは1行に収め、矢印は箱で終わらせる。

## 確かめてから返す

1. 結論と、手順のパネル1つを、幅1200と390、ライトモードとダークモードで撮って見る。撮るのはヘッドレスの shell か Playwright。
2. Playwright で、頁の中のリンクを全部押し、正しいパネルが開くかを確かめる。
3. ゲート1（`.claude/skills/doc-writing-skills/bin/doc-writing-skills check <file>`）を0件にする。
4. git の状態を変えるコマンドは使わない。

## v2 の決まり（usecase-answer-sim-v2.html で合意済み。ux 以外の advisor に適用する）

| 決まり | 中身 |
|---|---|
| 返すのは承認のポイント | 仕様を正しく書けるかを決めるポイントを 3〜5件だけ出す。成果物の全文（本文 ・ 計画書 ・ 全部の表）は出さない |
| 1つの手順＝1つのポイント | 判断に必要な最小の絵（図 ・ 小さな比較 ・ 2〜3行の表まで）→「このポイント」1行 →「これで決まること」1〜3項目 → 根拠（閉じた details）。ほかは置かない |
| 外したもの | 結論の「次の工程で書くもの」に名前だけ書く |
| デザインと図 | v1 の土台と図はそのまま使う。変えるのは粒度と、文字の多い表の見せ方だけ |
| 表 | 列を少なく、要の列を先頭に置く。中身が構造ならカード ・ 図 ・ 一覧にする |
| 用語の説明 | 分野の外の人が知らない語に ⓘ を付ける。パネルごとに最初の1か所だけ。説明を先に出し、原典の全文は「原文を見る」に置く。`data-help-src="criteria:<id>"` を持たせる。語と ⓘ を1つの span にまとめ、折り返さない。実装は meta-thinking-answer-sim-v2.html を流用する（usecase-answer-sim-v2.html は、説明か引用の1つだけを出す前の形） |
| 誤解される略記 | In / Out のような英語の略記を使わない（例：「システムが受け持つこと」「システムの外」） |
