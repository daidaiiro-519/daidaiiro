構造を、何を基準に決めるのか ── 何を分け、何に持たせるのか

C手法はポートとアダプタを採る。内側は、変更理由が同じものをまとめ、違うものを分ける。
この答えを導いたもの（11件）
  • 手法はポートとアダプタである
    内側と外側に分け、境界の定義は内側が持つ。要素が2つなので、検査も依存の向き1本で済む
  • ポートとアダプタが防ぐのは1種類だけ
    外部の技術が内側へ染み出すこと。内側の腐敗は防がない
    防がないもの（3件）
    • 内側に3000行の1関数があっても成立する
      分け方は基準の側が決める
    • 実装が1つしかないインターフェースが増える
      作る条件を決めないと量産する
    • 1つの関数の中で責務を混ぜる ・ 分けずにフラグ引数を足す
      境界の外で起きる
  • ポートを作る条件は2つで、どちらかを満たすときだけ作る
    実装が2つ以上あり得るか、テストで差し替えるか
  • クリーン ・ オニオン ・ レイヤードは選ばない
    同じ目的の別表現だと原典が書いている。流派を選ぶ議論をしない
  • DDD の語彙は、業務に状態と規則があるときだけ足す
    エンティティ ・ 値 ・ 集約。無い対象には足さない
  • 分ける単位は、変更理由である
    原典がそう書いている
  • 名前は、その単位に付ける
    単位が決まってから名前が決まる。逆ではない
  • 層は、依存してよい先で決まる
    層名を先に決めて、そこへ概念を割り当てない
  • 仕様は決めない
    何を作るか ・ どう振る舞うかは利用者が持つ。こちらが決めるのは分け方だけである
  • 書くのは、分け方に迷うときだけ
    1行足すだけなら書かない
  • 採用したら、採用したと書く
    暗黙の前提にしない
この答えの完成イメージ ── 実例

例　仕様「ブレストの回答を受け取って、1件ずつ保存する。論点1件につき1つ。直前と同じ内容は保存しない」

仕様のどこが変わると、どこが動くか。これが同じものを1つにする。
この仕様が変わると動く単位
回答の項目が増える（例：確信度）回答 だけ受け取りアダプタも蓄積先も動かない
重複の判定を変える（直前ではなく全件と比べる）重複の判定 だけ保存の仕方は動かない
受け取り方を変える（HTTP からファイル監視へ）受け取りアダプタ だけ内側は動かない
保存先を変える（ファイルからデータベースへ）蓄積先 だけ内側は動かない
内側と外側に分け、境界（ポート）は内側が定義する。
内か外か変更理由依存してよい先
回答内回答の項目が変わるとき無し
重複の判定内判定の規則が変わるとき回答
回答を受け取る内手順が変わるとき回答 ・ 重複の判定 ・ 蓄積ポート
蓄積ポート（ポート）内保存に何を渡すかが変わるとき回答
受け取りアダプタ外受け取り方が変わるとき回答を受け取る
蓄積先（アダプタ）外保存先が変わるとき蓄積ポートを実装する

蓄積ポートが内側に在るので、保存先を変えても内側は1行も動かない。外側から内側への一方向になっている ── 層はその結果である。

仕様が決めたのは「論点1件につき1つ」と「直前と同じ内容は保存しない」である。こちらが決めたのは、それをどう分けたかだけである。

この例でポートは1つだけである。蓄積ポートは、テストで差し替えるので作る。受け取りアダプタは外側のアダプタで、内側が呼ばないのでポートを作らない。

@dataclass(frozen=True)
class 回答:
    論点: int
    諾否: str          # approve / return / skip
    理由: str = ""

@dataclass(frozen=True)
class 送信:
    回答群: tuple[回答, ...]
    def __post_init__(self):
        番号 = [a.論点 for a in self.回答群]
        if len(番号) != len(set(番号)):
            raise ValueError("論点1件につき回答は1つである")

def 重複か(前: 送信 | None, いま: 送信) -> bool:
    return 前 is not None and 前.回答群 == いま.回答群

class 蓄積ポート(Protocol):        # 内側が定義する
    def 直前(self) -> 送信 | None: ...
    def 足す(self, s: 送信) -> None: ...

内側　③手順

# usecase.py ── 外側の道具は、ポートを通してしか触らない

def 回答を受け取る(ポート: 蓄積ポート, s: 送信) -> int:
