# 規則があるときと、無いときの違い ── 実測

同じ仕様（`SPEC.md`）から2つ作り、**同じ仕様変更**（保存先をファイルから SQLite へ）を
両方に当てて測った。2026-09-23。

## 作ったもの

| | 規則なし版 `a-no-rules/` | 規則あり版 `b-rules/` |
|---|---|---|
| ファイル | 1（`serve.py` 47行） | 5（内側2 ・ 外側2 ・ 組み立て1。118行） |
| 試験 | 1件（HTTP を立てる） | 2件（内側 ・ 外側。HTTP を立てない） |
| 最初の行数 | **少ない** | 2.5倍 |

**規則あり版のほうが、最初は2.5倍書く。** これが費用である。

## 仕様変更を当てた結果

| | 触ったファイル | 足した行 | **消した行** | 試験 |
|---|---|---|---|---|
| 規則なし版 | 1 | 17 | **10** | **隔離が壊れた**（下記） |
| 規則あり版 | 2（新規1 ・ 変更1） | 30 | **2** | 9件とも無傷 |

**消した行が、既存の動く実装を書き換えた量である。**

- 規則なし版は、**重複の判定を書き直した** ── ファイルの最終行を読む処理が、SQL の問い合わせに変わった。
  判定の規則は1文字も変わっていないのに、判定のコードが動いた
- 規則あり版は、`main.py` の2行（どの蓄積先を渡すか）だけが変わった。判定も手順も1行も動いていない

## 試験で起きたこと

**規則なし版の試験は、通った。しかし壊れていた。**

試験は `serve.OUT`（ファイルの置き場）を一時ディレクトリへ差し替えていた。保存先が SQLite に
変わって `OUT` が使われなくなったので、差し替えが効かなくなり、**リポジトリの中に `answers.db` が
2行入った状態で「3件すべて通った」と出た**。

規則あり版は、内側の試験が偽物の蓄積先を渡す形なので、保存先が変わっても差し替えが効いたままである。

## 分かったこと

| | |
|---|---|
| 規則が効くところ | **既存の実装を書き換える量**（10行 → 2行）と、**試験の隔離が保たれること** |
| 規則の費用 | 最初に書く量が2.5倍。ファイルが1つから5つへ増える |
| 効かないところ | 行数の合計は増える。小さいまま終わる対象では、費用だけが残る |
