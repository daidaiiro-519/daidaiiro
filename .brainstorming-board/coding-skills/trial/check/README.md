# `check` の試作 ── 記録のコマンドを実行し、終了コードで判定する

`cli.py <根> <記録> [--json]`。標準ライブラリだけで動く（`subprocess` ・ `json`）。

## この試作が持たないもの

- **道具の名前** ── 実行するものは記録から来る。言語ごとの違いは記録が持つ
- **出力の解析** ── 検出は道具の仕事で、意味の解釈は読み手が実施する

## 判定は3つ

| 判定 | 条件 |
|---|---|
| 合格 | 終了コードが0 |
| 不合格 | 終了コードが非0。出力を道具のまま添える |
| 実行しない | 道具が見つからない ・ 検証方法に道具が無い ・ 制限時間で終わらない |

「実行しない」は合格にも不合格にもしない ── 合格にすると、道具が消えた瞬間に全部が通る。

## 動かした結果（2026-09-23）

規則3件（層の向き ・ 内側の試験 ・ 整形）を `trial/sim/b-rules` へ当てた。

| 状態 | 結果 |
|---|---|
| 違反なし | 合格2 ／ 不合格0 ／ 実行せず1（`gofmt` がこの環境に無い） |
| 違反あり（`domain` から `adapters` を参照） | **不合格2** ── 層の向きと、内側の試験の両方 |

**1つの違反が、2つの規則で出た。** 依存の向きの検査が捕まえ、試験は循環 import で落ちた。
どちらも出力は道具のまま渡している。

## 殻を経由しない

道具は配列のまま `subprocess.run` へ渡す。文字列1本にすると、`./...` の展開が実行する殻に依存する。

## 残る費用

記録に `true` と書けば合格になる。**コマンドが本当に検査しているかは、この試作では確認できない。**
