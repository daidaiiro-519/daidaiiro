Q1

Skill の型は何のためにあり、作られた Skill に何を必ず求めるか

型は、Claude が正しいときに Skill を呼び、手順どおりに動けることを、書いたその場で確かめるためにある。SKILL.md は Claude が読む正本のまま手で書き、skills-creator の check が先頭の欄と節を読み取って、型のスキーマで検査する。
  • SKILL.md を読むのは Claude で、人は書いてレビューする。直す場所は、Claude が読むその SKILL.md である
  • 型は JSON Schema（skills-creator/skill@v1）で持ち、欄ごとに誰が読むための条件か（Claude か、エンジンと skills-creator か）を書く
  • どちらの読み手にもつながらない欄は、型に入れない。手順や決まりの文章そのものも、型に入れない
  • Claude のための条件：先頭の欄は name と description が必須で、claude.ai ・ API でも読める6つの欄だけを許す
  • Claude のための条件：name は64文字までの小文字 ・ 数字 ・ ハイフンでフォルダ名と同じ、description は1,024文字まで、SKILL.md は500行未満
  • Claude のための条件：6つの節（目的 ・ 役割 ・ 入力の想定 ・ 実行手順 ・ 出力形式 ・ ガードレール）をこの順に持つ
  • エンジンと skills-creator のための条件：tool.json に、使う abstract の版を書く
  • SKILL.md を読み取って JSON にする処理は、提供側の skills-creator の check が持つ。作られた Skill はコードを持たない
  • 基盤のコンセプトは、書いたその場で検証するという目的の高さで当てはめ、JSON を正本にするという手段の高さでは当てはめない
この答えの完成イメージ ── 図 ・ コード

いまの17の SKILL.md を数えた結果。型をスキーマで持って検査すれば、上の3つは書いたその場で見つかる。いまの検査は、どれも見つけていない。

// 型のスキーマ skills-creator/skill@v1 の見本（抜粋）。欄ごとに、誰が読むための条件かを持つ
{"$id": "skills-creator/skill@v1",
 "properties": {
  "frontmatter": {
   "x-reader": "Claude",
   "required": ["name", "description"],
   "propertyNames": {"enum": ["name", "description", "license", "compatibility", "metadata", "allowed-tools"]},
   "properties": {
    "name":        {"pattern": "^[a-z0-9]+(-[a-z0-9]+)*$", "maxLength": 64},
    "description": {"minLength": 1, "maxLength": 1024}}},
  "lines":    {"x-reader": "Claude", "maximum": 499},
  "sections": {"x-reader": "Claude",
               "description": "目的 ・ 役割 ・ 入力の想定 ・ 実行手順 ・ 出力形式 ・ ガードレール の見出しが、この順にある"},
  "tool":     {"x-reader": "エンジンと skills-creator",
               "required": ["abstract"],
               "description": "使う abstract の版（schema-driven/abstract@v1）"}}}

// いまの acdr に check を当てたときの出力の見本
$ skills-creator check .claude/skills/acdr
NG  /frontmatter：SKILL.md の1行目が --- でない。name と description が無い
    → Claude Code はフォルダ名と1行目で代わりに読むが、claude.ai ・ API では読まれない
NG  /tool/abstract：使う abstract の版が無い

採らなかった案（3件）
案採らなかった理由
A：SKILL.md を手で書き、skills-creator が見出しを独自に検査する検査が skills-creator の中に閉じ、型の版と検査の中身の対応を機械で確かめられない
B：skill.json を正本にし、SKILL.md をエンジンが作るClaude が読む SKILL.md が作り出された写しになり、観察して直す往復が遠くなる。エンジンに Markdown を書き出す機能も増える。手段の目的化にあたる
Claude Code にしかない欄も型で許すclaude.ai ・ API に載せるとエラーになる。いまその欄を使っているのは1件だけで、その Skill の型の外の設定として扱える
