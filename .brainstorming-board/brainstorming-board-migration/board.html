Q1

承認する人はブレストボードで何を判断し、そのために何をどの順で見る必要があるか

ボードは、AI が作ったもののうち自分の意図からずれた所だけを早く見つけて正し、ほかは任せて進めるためにある。承認する人が論点ごとに答える問いは「この答えを、このまま進めてよいか」の1つにし、見る順を画面の並びが決める。
  • 見る順は、現在地 → 問いと答えの1文 → この回で変わったところ → 完成イメージ → 置いた前提 → 確かめてほしい箇所 → 裏づけ → 回答にする
  • 置いた前提を、根拠や採らなかった案より先に見せる
  • 裏づけ（根拠と採らなかった案）は名前だけを見せ、中身は開いて読む
  • 回答の主な操作は、ずれを自由文で返すことにする。進めてよいときは押すだけで終わる
  • UI ・ UX ・ デザインシステムは、完成イメージの表の11の基準を満たすように決める
  • SKILL.md の「この決定を覆すか」は、「この答えを、このまま進めてよいか」に直す

Q2

判断の目的を満たすために、ボードはどんな画面の流れ ・ 情報の並び ・ 操作を提供するか

ボードを開くと、いま答える論点が最初から開いている。論点の中は見る順に1列で並べ、閉じておくのは答えの詳しい決まりと裏づけだけにする。
  • 現在地は1行のチップ（決着 ・ いま答える ・ まだ）と「この回で答える論点：n件」にし、論点ごとのタブは並べない
  • 意味のまとまり（完成イメージ ・ 置いた前提 ・ 確かめてほしい箇所 ・ 裏づけ ・ 回答）は、それぞれ同じ形の白い枠に入れ、見出しを枠の中に置く。枠はページの背景の上に直に並べ、面を重ねない。答えは色の付いた枠、この回で変わったところは1行の知らせの帯にする
  • 答えは1文だけを見せ、下位の決定は「答えの詳しい決まり（n件）」を開いて読む
  • この回で変わったところは、件数と行き先を1行で出す。押すとその文へ移って光り、変わった文の中に前の回の文と変えた理由が出る
  • 置いた前提は、完成イメージのすぐ後に番号付きで並べる
  • 確かめてほしい箇所は3件までにし、「移る先 ── 何を確かめてほしいか」の1行で書く。押すとその箇所へ移って光る
  • 裏づけは主張ごとに束ね、各主張の根拠は2件まで見せ、残りは「ほかの根拠 n件」で開く。見出しに主張 ・ 根拠 ・ 採らなかった案の数を出す
  • 採らなかった案は、表にせず「案 ── 採らなかった理由」の1行にする
  • 知らないかもしれない語は、ページで最初に出るところにだけ ⓘ を付ける。押すと説明が出て、Esc で閉じる
  • 回答は「このまま進める」「差し戻す」の2つにする。差し戻すを選ぶと「どこが違うか」の欄が出て、空のままでは送れない。書き足しは任意である
  • 送ったら、次にすること（チャットで一言もらう）を画面が言い切る
  • 完成イメージのタブ名は図 ・ 画面 ・ コードにし、題の上は「第n回」にする
