Q1

承認する人はブレストボードで何を判断し、そのために何をどの順で見る必要があるか

ボードは、AI が作ったもののうち自分の意図からずれた所だけを早く見つけて正し、ほかは任せて進めるためにある。承認する人が論点ごとに答える問いは「この答えを、このまま進めてよいか」の1つにし、見る順を画面の並びが決める。
  • 見る順は、現在地 → 問いと答えの1文 → この回で変わったところ → 完成イメージ → 置いた前提 → 確かめてほしい箇所 → 裏づけ → 回答にする
  • 置いた前提を、根拠や採らなかった案より先に見せる
  • 裏づけ（根拠と採らなかった案）は名前だけを見せ、中身は開いて読む
  • 回答の主な操作は、ずれを自由文で返すことにする。進めてよいときは押すだけで終わる
  • UI ・ UX ・ デザインシステムは、完成イメージの表の11の基準を満たすように決める
  • SKILL.md の「この決定を覆すか」は、「この答えを、このまま進めてよいか」に直す
この答えの完成イメージ ── 図 ・ UI

承認する人が見る順と、それぞれが応えるもの。

案採らなかった理由
目的を「この決定を覆すか」に置く覆すかはレビューと同じ手段で、その先の目的が見えない。差し戻しが承認より多く、どれも自由文である記録と合わない
部品と見た目から決める（前の答え）見た目が変わる理由を、目的から言えなかった。差し戻された
目的を抽象のまま利用者に聞く仮説の目的と、それから導いた見る順の具体を見せないと、承認する人が判断できない
