Q1

ブレストボードのページを基盤のカタログの部品だけで描くとき、承認する人が「この決定を覆すか」を判断する体験をどう保つか

ボードはページテンプレートでカタログの部品を並べて描き、先頭の現在地に論点の一覧 ・ いま見る論点 ・ この回で変わったところを置く。変わった欄は mark で示し、その記録は回を進めるツールが論点の中に書く。
  • 論点はタブにし、問い ・ 答え ・ 完成イメージ（開いたまま）・ 根拠と採らなかった案（開閉）・ 回答欄の順に並べる
  • 状態（決着 ・ いま見る ・ 待ち）と完成イメージの種類（図 ・ UI ・ コード）の語は、ボードのスキーマの x-view に言い換えの表で持ち、ページは view() で引く
  • 前の回との差分は、回を進めるツールが論点ごとの changes に書く。ページは描くだけで、比べない
  • 変わったところの一覧は現在地に並べ、押すとその印へ移る。画面の端の引き出しは作らない
  • 変わった欄の印は、カタログの mark の決まりどおり初めから開いている。SKILL.md の「押すと開く」をこれに合わせて直す
  • 回答欄は回答待ちの論点だけに置き、判定（承認する ・ 差し戻す ・ まだ答えない）と、理由 ・ 書き足しの自由文の欄を持つ。値は回答の形の approved ・ returned ・ unanswered にする
  • 答えの名前は「論点の id.欄」にし、送る部品はページの末尾に1つだけ置く
  • 理由のボタンは足さない。差し戻しの理由がたまって同じ理由が繰り返されたら、カタログへ足す相談をする
  • 自前のデザイン（parts.html ・ board.css ・ board.js ・ design-system.json と部品 board）は消す
この答えの完成イメージ ── 図 ・ UI ・ コード
