論点の一覧

SKILL.md 以外の中身（references。knowledge もここへ統合する）は、JSON Schema と、それに従う JSON を正本にする。人が見るときは、JSON から導出した HTML で確認する。構造があらかじめ分離されていれば、読み手は構造を解釈せずに内容に集中できる ── 人にとっても AI にとっても同じである。この方針を、道具を持つ Skill と、アドバイザー系 ・ skill-router ・ memory-cultivator を含む16の Skill へ適用する形を決める。

SKILL.md 以外の中身を、どの単位の JSON Schema と JSON で持つか

Q2

JSON から HTML への描画を、どこが持つか

JSON から HTML への描画は、契約が1つだけ持つ。描画は、スキーマと JSON に、トークン（見た目の値）と型（HTML の雛形）を合わせて HTML を組む。既定の型は雛形が持ち、独自の見た目が必要な Skill は型とトークンを差し替える。Skill ごとに描画のコードを書かない
  • 描画は契約が1つだけ持つ ── 入力はスキーマ ・ JSON ・ トークン ・ 型の4つ
  • 見た目はトークンが持つ ── 色と寸法を直書きしない
  • 独自の見た目は、型とトークンの差し替えで表す ── acdr ・ ブレストボードは、すでに型とトークンから組んでいる。描画のコードを Skill ごとに書かない
  • 既定の型 ── オブジェクトは節、同じ形の配列は表、文字列の配列は一覧、長い文字列は段落。見出しはスキーマの title、説明は description

Q4

モデルが references の中身を読むとき、ファイルを直接読むか、Skill の道具で必要な部分だけを取り出すか

references を持つ Skill は、すべて道具を持つ。道具は references の種類と項目を指定して、必要な部分だけの JSON を返す（get）。スキーマで検査し（validate）、HTML に描画する（view）。この3つの動詞は Skill ごとに書かず、契約の雛形が持つ
  • get ── 種類と項目の id を指定し、その1件の JSON だけを返す。モデルはファイル全体を読まない

  • view ── references の JSON を HTML に描画する（論点2で置き場所を決める）
  • 3つの動詞は契約の雛形が持つ ── references しか持たない Skill（アドバイザー系など）は、固有のコードを書かずに道具を持てる
