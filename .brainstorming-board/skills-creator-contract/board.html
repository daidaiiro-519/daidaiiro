Q1

どの言語で書いた Skill も満たすべき契約として、skills-creator は何を正本に持つか

ほかの4つの論点の前提になる論点。契約に何を入れるかで、検証の方法もテンプレートの形も決まる
C

契約は次の3つで構成する。どれも言語に依存しない

  1. ディレクトリ構成
    置くファイル（SKILL.md ・ references ・ tool.json ・ mcp.json ・ 実装 ・ テスト）
  2. CLI のインターフェース
    サブコマンド ・ 引数 ・ 終了コード ・ --json の出力形式 ・ オプションの扱い。tool.json には実行 ・ ビルド ・ テスト ・ フォーマットのコマンドを書く
  3. テストケース
    入力（references と回答）と呼び出しに対する期待値（終了コード ・ JSON ・ HTML）。共通ツールの振る舞いはテストケースで決まる

実装は Rust のリファレンス実装を1組だけ持つ。リファレンス実装は契約ではなく、テストケースに合格する実装の1つである

Rust 以外の言語で Skill を作るときは、AI がリファレンス実装を移植し、テストケースに合格したら完成とする。移植したコードは skills-creator に保存しない

層の構成（4層と依存の向き）は ACDR 0059 のとおり契約に入れない。リファレンス実装が推奨の形として示す
