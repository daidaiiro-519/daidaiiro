Q3

Rust のリファレンス実装とテストケースを、どの形で持つか

リファレンス実装は今の Rust のテンプレート1組を sample/rust/ へ移す。verify がそこから Skill を生成し、ビルドしてテストケースを実行する。テストケースは1件1ファイルで、リファレンス実装のテスト1件ごとに同名のテストケースを置く。比較から除外する箇所は JSON Pointer で書く。リファレンス実装から読み取りにくい前提は assumptions.json に書く
  • リファレンス実装は、今の Rust のテンプレート1組（profiles/rust/）を sample/rust/ へ移したもの。プレースホルダー（{{接頭辞}} など）は今のまま残す
  • リファレンス実装が動くことは verify で確認する。テンプレートから Skill を生成し、ビルドしてテストを実行し、テストケースを実行する（今の verify と同じ流れ）
  • テストケースは contract/cases/ に1件1ファイルで置く。項目は、説明 ・ 対応するテストの名前 ・ 呼び出し ・ 期待値（終了コードと JSON）・ 比較から除外するパス（ignore）

  • 比較から除外する箇所（スキーマ検査のエラー文など）は、ignore に JSON Pointer で書く
  • リファレンス実装から読み取りにくい前提（JSON のキー順 ・ 空白の定義 ・ 行の分割 ・ 上書き時の位置など）は、contract/assumptions.json に1件ずつ、ルール ・ 理由 ・ 確認するテストケースで書く

Q4

get ・ validate ・ view ・ import を、各 Skill に複製するか、共通の1つにするか

各 Skill に複製する。Rust の Skill はリファレンス実装をそのまま複製し、ほかの言語の Skill は AI が移植したコードを持つ。ずれは、Rust の Skill では check がリファレンス実装との差分で、どの言語でもテストケースで検出する
  • 共通ツールは、今と同じく各 Skill が自分のコードとして持つ。Skill は単体で動く
  • Rust の Skill は、リファレンス実装の refs をそのまま複製する。リファレンス実装を直したら、複製し直す
  • ほかの言語の Skill は、AI が移植したコードを持つ。リファレンス実装を直したら、テストケースに不合格になった Skill だけを直す
  • ずれの検出は2段である。Rust の Skill は check がリファレンス実装との差分を検出する（今と同じ）。どの言語の Skill もテストケースが振る舞いの差を検出する
