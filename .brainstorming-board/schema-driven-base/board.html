論点の一覧

スキーマ駆動の道具を、どの concrete にも使える抽象の基盤として形を決める。ユースケース駆動は、その上に載る concrete の1つである。

  1. 基盤が知る形の線引きが、concrete の契約 ・ 射影と変換 ・ 配り方のすべての前提になる

残り 3 件は、上流が決まるまで動く。回答欄は持たない。

Q1

基盤は、宣言のどこまでの形を知るか

この論点が、基盤が concrete の語を含めずに済むかを決める。論点2〜4は、この線を前提にする
B基盤の宣言は4つの欄だけを持つ。kind（種類の名前、文字列のまま）・ id ・ name ・ body（基盤は形を見ない）。concrete が申告する3つ。
  • 種類ごとの JSON Schema
    body の形と検査。操作 ・ 条件 ・ シナリオのような構造は、ここにだけ現れる
  • ID を持つ節の在りか
    body の中のどこに、テストや外の識別子と結ぶ節があるかを JSONPath で書く
  • 参照の在りか
    body の中のどこが、どの種類の宣言の ID を指すかを JSONPath で書く。多重度もここに書く

基盤は、この申告だけを読んで、節の一覧 ・ 参照と逆参照 ・ 引き算を行う。試作の基盤が固定していた rules ・ ops ・ pre ・ post ・ writes ・ nodes は、ユースケース駆動の concrete の Schema へ移す。
