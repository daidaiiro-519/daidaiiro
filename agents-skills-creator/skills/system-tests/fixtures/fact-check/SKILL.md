## 目的

外の情報源の内容を、文書 ・ 設計 ・ 実装へ取り込む人か AI が、項目名などの識別子を書き写すときに、書く識別子のどれが原文にあり、どれが無いかが分かった状態を得る。

## 役割

- 受け持つ：原文を取って、取った日と sha256 と一緒に残す
- 受け持つ：識別子を、原文の文字列で照合する
- 受け持たない：真偽を判定する（原文が誤っていても照合は通る）
- 受け持たない：取り込む先の文書を書き換える

## 事前条件

- 書こうとしている識別子が決まっている

## 入力と出力

- 入力：調べる対象（URL）
- 入力：識別子の一覧（1行1個のテキスト）
- 出力：照合の結果（JSON（schema：references/verify-result.schema.json） ・ 標準出力）
- 出力：原文（sources/）

## 手順

1. 原文を取る（完了条件：原文と sha256 が sources/ にある）
2. 識別子を原文と照合する（完了条件：標準出力に、照合の結果の JSON が出ている）
   - 2a 読めなかった範囲がある → 読めるようにする（ステップ2へ戻る）

## 守ること

- 照合する識別子を言い換えない（言い換えた名前は、原文の名前とは別のキーになり、そのキーで引く実装は何も返さない）

## 最低保証

- どこで止まっても、sources/ の外は変わらない

## 完了条件

- C1 一覧のどの識別子にも、原文にある ・ 無いが付いている（確かめ方：照合の結果の件数と、一覧の行数が同じ）
- C2 読めなかった範囲が、結果に載っている（確かめ方：照合の結果に、読めなかった範囲の件数がある（0件でも））

## 例

- E1（人が直接）：Claude Code のサブエージェントの頁の URL と、項目名3つ（skills ・ disallowedTools ・ allowedSkills）の一覧がある。「この URL で3つを照合して」
  → skills と disallowedTools に ok と原文の行、allowedSkills に「読めた範囲には無い」が付き、読めなかった範囲 0件
- E2（人が直接）：API 仕様の URL（一部の頁が読めない）と、項目名3つの一覧がある。「この URL で3つを照合して」
  → 3件ともに ある ・ 無い が付き、読めなかった範囲 1件が結果に載る
